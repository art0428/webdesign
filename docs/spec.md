# 網頁設計規範

本文件是通用的網頁介面視覺依據，不綁任何特定產品或系統類型。任何系統要新增或修改畫面，先讀這份，再動工。

v30 變更範圍：**圓角跟著風格走、輸入框圓角收斂**。起因是七套的按鈕圓角看起來各不相同，問題是「圓角要隨風格走，還是開放使用者自訂」。實測七套元件庫後分成兩類：按鈕 S1〜S5 一律膠囊、S6 6px、S7 2px，是材質需要的設計決定；輸入框卻是 12／14／13／14／16，token 全寫 12 而風格層各自用寫死的數字覆寫，是漂移。v30 在 5.2 寫明**圓角屬風格的材質層，跟著風格走，不做第五條軸、不開放產品或使用者自訂**；「風格層可以覆寫」不等於每套都要覆寫，共用層的值就是預設，只有材質需要才覆寫並寫進 5.2 的例外。逐套判定的結果：**S2 浮雕**整條圓角階（容器 20、小件 14）是「柔影要配更圓」的一致決定，保留並寫成例外；**S3 琉璃**每級都比共用值大 1〜2（22、13、11、7），不在 4px 標尺上，容器定為 20、其餘刪掉覆寫回到共用值（chip、token 格、檔案列、提示框 12，提示氣泡 10，屬性 tag 6）；**S5 極光**輸入框與多行輸入的 16 與 16/16/16/6 刪除回到 12（三圓一尖留給卡片、chip 等有面積的元件）；**S4 手帳**小件維持 14，寫成例外；S6、S7 不變。兩套的彈窗 22、提示氣泡 11 同樣是不在標尺上的值，一併收成 20 與 10。5.2 補一張七套圓角定案表。改到 `material/s2、s3、s5`（來源）與 `dist/style-s2、s3、s5.css`，版號 `30.0.0`。

v29 變更範圍：**S6 石墨深色的「深色底」預設改為跟隨色系**（依《S6 深色跟隨色系條文草案 v2》，2026-10-27 定案）。v28 以前 S6 深色是 `#121212` 系列的純無彩灰；比對 Mercury 等產品後確認深色不必是純黑或純灰，帶極少量品牌色調的深色能保留品牌個性、又不影響閱讀。v29 起六個面（page、card、paperc、sel、line、line-2）帶目前色系主色的色調：**明度與中性值相同、OKLCH 彩度 `min(0.012, 主色彩度)`、上限 0.015**，換色系時自動跟著換；四個語意淡底與品牌淡底照舊規則（16% 混入卡片色）重算，C2 深湖青、C3 深靛的主色各補一階明度；文字三色與四個 `--on-*` 不變。使用者只多一個二選一的設定（8.8.5）：**跟隨色系（預設）／中性石墨**（`<html data-dark-tint="neutral">`，與 v28 以前完全相同）。**既有 S6 專案升級後深色畫面會帶色調**，要維持原樣寫 `neutral`。3.5 的 S6 段與 8.2 的 S6 鐵則二補上這個唯一的例外；8.3 可用組合 148 → **163**；8.8 新增 8.8.5、8.8.2 改標為中性石墨的值、驗收加兩項；12.1 版號 `29.0.0`、12.3 拆檔驗證 19 → 21 次、12.4 補 `DS.setDarkTint()`、`DS.darkTint()`；名詞表加兩條。順手修掉兩個深色段的寫死值：卡片色半透明 `rgba(26,26,26,…)` 四處改 `color-mix(in srgb,var(--card) …,transparent)`（跟隨色系時會留一塊中性灰）；骨架屏 `.sk` 深色漸層第三段殘留的淺色 `#EFEFEF` 改 `var(--sel)`（深色下載入動畫會掃過一條亮帶，v14 起就有）。其餘章節與 v28 逐字相同。

v28 變更範圍：**v27 的文件落差校正**（公開版發佈前的交叉檢查找到的），加一條結構層規則。一、**6.6 第一條補「表格的單號與日期 `.dt` 不折行」**：範例頁從使用說明 v2 起自己寫這條，並註明「之後會收進 `base.css`」；v27 收了按鈕、沒收 `.dt`，元件庫的表格欄寬夠所以量不到，但欄位多的產品表格在平板寬度會把「SO-261010-021」從連字號折成三行（範例頁 `s1-admin.html` 在 768、1024 實測）。v28 收進結構層（`patch_v28.py`），範例頁的 `<style>` 只剩排版。範例頁另一條覆寫——手機上把表格標題列的篩選膠囊改回換行——會蓋掉 6.6 第二條的橫滑，一併拿掉。二、**12.3** 拆檔驗證的組合數還寫 v24 的 15 次，改為 v26 起的 19 次（5.7 早已寫 19 種）。三、**6.5 的欄距表與 8.7** 兩處還用 v24「S6 密集模式」的說法，改為 v26 的緊湊密度（S1、S3、S6 可開）。12.1 版號改 `28.0.0`；`dist/` 的 README 與 `theme.js` 檔頭的 API 清單補 `DS.labelTables()`，風格檔檔頭把純度檢查改正為第六項（12.2）；工程師手冊升 v10。不動任何 token 的值與顏色。其餘章節與 v27 逐字相同。

v26 變更範圍：**5.7 改為「密度三檔」，密度成為第四條軸**。v24 的密集只有「標準／密集」兩檔、只開放 S6，而且所有數值（卡片 16／20、儲存格 12／20）都寫成範圍卻沒說預設，工程師自然挑小的。v26 起密度是風格、字級套、色系之外的第四條軸：**comfortable 寬鬆／normal 標準／compact 緊湊**，三檔的數值全站只有一份（`base.css`），**每套風格只決定預設哪一檔、能選哪幾檔**——S6 石墨預設標準，其餘六套預設寬鬆；S2、S4、S5、S7 鎖緊湊（柔影、手繪框、有機圓角、明體留白在 32px 元件上會壞）。寬鬆＝元件高度採用手機的觸控尺寸（44／44／40／44）、卡片與板內距 24、儲存格 16／20（列高 ≥56）、表格內文 B1、卡片與表格標題升 H2、表單標籤墨色。**不寫 `data-density` 就是該套的預設**（CSS 自己判斷，不靠 JS）；768px 以下三檔收斂成一檔；密度是系統層的決定，頁面層只准往緊的方向覆寫一次。6.3 補一條「描述清單放進卡片一律兩欄」；名詞表、8.7 選型第四條、12.1、12.4 相應修改；`dist/` 升 `26.0.0`（`base.css` 加寬鬆區塊與各套預設、`theme.js` 的 `DENSITY` 矩陣取代 `DENSE_STYLES`）。標準檔與緊湊檔的值不動（七套元件庫 × 三檔 × 深色，拆檔比對 19 種 0 差異；尺寸 29 次量測 0 不合規）。依據見「七套風格密度情境圖」畫布（七套首選情境頁的現況與寬鬆並排）。其餘章節與 v25 逐字相同。

## 二、五條設計總則

一、**內容專業、外殼柔和**。資料區（表格、數字、編號）維持高對比與緊湊密度，保證看得快、看得準；容器與操作元件用大圓角與柔和線條，降低剛硬感。這是本視覺系統的核心矛盾與解法。

二、**顏色是專案的，結構是規範的**。品牌雙色只負責「強調」與「品牌感」，介面的辨識度來自版型、字級層級、元件形狀。換掉任何顏色，介面都必須依然成立。

三、**每頁只有一個視覺焦點**。一頁最多一顆實心主按鈕、最多一個放大的關鍵數字。其餘元件保持安靜。

四、**狀態不可只靠顏色表達**。所有狀態標示一律「符號＋文字」並用（例如「● 待確認」），確保色覺不同的使用者也能判讀。

五、**數字要當主角處理**。金額、編號、單號、數量一律使用 Arial 等寬對齊、靠右排列、加千分位。

## 三、色彩體系

### 3.1 三層架構

色彩分成三層，各自的可變性不同。這是整套系統最重要的結構決策。

| 層 | 內容 | 可變性 |
|----|------|--------|
| 第一層｜品牌雙色 | accent-1 主色、accent-2 副色 | 每個專案從十二組核心或 SC 特殊色系中選一組，程式執行時注入 |
| 第二層｜結構灰階 | 文字、次要文字、框線、底色、表頭帶 | 全系統固定 |
| 第三層｜語意色 | error 紅、warning 琥珀、success 綠、info 藍 | 全系統固定，永不隨品牌變 |

**鐵則：介面上不得出現這三層以外的任何顏色。**需要區分更多層次時，用灰階深淺或留白解決，不要新增色相。

### 3.2 雙色分工

| 色 | 負責 | 具體用在哪 | 出現頻率 |
|----|------|-----------|----------|
| accent-1 主色 | 所有「操作」 | 主按鈕、選中狀態、連結、聚焦框、目前頁籤、進行中狀態 | 每頁大量 |

副色的存在意義是讓品牌有兩個顏色可以表達，而不是讓介面變花。**副色出現超過三處就是用錯了。**

### 3.4 副色的使用限制（重要）

十二組副色裡只有四組在白底上白字達 4.5（C1、C6、C7、C9）——副色本來就是選來當點綴的，飽和度與明度都高。因此副色分兩型，且承載文字時一律走深副色：

**深型**（十二組核心全部屬此型）：不承載文字的填色（進度條第二段、圖表第二數列、裝飾）用 `--acc2`；**承載文字的填色一律用 `--acc2-deep` 配白字**（AI 標記、副色頭像、漸層鈕的深端）；副色當字（漲跌數字、副色連結）一律用 `--acc2-deep`。

**淺型**（僅 SC 系列）：填色上放 `--ink` 主文字，不放白字（實作上讀 `--acc2-text`，深型為白、淺型為該風格的 `--ink`）；副色當字一律用 `--acc2-deep`；填色元件必須有 1px 框線或置於白卡上，不得裸放在頁面底；同一元件或同一列內不得與語意色 warning 琥珀並存（兩者色相相近，會讓人分不清品牌點綴與待處理狀態）。

兩型的判定不憑目測，以計算為準：白字對比 ≥4.5 為深型、`--ink` 對比 ≥4.5 為淺型。副色出現超過三處就是用錯了（見 3.2）。

### 3.6 語意色（固定，永不隨品牌變）

四個語意色七套風格共用同一組，以最深的不透明底色（S2 浮雕的 `#E6EAF0`）為約束條件反推，使四色在七套風格的所有底色上都 ≥4.5。

| 語意 | 變數 | 文字色 | 淡底 | 對白底 | 對浮雕底 | 使用場景 |
|------|------|--------|------|--------|----------|----------|
| error 紅 | `--err` / `--err-soft` | `#B23F2F` | `#F7ECEA` | 5.76 | 4.77 | 錯誤訊息、必填星號、逾期、已取消、不可回復動作 |
| warning 琥珀 | `--wrn` / `--wrn-soft` | `#846200` | `#F3EFE6` | 5.63 | 4.67 | 待處理、待確認、額度不足、需人工判斷 |
| success 綠 | `--ok` / `--ok-soft` | `#2A722E` | `#EAF1EA` | 5.92 | 4.91 | 成功、已完成、已通過、資源充足 |
| info 藍 | `--info` / `--info-soft` | `#1A66AA` | `#E8F0F6` | 5.96 | 4.93 | 中性提示、說明、系統訊息、維護公告 |

info 藍是獨立的資訊色：中性提示不再借用 accent-1（accent-1 隨品牌改變，同一個提示框在酒紅品牌會被誤讀成警告）。語意色一律「符號＋文字」並用（見總則四），不單靠顏色傳達。

### 3.7 狀態的顏色對應

這是全站最常出現的狀態集合，對應關係固定：

| 狀態語意 | 顏色 | 理由 |
|----------|------|------|
| 待人處理 | warning 琥珀 | 需要有人去處理 |
| 進行中 | accent-1 主色 | 流程正常在跑 |
| 成功結束 | success 綠 | 階段性成功 |
| 結案封存 | 灰 | 結案，不需再注意 |
| 異常 | error 紅 | 出錯或被中止 |
| 中性提示 | info 藍 | 與狀態無關的系統訊息、說明、公告 |

各系統把自己的狀態名對應到這六類即可，顏色語意在所有系統之間保持一致。

### 3.8 CSS 變數實作

色彩以 CSS 變數（寫在樣式表裡的可替換參數）實作。依專案設定，在 HTML 的 `<html>` 或 `<body>` 標籤上注入 style 屬性覆寫第一層的七個變數即可，其餘全部固定不動。

```css
:root{
  /* 第一層：品牌雙色（runtime 注入，僅此七個可變） */
  --acc:#2B5FB8;  --acc-soft:#EDF1F9;  --acc-deep:#2B5FB8;
  --acc2:#C2377B; --acc2-soft:#FAEEF4; --acc2-deep:#BA3576;
  --acc2-text:#FFFFFF;        /* 深型副色為白；淺型副色為該風格的 --ink */

  /* 第二層：結構灰階（以 S1 奶油為例，其餘風格見 3.5） */
  --ink:#26292E; --muted:#6F6B64; --line:#E4E2DE;
  --band:#FBFAF8; --page:#F6F5F2; --card:#FFFFFF;

  /* 第三層：語意色（固定） */
  --err:#B23F2F;  --err-soft:#F7ECEA;
  --wrn:#846200;  --wrn-soft:#F3EFE6;
  --ok:#2A722E;   --ok-soft:#EAF1EA;
  --info:#1A66AA; --info-soft:#E8F0F6;
}
```

注入範例（頁面產生時寫入，以 C7 焦糖磚橘為例）：

```html
<body style="--acc:#A8481F;--acc-soft:#F8EFEC;--acc-deep:#A8481F;
             --acc2:#2B2B2B;--acc2-soft:#EDEDED;--acc2-deep:#2B2B2B;--acc2-text:#FFFFFF;">
```

元件庫與選型介面以 `THEMES` 物件存放十五組設定（十二組核心 ＋ SC1〜SC3），每組帶 `styles`（可用風格）與 `adjust`（可用但自動套調整的風格）欄位；切換風格時逐組檢查，不適用者鎖住、目前色系不合法時退回 C1 並提示，網址 hash 與跨頁訊息也走同一個檢查，不得靜默套用。

**禁止事項**：任何元件的 CSS 不得寫死色碼，一律引用變數。唯一例外是純黑純白（`#fff`）與陰影用的半透明黑。

### 3.9 色彩的定義單位

一、本規範所有顏色以 sRGB 色碼（六位十六進位）為唯一真值。對比度、色盲檢查、色差檢查一律以此色碼計算。

二、外部色彩系統（PANTONE、RAL、DIC 等）只作對照，不作定義。規範本體與 skill 不得出現任何外部色號。

三、專案導入既有品牌色時，若客戶以外部色號提供：以該系統官方工具取得 sRGB 近似值，依本章及第十章門檻驗收，不合格者調整色碼並在專案文件記錄「螢幕版與印刷版不同」。外部色號與查詢日期只記錄在專案自己的品牌文件。

四、允許以 `color(display-p3 …)` 提供廣色域增強，但每個顏色必須同時存在 sRGB 後備值，驗收以 sRGB 後備值為準。

### 3.10 SC 特殊色系

SC 系列收錄「需要例外規則、或只在部分風格可用」的色系。它們不佔核心十二組的位置、不隨年度退場，但每一組都必須標明適用風格，元件庫與選型介面須依此鎖定。

| 編號 | 名稱 | `--acc` | `--acc-soft` | `--acc-deep` | `--acc2` | `--acc2-soft` | `--acc2-deep` | 副色型 |
|------|------|---------|--------------|--------------|----------|---------------|---------------|--------|
| SC1 | 深綠 × 相思黃 | `#35463D` | `#EFF0EF` | `#35463D` | `#DACD65` | `#FCFBF3` | `#6F6519` | 淺型 |
| SC2 | 鈷藍 × 亮橘 | `#2449E8` | `#EEF1FD` | `#2449E8` | `#FF7A1A` | `#FFF3EA` | `#B0490A` | 淺型 |
| SC3 | 石板藍 × 冰川青 | `#3D4C5E` | `#EFF1F3` | `#3D4C5E` | `#5FB4C9` | `#F0F8FA` | `#296778` | 淺型 |

SC1 實測：主色白字 10.02、放淡底 8.77、放浮雕底 8.30、放手帳紙 9.07；副色配 `--ink`（五風格分別為 8.97／6.93／8.95／8.76／9.32）；深副色白字 5.91、放浮雕底 4.90、放手帳紙 5.35、放頁面底 5.42、放副色淡底 5.70；副色與 warning 琥珀 `#846200` 對比 3.46（故訂並存禁令）；副色與各底色邊界對比 1.35〜1.63（故訂框線規則）。琉璃 70% 白玻璃疊在相思黃上合成 `#F4F0D1`，次要文字 `#454C59` 對比 7.5；墨色 66% 深玻璃疊上去合成 `#59573E`，白字 7.35。

| 風格 | 判定 | 理由 |
|------|------|------|
| S1 奶油 | ◎ 可用 | 白卡上的黃色塊乾淨 |
| S2 浮雕 | ✕ 不建議（鎖定） | 浮雕靠同色凸凹表現材質，冷灰底上的亮黃塊像貼紙；邊界對比亦最低 1.35 |
| S3 琉璃 | ◎ 可用 | 深綠到黃的漸層疊白玻璃為淡奶黃 |
| S4 手帳 | △ 需調整 | 暖紙底偏黃，黃色塊會糊進去；填色元件自動加 1px `--ink` 框線後可用，語彙即「螢光筆」 |
| S5 極光 | ◎ 最推薦 | 深綠與黃的柔霧暈染即極光本身 |
| S6 石墨 | ◎ 可用 | 白卡上的黃色塊乾淨，判定同 S1（v6 加入 S6 時漏列，v13 補上） |

**SC2 鈷藍 × 亮橘**——高彩度。十二組核心全是沉穩路線，零售、消費品、活動頁要「亮」時沒有選項。主色彩度約為 C1 深海藍的 1.75 倍。

SC2 實測：主色白字 6.58、放淡底 5.84、放浮雕底 5.45、放手帳紙 5.95；副色配 `--ink`（S1／S2／S4／S5／S6 分別為 5.59／4.32／5.47／5.81／6.87，浮雕未達 4.5，故鎖定）；深副色白字 5.52、放浮雕底 4.57、放手帳紙 5.00、放頁面底 5.06、放副色淡底 5.06；副色與 warning 琥珀色差 29.6（CIEDE2000），比 SC1 遠得多，但淺型副色的並存禁令照樣適用；副色與各底色邊界對比 2.16〜2.61，故同樣適用框線規則。

**主色與 C1、C4 的色差約 10**（C1 9.8、C4 10.2），低於核心十二組之間的門檻 14.8。這不是挑色失誤：能承載白字（≥4.5）的鮮豔藍，全都夾在 C1 深海藍與 C4 電光紫之間，網格搜尋的上限是 12.3。SC2 的辨識度靠的是彩度，不是色相。同一個專案一次只用一組色系，所以這只影響選型時的辨識，不影響使用。

## 四、字型、字級與行距

### 4.1 字型家族

```css
/* 中文：Google Fonts 黑體，確保跨系統一致 */
--font-cjk: 'Noto Sans TC', sans-serif;
/* 數字與英文：系統字 Arial，後接中文備援 */
--font-num: Arial, Helvetica, 'Noto Sans TC', sans-serif;
```

引入方式：

```html
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500;700;900&display=swap" rel="stylesheet">
```

使用規則：

- 中文一律 Noto Sans TC，只載入 400／500／700／900 四個字重，不要載入更多（每個字重都是額外的下載量，中文字型檔案很大）。
- 數字、英文、料號、單號、金額、日期、電話一律 Arial。Arial 沒有中文字符，堆疊 `Arial, 'Noto Sans TC'` 可讓中英數在同一段文字裡自動分流，混排安全。
- **中文絕不使用斜體**。中文沒有真正的斜體字面，瀏覽器會用機械傾斜模擬，字型會變形難看。要強調用字重或顏色。
- Arial 在 macOS 會以 Helvetica 系呈現，跨系統有些微差異，這是已知且接受的。

**風格層例外（僅 S6 石墨）**：N4 級（料號、單號、日期、IP、追蹤碼這類技術識別碼）改用等寬字堆疊 `"SF Mono", Menlo, Consolas, "Liberation Mono", monospace`，讓上下兩列逐字對齊。**僅限 N4 一級**——金額（N1〜N3）仍用 Arial，中文一律 Noto Sans TC。其他風格不套用此例外。

**風格層例外（僅 S7 編輯）**：標題 H0、H1、H2、H3 與元件內的標題（卡片標題列、彈窗、側滑面板、表格標題、圖表卡標題）改用明體 `'Noto Serif TC', 'Songti TC', 'Source Han Serif TC', 'PMingLiU', serif`，Google Fonts 另載入 `family=Noto+Serif+TC:wght@700;900`。**只換字型**——字級、行距、字距、字重照 4.2 的十四級表；內文、標籤、按鈕仍是 Noto Sans TC，D1 與金額仍是 Arial。明體只給標題，是因為中文明體在小字與長段落的辨識度不如黑體。

```html
<body data-type="productive">   <!-- 後台、工作介面、結帳流程 -->
<body data-type="expressive">   <!-- 前台、閱讀與瀏覽型頁面 -->
```

Expressive 的放大倍率**刻意不等比**：頂端 D1 放大約 47%、底端 L2 只放大 10%。表現型要的是「大的更大」造成的節奏感；標籤字若跟著等比放大，頁面會顯得鬆散、失去重心。

**行動裝置例外只有兩個**：Expressive 的 D1 在 768px 以下降為 36px（3.6rem），行距維持 1.10——44px 的數字在手機上會擠壓同列的其他內容；Expressive 的 H0 在 768px 以下降為 32px（3.2rem），行距維持 1.25——40px 的標題在 390px 寬的畫面一行只放得下八、九個字。其餘十二級在手機上都不縮小。

**H0 展示標題**：只給前台的 Hero 主標與活動頁主標，**一頁最多一個**，後台畫面不用（Productive 也定義 H0，只是為了讓兩套的代號一一對齊）。一行以十四個字為上限、最多兩行；必須加 `text-wrap:balance`，讓瀏覽器平衡各行長度——40px 的中文標題很容易在最後一行只剩一兩個字。D1 仍然只給數字：它的行距 1.10 是為沒有下伸部的數字設計的，放中文會擠在一起。

**H2 與 H3 怎麼分。**分界不是「區塊還是卡片」，而是這個標題領導的是一整塊獨立內容，還是緊接著一列密集內容：

- **H2**：頁面裡的區塊標題；彈窗標題；側滑面板標題；獨立存在、自成一件事的大卡片（例如設定頁的一張設定卡、儀表板上的主圖表卡）。
- **H3**：卡片的標題列（下方有分隔線、帶 `--band` 底色的那一條）、表格標題、圖表卡的標題列、表格分區標籤、表單裡的分組小標題。

H3 與 B1 同為 14px（Expressive 同為 16px），層級靠字重 900 與 0.08em 字距撐起來，所以它只適合「下方緊接著分隔線或密集內容」的場合；標題底下是大段留白與多段內文時，改用 H2。這與 IBM Carbon 的分工一致：14px 的 heading-compact-01 用在表格分區與行內小標題，卡片與面板標題用 16px 的 heading-02——本規範的 H1 21／H2 17／H3 14／B1 14 正好對應 Carbon 的 20／16／14／14。覺得某張卡片的標題太小，直接改用 H2，不得新增中間值。

**字級與行距必須配成同一代號。** 寫了 `var(--fs-b2)` 就要同時寫 `var(--lh-b2)`，不可以拿 B2 的字級去配 B3 的行距。十四級是「字級 ＋ 行距」成對設計的，拆開配會讓同一頁出現兩種看不出理由的垂直節奏；更麻煩的是每個值單獨看都在表上，所以肉眼與逐值檢查都抓不出來。

沒有自己指定行距的元素會往上繼承，所以 `body` 一定要寫 `line-height:var(--lh-b1)`。漏掉的話整份文件的預設行距會是瀏覽器的 `normal`（約 1.2 倍），所有沒單獨設定行距的文字都不合規。

這一條有兩個例外，都是本規範自己要求的，不算違規：

- **貨幣前綴縮小 0.68 倍**（見 4.6）。它是跟著金額走的附屬符號，不是獨立的一級。
- **768px 以下的輸入框 16px**（見 6.4）。這是為了擋掉 iOS Safari 的自動放大。

**驗收：交付前跑 `check_lineheight.py`，這是第四項自動檢查。** 它分兩關：先靜態掃每一條 CSS 規則與行內 `style`，檢查同一條規則裡的字級與行距是不是同代號、有沒有寫了字級卻漏掉行距；再把頁面渲染出來，逐一取每個文字元素實際算出來的字級與行距來比對。兩關都要 0 不合規。只看宣告值的 `check_tokens.py` 抓不到這一類。

### 4.3 兩套怎麼選

| 頁面性質 | 用哪一套 |
|----------|----------|
| 後台所有畫面 | Productive |
| 資料密集的清單、表格、報表 | Productive |
| 結帳、核對、輸入數值的流程 | Productive |
| 前台首頁、目錄、內容頁 | Expressive |
| 閱讀型頁面、活動頁 | Expressive |

判斷準則一句話：**這一頁是「拿來看的」還是「拿來做事的」**。看的用 Expressive，做事的用 Productive。同一個流程中途切換是允許的，因為使用者的任務性質確實改變了。

Expressive 的完整樣貌見七張前台示範頁 `storefront_s*.html`（S3、S5、S6 同一頁可切深色，設計系統瀏覽器的「前台示範」檢視）：同一套風格、只用元件庫既有的 class；v25 起每套各做它最適合的那一種網站（會員中心、自助機台、產品發表、咖啡館、選物電商、開發者產品官網、線上雜誌，見 8.7 的「每套風格的前台示範」）。閱讀型前台的首選是 S7 編輯。

### 4.4 行距的設計理由

行距（line-height）是中文介面最容易被忽略、但對閱讀感受影響最大的一項。本規範的邏輯：

- **中文段落 1.8**：中文字是方塊字、字面率高、沒有英文那種起伏的輪廓，行距太小會糊成一片。1.8 是中文長文的舒適下限。
- **表格內 1.7**：表格要密集，但仍需可讀，比段落稍緊。
- **說明文字 1.70**：字級小（12px）時要用比內文更大的「行距除以字級」來補償，否則顯得擁擠。1.70 ＝ 20.4px，對齊 Ant Design 與 TDesign 給 12px 的 20px；舊版的 1.85 ＝ 22.2px 偏鬆。
- **標題 1.4〜1.5**：標題通常一到兩行，行距太大會讓標題「散開」失去份量。
- **純數字 1.15〜1.25**：數字沒有下伸部（像 g、y 那樣往下延伸的筆畫），不需要多餘的垂直空間；大數字行距太鬆會顯得軟弱無力。

**行距不得改用其他設計系統的數值。**常見的 14px/1.43 是為拉丁字母調的——英文有 b、d、g、y 這類上下伸出的筆畫，字與字之間天然有起伏，行與行不容易黏在一起。中文套用會讓整段糊成一塊灰。

**單位寫法**：一律使用無單位倍數（`line-height: 1.8`），不要寫 `28px`。無單位值會依各元素自己的字級計算，巢狀元素才不會繼承到錯誤的行高。

### 4.5 最小字級規定

- **12px 是承載句子的最小字級。**任何完整句子、說明文字不得小於 12px。Expressive 的下限是 13px。
- **11px 是整套標尺的絕對下限，而且只給「微標籤」**——一到四個字的單詞或極短片語（例如「客戶」「NT$」「待確認」），且必須字重 700 以上、加大 letter-spacing 補償辨識度。不得用來寫句子。
- **欄位標籤不得用 11px，一律 12px（L1）。**欄位標籤是表單裡每一列都要讀的功能性文字，不是微標籤。IBM Carbon、Atlassian、GitHub Primer、Ant Design、Arco、TDesign、Element Plus、Semi 八套的欄位標籤都是 12px。
- **不得出現 10px 以下的字。**中文圈五套主流元件庫（Ant Design、Arco、TDesign、Element Plus、Semi）的最小字級 token 全部是 12px，零例外；西方只有 Salesforce 有 10px，而且整份樣式表只出現六次，全部用於開關的 ON／OFF 與頭像縮寫這類兩個字母的標記。
- 行動裝置不縮小字級（例外只有 4.2 的 D1 與 H0）。透過版型改變（單欄化）而非縮字來適應。
- **標題不得小於它所領導的內文。**H3（卡片標題列、行內小標題）與 B1（內文）同為 14px，靠字重 900 與 0.08em 字距區分，H2 與 H3 的用途分界見 4.2；這與 IBM Carbon 的做法一致（heading-compact-01 與 body-compact-01 都是 14px，只差字重），好處是標題與內文共用同一條基線格線，排在一起不會錯位。

這幾條的對標依據與十四套設計系統的逐項比對見《字級與行距對標主流 v1》。


```css
.price{ font-family:var(--font-num); font-weight:700; font-variant-numeric:tabular-nums; white-space:nowrap; }
.price small{ font-size:.68em; color:var(--muted); font-weight:400; margin-right:2px; }
```

規則：

- 千分位一律加。
- 貨幣前綴縮小至 0.68 倍並轉灰，讓數字本身成為視覺主體。
- 表格中的金額一律靠右對齊，數字位數才會對齊、方便上下比較。
- 金額與料號欄位加 `font-variant-numeric: tabular-nums`，讓每個數字佔用等寬。
- 數量、頁碼、計數等純數字同樣使用 Arial，但字重視情況（表格中的數量用 700，次要資訊用 400）。
- 負數或折讓金額前加減號並轉 error 紅。

### 4.7 單位：字級與間距用 rem，造型用 px

使用者可以在瀏覽器設定裡調整預設字型大小，這是視力不佳者最常用的輔助手段。用 px 寫死的頁面完全不理會這個設定；用 rem 寫的會跟著放大。

```css
html{ font-size:62.5%; }                      /* 1rem = 10px */
body{ font-size:1.4rem; line-height:1.8; }    /* B1 */
```

採 62.5% 寫法的好處是心算容易——**px 值除以 10 就是 rem 值**（14px → 1.4rem）。因為 62.5% 本身是相對值，使用者調整設定時整站仍會等比放大。

| 項目 | 單位 | 理由 |
|------|------|------|
| 字級 | rem | 本項的目的 |
| 元件高度、內距 | rem | 字變大時框要跟著長高，否則字被裁切 |
| 間距標尺 | rem | 字變大時段落之間也要跟著鬆開 |
| 容器最大寬度 | px | 版面寬度由螢幕決定，不該由字級決定 |
| RWD 斷點 | px | 斷點若用 rem 會在放大時意外切換版型 |
| 圓角 | px | 造型，不是內容 |
| 框線粗細 | px | 造型；1px 線放大後會變糊 |
| 陰影位移與模糊 | px | 造型 |
| 行距 | 無單位倍數 | 依各元素自己的字級計算 |

**固定高度一律改為 min-height。**原本寫 `height:40px` 的元件，字級放大後框不會變高，字會被裁掉。

```css
/* 錯誤 */ .btn{ height:40px; padding:0 24px; font-size:13px; }
/* 正確 */ .btn{ min-height:var(--h-btn); padding:0 var(--sp-5); display:inline-flex; align-items:center; font-size:var(--fs-b2); line-height:var(--lh-b2); }
```

**驗收條件**：在瀏覽器預設字級 100%、125%、150% 三種設定下各檢查一輪，確認沒有文字被裁切或溢出、按鈕與輸入框跟著長高、表格的數值欄不換行、側欄選單文字不換成兩行、版面沒有出現水平捲軸。

## 五、間距、圓角與框線

### 5.1 間距標尺（4px 基準）

所有 margin 與 padding 一律取自此標尺，不得出現標尺以外的數值（例如 13px、18px）。

| Token | 值 | rem | 典型用途 |
|-------|-----|-----|----------|
| `--sp-1` | 4px | 0.4rem | 圖示與文字之間、說明文字到輸入框 |
| `--sp-2` | 8px | 0.8rem | 元件內的小間隔、並排的小按鈕、**欄位標籤到輸入框** |
| `--sp-3` | 12px | 1.2rem | 元件之間的標準間距、表格儲存格垂直內距、欄位之間、欄格的緊湊欄距（6.5） |
| `--sp-4` | 16px | 1.6rem | 卡片垂直內距、區塊內元素間距 |
| `--sp-5` | 20px | 2.0rem | 卡片、儲存格、表頭、表格標題列的水平內距 |
| `--sp-6` | 24px | 2.4rem | 區塊與區塊之間、欄組之間、欄格的標準欄距與桌機容器內距（6.2、6.5） |
| `--sp-7` | 32px | 3.2rem | 大區段之間 |
| `--sp-8` | 40px | 4.0rem | 頁面區段分隔 |
| `--sp-9` | 48px | 4.8rem | 頁首與內容之間 |
| `--sp-10` | 64px | 6.4rem | 頁面上下留白 |

**命名以 CSS 為準**：token 連號 `--sp-1`〜`--sp-10`，不是「4px 的倍數」。v17 以前本表寫 space-8＝32px、space-12＝48px，而 `tokens.css` 與七套元件庫一直是 `--sp-7`＝32px、`--sp-9`＝48px，工程師照舊表找 `--sp-8` 會拿到 40px。v18 起兩邊一致。

全站最常出現的兩個內距，一律取自標尺：

| 位置 | 垂直 | 水平 |
|------|------|------|
| 卡片內距 | 16px（1.6rem） | 20px（2.0rem） |
| 表格儲存格 | 12px（1.2rem） | 20px（2.0rem） |

儲存格比卡片緊，是刻意的——表格要密、卡片要鬆。兩者水平內距相同，卡片與表格並排時左緣才會對齊。表頭 `th` 與表格標題列 `.tcap` 的水平內距同樣是 20px，表頭、標題列、儲存格、卡片四者左緣才會對齊；v17 以前 S1、S4、S6、S7 用 16px，基準 S1 本身就錯了。批次選取的勾選欄 `.ck` 是 36px 窄欄，右內距 0，為唯一例外。**表格列的高度由這個內距與列內容決定，不另設 `min-height`**（見 5.4）：純文字列 12 ＋ 12 ＋ B2 行框 21.25 ＋ 1px 線 ≈ 46px，含狀態膠囊的列約 50px。

### 5.2 圓角尺度（四級，固定）

| 級別 | 值 | 用在哪 |
|------|-----|--------|
| 焦點框 | 18px | 頁面的招牌元件（重點標註框）、確認彈窗 |
| 大容器 | 16px | 表格外框、標題卡片、大面板 |
| 小件 | 12px | 統計卡、輸入框、選項 chip、下拉面板 |
| 膠囊 | 999px | **所有按鈕**、狀態標籤、篩選器、搜尋框、數量調整器、側欄選中項 |

設計邏輯：**面積越大，圓角越大**（大面積配小圓角會顯得生硬，小面積配大圓角會變玩具感）。

**按鈕圓度一律一致**：全部膠囊，不因重要性改變形狀。按鈕的層級只靠「填色」區分——實心 accent-1 ＝主要動作、accent-1 外框＝強調動作、灰框＝一般動作、error 紅框＝不可回復動作。

**風格層例外（僅 S6 石墨）**：按鈕與輸入框改為 **6px**、卡片與表格容器改為 **12px**；狀態膠囊、篩選膠囊、屬性 tag 仍維持 999px。這與 S4 手帳的手繪歪框、S5 極光的一角收尖同性質——都是風格的表面覆寫，不是破例。

**風格層例外（僅 S7 編輯）**：卡片、表格容器、面板、彈窗、選單一律 **0**（直角）；按鈕、輸入框、選項 chip、篩選、狀態標籤、屬性 tag **2px**；頭像與圓點維持正圓。實作上把 `--r-lg` 設為 0、`--r-sm` 設為 2px。雜誌的版面是直角的，圓角會把它拉回 App 的語彙。

**風格層例外（S2 浮雕，v30 寫入）**：整條圓角階比共用值大一級——容器（卡片、表格容器、區塊、彈窗、分割面板、行事曆、描述清單、時間軸、圖表）**20px**，次級容器（空狀態、上傳區、通知、手風琴）18，統計卡與選單 16，**小件（輸入框、下拉觸發、多行輸入、選項 chip、token 格、提示框、警示條、彈出層、工具列、檔案列、縮圖）14px**，小控件 10，屬性 tag 8；按鈕與膠囊仍是 999。柔影是靠面積與圓角撐出來的，每一級都圓一點，浮起來的感覺才連貫。

**風格層例外（S3 琉璃，v30 寫入）**：只有容器比共用值大——卡片、表格容器、區塊 `.board`、彈窗、頁首 **20px**，次級容器（空狀態、上傳區、通知、手風琴、行事曆、描述清單、時間軸、圖表、分割面板、結果區、頁尾）18；**小件一律共用值**（輸入框、chip、token 格、檔案列、提示框 12，提示氣泡 10，屬性 tag 6）。v30 以前 S3 是「每級都比共用值大 1〜2」的奇數階（區塊 22、小件 13、氣泡 11、tag 7），不在 4px 標尺上，統一收掉。

**風格層例外（S4 手帳，v30 寫入）**：輸入框、下拉觸發、多行輸入、選項 chip **14px**——2px 墨線粗框配稍大一點的圓角才像手繪的框；容器是手繪的不規則四角；按鈕仍是膠囊。

**風格層例外（S5 極光，v30 寫入）**：有面積的元件用「三圓一尖」——卡片、彈窗、分割面板、頁首 26／26／26／8，chip、縮圖、頁籤、工具列、提示框、彈出層 18／18／18／6，小控件 10／10／10／4；**輸入框、下拉觸發、多行輸入不收尖，共用值 12**（v30 以前是 16 與 16/16/16/6，輸入元件上的尖角只是和單行輸入框不一致，不是記憶點）。

S1 依上表，是其他六套的基準。

**圓角跟著風格走，不開放自訂（v30）。** 圓角和框線、陰影是綁在一起的材質：S2 的柔影要靠大圓角才像浮起來，S7 的 1px 細線要配直角才像印刷品，S5 的一角收尖本身就是記憶點。讓使用者把 S7 的按鈕調成膠囊，得到的不是客製化的 S7，而是四不像。所以圓角屬風格的材質層（第 0 節：風格層只准改顏色、框線、陰影、圓角），**不做第五條軸**，產品 CSS 也不得覆寫 `--r-*`（12.2）。現有的兩條使用者可切的軸——色系與密度——都和材質正交，圓角不是。

但「風格層可以覆寫」不等於每套都要覆寫。**共用層給的值就是每套的預設，風格層只在材質需要時覆寫，而且必須寫進本節的例外**；沒寫進來的差異一律視為漂移。判定的方法是看那一套自己的圓角階，不是只看跨套的表：v30 以前輸入框是 12／14／13／14／16 五種值、token 卻全寫 12，但 S2 的 14 是它整條階的一級（容器 20、小件 14，七個小件元件全是 14）、S4 的 14 有粗框的理由，兩者都是決定；S3 的 13 與 S5 的 16 在各自的階裡沒有對應，是漂移。決定的留下並寫成例外，漂移的刪掉覆寫回到共用值——**收斂一律是刪覆寫，不是改數字**。

七套圓角定案（v30 實測，px；「手繪」是 S4 的不規則四角、「26／8」「18／6」是 S5 的三圓一尖）：

| 元件 | S1 | S2 | S3 | S4 | S5 | S6 | S7 |
|---|---|---|---|---|---|---|---|
| 按鈕（主／一般／小） | 999 | 999 | 999 | 999 | 999 | 6 | 2 |
| 輸入框、下拉觸發、多行輸入 | 12 | **14** | 12 | **14** | 12 | 6 | 2 |
| 選項 chip | 12 | **14** | 12 | **14** | 18／6 | 6 | 2 |
| 卡片、表格容器、區塊、彈窗 | 16（彈窗 18） | 20 | 20 | 手繪 | 26／8 | 12 | 0 |
| 狀態膠囊、篩選膠囊 | 999 | 999 | 999 | 999 | 999 | 999 | 2 |

表上粗體是寫進本節例外的值。還沒做的是機制：這些例外值目前仍是風格層裡逐條寫死的數字，共用層的 `.card`、`.chip`、輸入框也還沒引用 `--r-lg`／`--r-sm`，所以第六項檢查守不住「風格檔不得出現圓角數字」。下一批次把共用層改成引用 token、各套例外改成只覆寫 token、`audit_layers.py` 加這一條，列入規範缺口。

### 5.3 框線與陰影

- 框線一律 **1px**，色 `--line`。
- 選中或聚焦狀態的框線 **1.5px**，色 `--acc`。
- **預設零陰影**。層次靠框線、底色深淺（`--band` 與 `--card`）與留白建立，不用 box-shadow。
- 例外：S2 浮雕（雙向柔影）、S3 琉璃（面板投影）、S4 手帳（硬影位移）三套風格的視覺原理就建立在陰影上，依第八章各自的定義實作。S1 奶油、S5 極光、S6 石墨與 S7 編輯維持零陰影。

### 5.4 元件標準尺寸（結構層，七套共用）

元件的高度是**結構**，不是材質：風格層只准改顏色、框線、陰影、圓角，**不准出現 `min-height` 與 `padding`**。v16 以前這張表只是數字，沒有落到 CSS，結果七套元件庫的同一顆按鈕量出三到四種高度（S1 39px、S2 45px、S4 41px）。v17 起高度做成 token，寫法固定如下：

```css
:root{--h-btn-primary:4.0rem;--h-btn:3.8rem;--h-btn-sm:3.2rem;--h-input:4.0rem;--h-qty:3.4rem;--h-pill:2.4rem;--h-nav:3.8rem;--h-tag:2.0rem}
@media (max-width:767px){:root{--h-btn-primary:4.4rem;--h-btn:4.4rem;--h-btn-sm:4.0rem;--h-input:4.4rem;--h-qty:4.4rem}}
.btn{min-height:var(--h-btn);padding:0 var(--sp-5);display:inline-flex;align-items:center;justify-content:center}
```

三條規則：

一、**高度用 `min-height` 鎖定，不用 `height`**（理由見 4.7）。多行內容可以更高，但不得更低。
二、**垂直內距歸零，用 flex 置中。** 高度不再是「內距 ＋ 行框 ＋ 框線」算出來的，所以 S4 手帳的 2px 框線、S2 浮雕的無框線都被 `box-sizing:border-box` 吸收，七套算出來一模一樣。
三、**水平內距只取標尺**，列在下表。風格層不得改。

**行動裝置的 4.4rem（44px）是觸控目標的國際慣例下限**，小於這個尺寸手指容易點錯。狀態膠囊與屬性 tag 不是可點擊元件，所以不受此限。

**表格列為什麼不鎖高度**：舊版寫 4.4rem，但儲存格內距 12px 與 B2 行框 21.25px 加起來就是 45.25px，再加 1px 線是 46px——用標尺上的任何內距都湊不出 44。與其寫一個做不到的數字，不如規定派生方式：列高 ＝ 上下內距 `--sp-3` ＋ 列內最高的內容。純文字列 46px；放了 24px 狀態膠囊的列，膠囊置中於行框，約 50px。要更密的表格，調的是儲存格內距（`--sp-2`），不是列高。

**驗收：交付前跑 `audit_sizes.py`，這是第五項自動檢查。** 它把頁面渲染出來，對上表每個元件取所有實例的實際高度：一、與規範值相差不得超過 1px（多行內容與被 flex 拉伸者可以更高，不得更低）；二、`min-height` 的計算值不得是 `auto` 或 `0px`；三、七套（加 S3、S5、S6 的深色模式）同一元件的眾數必須相同（相差 1px 內視為相同）；表格列改量儲存格上下內距是否等於 12px；四（v21）、**框線貼合與分隔線重複**：兩個四邊都有框線的元件（小於 20px 的圖示、勾選框、色點不量）邊緣距離低於 8px，或兩條分隔線相距 12px 以內、64px 以內而中間沒有內容，或分隔線貼在容器級框的上下緣 12px 以內，皆不通過（9.3 第六、七條；刻意相連的組件與浮層豁免，清單見腳本）。任何一條不是 0 即不通過。元件庫現況（v24）：七份元件庫、七張前台示範頁，加上 S3、S5、S6 兩者的深色模式與 S6 元件庫的密集模式（淺、深，5.7），共 22 次量測皆 0 不合規；v16 同一支腳本量出 740 處 `min-height` 未鎖定、11 個元件七套不一致。

### 5.5 動態（時長與緩動）

動態的時長與緩動和字級、間距一樣是 token，**不得寫死秒數**。

| Token | 值 | 用在哪 |
|---|---|---|
| `--dur-1` | 120ms | 顏色、框線、陰影的狀態變化：滑過、聚焦、按下、表格列反白 |
| `--dur-2` | 200ms | 元件內的位移與展開：開關滑塊、折疊箭頭、下拉選單、提示氣泡 |
| `--dur-3` | 320ms | 大面板的進出：彈窗、側滑面板、Toast 淡出 |
| `--ease-out` | `cubic-bezier(.2,0,0,1)` | 進場與狀態變化——快起慢停，東西「落定」 |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | 退場——慢起快走，東西「離開」 |

```css
:root{--dur-1:120ms;--dur-2:200ms;--dur-3:320ms;
      --ease-out:cubic-bezier(.2,0,0,1);--ease-in:cubic-bezier(.4,0,1,1)}
@media (prefers-reduced-motion:reduce){:root{--dur-1:0ms;--dur-2:0ms;--dur-3:0ms}}
.btn{transition:background var(--dur-1) var(--ease-out)}
```

- **可以做轉場的屬性**：顏色、背景、框線色、陰影、`opacity`、`transform`。**不可以**：`width`、`height`、`top`、`left`、`margin`、`padding`——這些會觸發重新排版（瀏覽器重算整頁版面），動起來會卡。要移動東西用 `transform:translate()`。
- **不寫 `transition:all`**。列出實際會變的屬性，否則日後加一條樣式就會意外跟著動。
- **退場比進場短一級**：彈窗以 `--dur-3` 進場、`--dur-2` 退場。使用者關掉東西時不想等。
- **元件內的動畫不超過 `--dur-3`**。超過 320ms 的動畫在後台會讓人覺得系統慢。
- **迴圈動畫不受此表限制**：骨架屏的流光、處理中的轉圈，週期依元件自己的設定。
- **減少動態**：使用者在系統設定開啟「減少動態」時，三個時長自動歸零（見上方 CSS），元件不必逐條覆寫。迴圈動畫另依 10.5 處理。

### 5.6 層級（z-index）

疊在頁面上的東西只有五層，值做成 token，**不得出現表外的 `z-index`**。沒有層級表的後果是每個工程師自己挑數字（v17 以前的元件庫裡散落著 1、5、6、50、60），最後一定有人寫 9999。

```css
:root{--z-sticky:10;--z-pop:20;--z-drawer:30;--z-modal:40;--z-toast:50}
```

| 層 | token | 值 | 用在 |
|---|---|---|---|
| 吸附 | `--z-sticky` | 10 | 吸附表頭、頂列、手機底部固定條 |
| 浮層 | `--z-pop` | 20 | 下拉選單、就地確認、自動完成、日期選擇器 |
| 面板 | `--z-drawer` | 30 | 側滑面板與它的遮罩 |
| 彈窗 | `--z-modal` | 40 | 彈窗與它的遮罩 |
| 通知 | `--z-toast` | 50 | Toast、提示氣泡 |

同一層內靠 DOM 順序決定前後，不另外加數字。元件內部的局部堆疊（例如步驟精靈的圓點壓在連接線上）用 `z-index:1` 並在元件根建立 `isolation:isolate`，不會逃出元件影響這張表。

### 5.7 密度三檔（v26；v24 的密集模式併入）

**密度是第四條軸，不是風格的屬性。**規範有三條互不干涉的軸：風格（殼，只管材質）、字級套（Productive／Expressive，看頁面是做事還是閱讀）、色系；v26 加第四條——**密度**，管的是元件多高、內距多寬、一屏放幾列。和深色（8.8）一樣，同一份元件 HTML、同一張樣式表，在 `<html>` 上以 `data-density` 切換：字級層級、字型、顏色、圓角、框線粗細全部不變。可與深色並用。

**三條配套規則**：

一、**密度是系統層的決定**，跟風格一樣寫在 `<html data-density>`，建置時定。**不寫就是該套的預設**：`base.css` 以 `html[data-style="s1"]:not([data-density])` 這類選擇器套用預設，不靠 JS；寫 `data-density="normal"` 才回到標準。頁面層只准往「緊」的方向覆寫一次（S1 後台的報表頁單獨開緊湊可以），不准往鬆——同一個系統不得出現兩種手感。
二、**768px 以下三檔收斂成一檔**：緊湊本來就不生效（5.4 的 44px 觸控下限優先），寬鬆在手機上的數值等於標準檔的手機值，所以 CSS 把寬鬆也包在 `@media (min-width:768px)` 裡，產品不用另外判斷。
三、**鎖住的組合由 `theme.js` 擋**（12.4）：`DS.setDensity()` 收到不在該風格可選範圍的檔，退回該套預設並回傳實際套用的檔，不靜默套用；設計系統瀏覽器的「密度」列把鎖住的檔反灰停用。CSS 本身不擋——`data-density="compact"` 寫在 S2 上仍會生效，這是產品的錯，第五項檢查會量到。

**S7 的例外**：S7 的 `.board` 左右內距 0、上緣 2px 欄線是風格層的定義（8.2），寬鬆的板內距 24 不套用到 S7；其餘寬鬆值 S7 照用。

**什麼時候用緊湊**：一屏要看大量列的後台——訂單與庫存清單、監控與日誌、對帳、權限表——而且使用者用滑鼠操作。使用者的選擇要記住（`localStorage` 的 `ds.density`）。

**不隨密度變的東西**：字級層級表（第四章的十四級；寬鬆只是把表格內文從 B2 換成 B1、容器標題從 H3 換成 H2，都在表上）、9.3 的間距原則（有框元件之間最小 `--sp-3`，三檔一樣）、焦點環、勾選框與開關的尺寸。

**寫法**：高度由 5.4 的 `--h-*` token 決定，所以三檔主要是在 `html[data-density="…"]`（與各套的 `:not([data-density])` 預設）上覆寫那八個 token；儲存格、卡片、板的內距以 `:where(html[…])` 包住前綴覆寫，權重與原規則相同、排在後面，`.t td.ck` 的右內距 0、`.desc.v` 的上下內距 0 這類更具體的規則照樣有效。風格檔不得出現密度規則（12.2 的純度檢查會擋）。元件庫的區塊由 `patch_v24.py`（緊湊）與 `patch_v26.py`（寬鬆與各套預設）產生，矩陣在 `density_cfg.py`。

**驗收**：`audit_sizes.py` 每套元件庫以 `#c1.normal`、`#c1.cozy`、`#c1.dense` 各量一次（只量該套開放的檔；S3、S5、S6 另量深色），前台示範頁量該套的預設檔，高度與儲存格內距照上表，框線貼合與分隔線重複的規則不變；七套眾數一致的檢查只看標準檔。現況 29 次量測 0 不合規。`verify_css_split.py` 加 `s6:cozy`、`s1:normal`、`s1:dense`、`s7:normal`，19 種 0 差異；`audit_contrast.py` 的 S1、S7 預設寬鬆、`s6:cozy`、`s1:dense` 共 60 組 0 不及格。

## 六、RWD 響應式規範

### 6.1 斷點定義

```css
/* 手機直立 */            @media (max-width: 479px)
/* 大手機／手機橫向 */     @media (min-width: 480px) and (max-width: 767px)
/* 平板 */                @media (min-width: 768px) and (max-width: 1023px)
/* 筆電 */                @media (min-width: 1024px) and (max-width: 1279px)
/* 桌機 */                @media (min-width: 1280px)
```

實務上只有兩個斷點真正改變版型，其餘只是微調：

- **768px**：主要分界。側欄收合、多欄變單欄、表格轉卡片。
- **480px**：次要分界。網格清單從兩欄變一欄（商品卡列表例外，維持兩欄，見 6.3）、按鈕改為滿版寬度。

五個級別的名稱（v22）。名稱給第六、九章與日後的版型條文引用；CSS 的 media query 照舊寫像素：

| 級別 | 範圍 | 原名 | 欄格（6.5） |
|------|------|------|------|
| 緊湊 | < 480px | 手機直立 | 4 欄 |
| 中 | 480〜767px | 大手機／手機橫向 | 8 欄 |
| 平板 | 768〜1023px | 平板 | 8 欄 |
| 寬 | 1024〜1279px | 筆電 | 12 欄 |
| 特寬 | ≥ 1280px | 桌機 | 12 欄 |

對標：Material 3 的視窗級別是 600／840／1200／1600，IBM Carbon 是 672／1056／1312／1584；本規範沿用既有的 480／768／1024／1280，只補級別名稱與欄數。

### 6.2 容器寬度

| 情境 | 最大寬度 | 左右內距（即欄格外邊距，6.5） |
|------|----------|----------|
| 後台內容區 | 1060px | 寬與特寬 `--sp-6` 24px／平板 `--sp-5` 20px／中與緊湊 `--sp-4` 16px |
| 前台頁面 | 1080px | 同上 |
| 表單型頁面（結帳、設定）與**長文閱讀** | 720px | 同上 |

v22 以前桌機寫 26px，26 不在 5.1 標尺上；元件庫與 `dist/` 本來就用 24px，改的是條文。720px 容器加「長文閱讀」用途：一行約 40 個中文字，落在 W3C 中文排版需求（clreq）建議的範圍內。

超過最大寬度時內容置中，兩側留白。不做滿版拉伸——表格列太長會讓眼睛從左掃到右時掉行。

### 6.3 各類畫面的響應行為

**導覽框架**

| 斷點 | 行為 |
|------|------|
| ≥ 1024px | 左側欄固定展開 226px，內容區自適應 |
| 768〜1023px | 側欄縮成 64px 只留圖示，滑鼠移上去展開浮層 |
| < 768px | 側欄完全隱藏，改為左上角漢堡選單開啟的抽屜（覆蓋式，右側半透明遮罩） |

**資料表格**——最關鍵的響應處理

| 斷點 | 行為 |
|------|------|
| ≥ 1024px | 完整表格，所有欄位顯示 |
| 768〜1023px | 隱藏次要欄位，保留識別碼／名稱／狀態／數值；仍放不下時表格容器橫捲（v27），不壓欄位、不在兩個中文字之間斷行 |
| < 768px | **表格轉為卡片列表**：每筆一張卡，識別碼與數值在第一行左右對齊，次要資訊在第二行，狀態膠囊在右下，整張卡可點 |

表格在手機上做水平捲動是下策——使用者看不到全貌、容易漏讀。卡片化雖然佔垂直空間，但每筆資料完整可讀。

**卡片列的版面（v27）**：`base.css` 在 768 以下自動把 `table.t` 排成卡片，表頭隱藏。每張卡第一行左邊是第一欄（識別碼，加粗、不折行），右邊是金額欄（`.amt`）；其餘每格一行，前面帶欄名；狀態膠囊在最後一行右側，列內只有一顆按鈕的格（「預覽」「確認」）在最後一行左側；有勾選欄（`.ck`）的表格，勾選框在第一行最左。欄名來自每格的 `data-l`，產品頁不用手寫——`theme.js` 載入時依表頭自動補上，動態新增的列再呼叫一次 `DS.labelTables()`。選取列（`.sel`）整張卡淡底，欄名改主文字色（4.5 第四條）。表格標題列 `.tcap` 的篩選膠囊與按鈕另起一行並橫滑。v26 以前的寫法是把表格改成 `display:block` 橫捲，表頭與表身各自排欄寬，欄位對不齊，已退場。

**主體＋摘要面板**（左邊操作、右邊即時結果）

| 斷點 | 行為 |
|------|------|
| ≥ 860px | 左主體區 ＋ 右側 340px 摘要面板（並排） |
| < 860px | 單欄堆疊：主體在上、摘要在下 |
| < 768px | 摘要改為**底部固定條**：永遠停在畫面底部，顯示關鍵數值與主要動作按鈕；點一下展開完整明細 |

底部固定條是行動裝置的標準做法——使用者在上方操作時，關鍵數值與主要按鈕始終在拇指可及之處，不必捲到底。

**網格清單**

| 斷點 | 欄數 |
|------|------|
| ≥ 1024px | 4 欄 |
| 768〜1023px | 3 欄 |
| 480〜767px | 2 欄 |
| < 480px | 1 欄 |

**例外：商品卡列表在 480px 以下維持 2 欄。**商品卡列表指「圖片 ＋ 名稱 ＋ 價格」的格狀清單（電商的商品列表、目錄頁）。單欄時一屏只看得到一件商品，比價與瀏覽都很吃力，業界的電商在手機上幾乎都是兩欄。兩欄時卡片只剩 150px 左右寬，必須同時做到四件事：

1. 卡片內距收為 `--sp-3`（12px），欄間距收為 `--sp-3`。
2. 商品名稱最多兩行，超出以刪節號截斷（`-webkit-line-clamp:2`）。
3. 次要資訊只留最必要的：評價只留星等、拿掉評價數。
4. 「加入購物車」改為卡片右下角的圖示鈕（44 × 44px，`aria-label` 寫明商品名稱），不放文字按鈕。

其他網格清單（文章卡、服務方案、相簿）照上表在 480px 以下改單欄。完整示範見 `storefront_s*.html` 的「本週新品」。

**清單＋摘要**

| 斷點 | 行為 |
|------|------|
| ≥ 860px | 左清單 ＋ 右摘要（並排，摘要 sticky 吸附） |
| < 860px | 單欄：清單在上、摘要在下、主要動作按鈕滿版 |

**描述清單放進卡片一律兩欄（v26）**：`.desc` 預設是「標籤／值／標籤／值」四欄，給表單與詳情頁的寬容器用；放進卡片或摘要方塊（`.card`、`.cardx`，寬 330〜360px）時每格只剩 100px，「13:30–15:00」「陳師傅（五星）」這類值必折行。`base.css` 的 `.card .desc,.cardx .desc` 固定成兩欄（`max-content 1fr`），不分密度、不分寬度。

### 6.4 行動裝置的通則

- **相鄰可點元件之間至少留 8px 間隔**（觸控目標尺寸見 5.4）。
- **表單欄位單欄化**，不在手機上並排兩個輸入框。
- **主要動作按鈕滿版寬度**（`width:100%`），次要動作放在其下方或收進「⋯」選單。
- **避免 hover 才出現的功能**。手機沒有 hover 狀態，所有功能必須用點擊可達。表格列的操作按鈕在桌機可以 hover 才浮現，但手機版必須常駐顯示。
- **輸入框加上正確的 inputmode**：數量與金額欄位設 `inputmode="numeric"`，電話設 `type="tel"`，這樣手機會直接跳出數字鍵盤。

### 6.5 欄格系統（v22）

**定義**：內容區鋪一張 12 欄流體格。欄數隨級別變（6.1：寬與特寬 12 欄、平板與中 8 欄、緊湊 4 欄），欄距固定，外邊距等於 6.2 的容器左右內距。欄寬由瀏覽器算，規範不給像素值。全站只有這一張欄格。

**混合格**：固定寬的區域不佔欄格——側欄 226px、主體旁的摘要面板 340px（6.3）、側滑面板 480／640px 都是固定寬；欄格只鋪在剩下的流體內容區。9.1 的側欄式框架就是這個做法。

**跨欄只開五種**：12（全寬）、6＋6（對半）、8＋4（主體加輔助）、4＋4＋4（三等分）、3×4（四等分）。其他分法不開放，避免每頁一種切法。寬級別以下的退化：

| 寬與特寬（12 欄） | 平板與中（8 欄） | 緊湊（4 欄） |
|---|---|---|
| 12 | 8 | 4 |
| 6＋6 | 4＋4 | 4、4 堆疊 |
| 8＋4 | 8 在上、8 在下 | 堆疊 |
| 4＋4＋4 | 4＋4，第三個換行 | 堆疊 |
| 3×4 | 4＋4、4＋4 | 堆疊（商品卡列表維持兩欄，6.3） |

6.3 的網格清單（4／3／2／1 欄）與商品卡兩欄例外維持不變：它們是一批同質卡片依寬度自動排列，不走跨欄。欄格管的是頁面上「不同區塊怎麼分寬度」，網格清單管的是「同一種卡片排幾欄」，兩者不衝突；網格清單整體放在欄格的一個 12 跨欄裡。

**欄距兩檔**（對標 Carbon 的欄距模式；只開兩檔，不開第三檔）：

| 檔 | 值 | 用在 |
|---|---|---|
| 標準 | `--sp-6` 24px | 預設，所有頁面 |
| 緊湊 | `--sp-3` 12px | 緊湊級別（< 480px，自動切換）；商品卡列表（6.3 的兩欄例外）；S6 石墨的資料密集儀表板、統計卡列與卡片格；緊湊密度（5.7）下全頁自動改用 |

緊湊檔只縮欄距，不改欄數、不改外邊距、不改卡片內距；卡片內距要跟著縮時依 6.3 商品卡的寫法另外指定 `--sp-3`。表格內部靠儲存格內距 12／20 處理，不需要第三檔。

**實作**：在 `dist/base.css`（結構層），風格檔不得覆寫。桌機與平板要用緊湊檔時加 `.dense`：

### 6.6 手機與平板版面（v27）

**為什麼要這一節**：元件在 1280 寬排得下，到了手機與平板就會被壓扁。v26 以前的檢查只量 1280、溢出檢查只看整頁會不會橫捲，所以「沒有溢出、卻被擠成直排或斷字」的問題一直沒被量到（《手機版面稽核報告 v1》：14 項，最嚴重的五項七套都有）。

**三條通則**：

一、**單行元件不折行**。按鈕、篩選膠囊、選項 chip、狀態膠囊、屬性 tag、分段控制的選項、頁籤、側欄項目、分頁器按鈕、步驟膠囊一律 `white-space:nowrap`；表格裡的單號與日期 `.dt` 也是（v28：識別碼從連字號斷開就讀不出來，整欄放不下時由表格容器橫捲）。**999px 圓角只給永遠單行的元件**：會長高的容器用 `--r-lg` 或 `--r-sm`，否則一換行就變成圓餅。
二、**放不下時由所在的列處理，不擠壓元件**。按鈕列（批次列、側滑面板與彈窗的底部、步驟精靈的上一步／下一步、表格標題列）允許換行；同質的一排膠囊或選項（分段控制、表格標題列的篩選膠囊、分頁器）不換行、改橫滑，捲軸隱藏。
三、**表格文字不在兩個中文字之間斷行**。`.t th, .t td` 一律 `word-break:keep-all`：只在空白與標點斷行，「大同機械」不會一字一行；整欄放不下時讓表格容器橫捲（平板以上），手機則轉卡片（6.3）。

**各元件的手機行為（< 768px）**：

| 元件 | 行為 |
|---|---|
| 表格 | 轉卡片列，見 6.3 |
| 唯讀步驟 `.flow` | 改直排、箭頭朝下；外框改 `--r-lg`。各寬度：走過的步驟前加「✓」（10.2，不只靠顏色），換行時上下留 `--sp-3` |
| 步驟精靈 `.stepper` | 圓點置中（v17 的正圓保護規則曾讓圓點靠左，連接線多出一截，各寬度都修正） |
| 側滑面板 `.drawer` | 全寬；單號與關閉鈕同一行，狀態換到第二行；明細的欄名不折行 |
| 級聯選擇 `.casc` | 每一層改成一列、各自橫滑，不再左右三欄 |
| 分段控制 `.seg` | 各寬度：放不下時橫滑，選項文字不折行 |
| 分頁器 P1、P2、P4 | 放不下時橫滑 |
| 觸控尺寸 | 照 5.4「手機觸控尺寸補列」 |

**前台示範頁**另有兩條：頂列 logo 不折行；獨立的文字連結（logo、頁尾連結、「全部商品」這類延伸連結）手機上點擊高度 4.4rem，段落裡的連結不受此限。

**驗收：交付前跑 `check_layout.py`，這是第七項自動檢查。** 在 360、390、768、1024 四種寬度渲染七套元件庫、七張前台示範頁、八張範例頁，量十一類：有框元件貼合（< 8px）、分隔線貼容器（< 12px）、膠囊變形（999px 圓角被撐到單行高度的 1.6 倍以上）、短標籤折行（八個字以內斷成兩行以上）、逐字斷行、內容被裁切、突出容器、懸空分隔符（箭頭、斜線換行後落在行首或行尾）、觸控目標（< 768：純圖示 < 44×44、文字可點元件高度 < 40、輸入框 < 44）、文字重疊、整頁溢出。每筆歸到元件節並截證據圖。刻意的設計寫在腳本的例外清單裡（堆疊頭像、裝飾暈染、貼紙、次要說明文字、黏頂黏底列、捲動容器內看不到的部分），新增例外要寫明理由。現況 22 頁 × 四種寬度 0 不合規；拿 v26 的元件庫重跑仍抓得到原本的問題。另外 `audit_contrast.py` 可用 `--width 390` 在手機寬度跑（卡片列的欄名、選取列），現況 148 種組合 0 不及格。

## 七、元件規範

本章定義**每個元件必須實作的狀態**——這是最容易被漏掉的部分。完整的視覺樣式與互動細節見各風格的元件庫檔案。

### 7.1 元件清單與必要狀態

| 2 | 輸入框 Input | 預設／focus 聚焦（2px 主色外框，見 10.3）／error 錯誤／disabled／唯讀／有值與 placeholder（佔位文字用 `--muted`，見 10.1） |

### 7.2 分頁器規格

全站統一使用 **P4 底線數字式**：無框純數字，目前頁為 accent-1 色＋字重 700＋2px 底線。放在表格外框的表尾區右側。選定理由是視覺重量最輕，不會跟表格內容搶注意力。

### 7.3 幾個容易做錯的元件

**數量調整器**：必須即時驗證數值範圍與級距規則。不符時不是跳錯誤訊息打斷使用者，而是「按鈕鎖住＋下方一行紅字說明」，讓使用者自己修正。

**空狀態**：兩種情境要分開處理。首次使用的空狀態要給行動指引（告訴使用者第一步可以做什麼）；篩選後無結果的空狀態要給「清除篩選」按鈕。用同一個畫面處理兩種情境是常見錯誤。

**載入中**：表格與列表一律用骨架屏。轉圈圈會讓使用者不知道要等多久、也不知道即將出現什麼；骨架屏先把版面撐開，內容到位時不會跳動。

**警示條與提示框**：這兩個元件最常被做得太重。警示條用**淡底 ＋ 1px 同色細框**，不再加粗左色條——底色、框線、左色條、圖示、獨立標題行五種手法同時用，四則排在一起整區就變成色塊牆。另外三條守則：

- **標題是選用的。** 一句話講得完就不要拆成標題加內文；標題與內文併在同一段，短訊息只有一行高。
- **動作最多一顆，而且是文字按鈕。** 實心膠囊鈕在淡底上太搶，會跟頁面的主按鈕打架。
- **錯誤與警告不給關閉鈕。** 使用者需要一直看到的訊息不該能被關掉；只有成功與中性提示可以關。
- **文字動作與關閉鈕要跟內文站在同一條基線上。** 它們現在是文字、不是按鈕，要和內文共用同一個行框（同字級、同行距、靠上對齊），不要再給它 `min-height`——按鈕那個 32px 的最小高度會把整列撐高，變成內文靠上、連結置中，差將近 6px。

提示框則改成**中性灰底塊**，不帶語意色也不帶品牌色、不加框線與左色條。提示框不代表「有事情要處理」，只是補充脈絡；長得像警示條就會被誤讀。

**危險動作**：所有不可回復的動作（刪除、取消、解除綁定）一律二次確認，且確認彈窗要寫明「會發生什麼」與「無法復原」，不是只問「確定嗎」。

### 7.4 圖示

**全站只用一套圖示：Lucide**（開源線條圖示庫，ISC 授權，可商用，只需保留授權聲明）。不得混用其他圖示庫，也不得混用線條與實心兩種畫法——同一畫面出現兩種畫法，會像兩個系統拼起來的。

| 尺寸 | 配哪一級字 | 用在哪 |
|---|---|---|
| 16px | B2、B3、L1 | 按鈕內的小圖示、表格列、標籤、說明文字旁 |
| 20px | B1、H3、主要按鈕 | 一般按鈕、表單欄位前後、側欄項目 |
| 24px | H2、獨立圖示鈕 | 頂列的搜尋、會員、購物車、選單；服務承諾列 |
| 48px | — | 空狀態、結果頁、圖片佔位的插圖 |

- **線寬一律 2**（Lucide 預設），四個尺寸都不改。不得用縮放圖示來湊出中間尺寸。
- **顏色跟著文字走**（`stroke="currentColor"`），預設是文字色或次要文字色；只有在「它本身就是操作」時用主色。語意色只給狀態圖示（錯誤、警告、成功、資訊）。
- **圖示與文字的間距**：16px 圖示配 `--sp-1`（4px），20px 以上配 `--sp-2`（8px）；圖示與文字垂直置中對齊。
- **純圖示按鈕必須有 `aria-label`**（給螢幕報讀器念的名稱），可點擊範圍至少 44 × 44px（見 5.4）；不是所有人都看得懂圖示，常用的才可以不帶文字（搜尋、關閉、選單、購物車），其餘一律圖示加文字。
- **裝飾性圖示加 `aria-hidden="true"`**，旁邊已經有文字的圖示屬於裝飾，不要讓報讀器重複念。
- **版本要鎖定**：專案引用的 Lucide 版本寫死（例如 1.52.0），不要用 `latest`，否則圖示形狀會在某天無聲改變。
- **風格不改圖示**：七套風格共用同一組圖示，手帳風格也不換成手繪圖示。圖示是語意，不是材質。

## 八、風格家族 S1〜S7

### 8.1 風格與結構的關係

風格是「殼」，結構是「骨」。第三章到第七章的所有規範（色彩三層、字級層級、間距標尺、元件狀態、RWD 行為）**七套風格一體適用**。風格只改變表面材質——陰影、背景、框線質感、形狀細節。

因此換風格不需要重寫元件邏輯，只需要替換一組樣式定義。

**v20 起這句話名實相符**：七套共用 S1 的元件 HTML 與結構，S2〜S7 都是「S1 ＋ 一層材質」。v19 以前 S2〜S5 是各自獨立的元件庫，標記與規則順序各走各的，換風格其實要換整份樣式表；現在換風格只換一個檔、一個 `data-style`。新增元件只在 S1 加一次，七套自動帶上，各套若需要不同的材質，加在該套的材質層（`material/` 或 `style-s*.css`），不得改結構。

**S7 的編輯紀律**：一、外層區塊不加框，改用上緣 2px 墨線分段（雜誌的欄線）；框只留給卡片與輸入元件，而且是 1px 細線。二、明體只給標題，內文一律黑體。三、外層區塊不留左右內距，內容與欄線的左緣對齊；欄線到內容之間留 `--sp-6`。

**S2 的互動語意**：凸＝可以按、凹＝已選中或輸入區。這組隱喻要貫徹全站，不可混用。

**S5 的漸層紀律**：漸層只准出現在三個地方——強調按鈕、重點標記、hero 數字與目前狀態節點。其餘一律純色。「強調按鈕」就是實心主按鈕 `.btn.primary`（每頁最多一顆；按鈕語彙七套共用，沒有另一個強調變體）；停用時回到灰底灰字。漸層一旦濫用立刻顯得廉價。

**S6 的三條鐵則**：一、側欄與頁面同色，只有卡片是白的——「只有資料躺在白紙上，其餘都是同一張桌面」；做成側欄白、頁面灰就變成另一套風格。二、灰階是純無彩色，每個灰的紅綠藍三值必須相等（見 3.5）。**唯一例外是深色模式的「跟隨色系」**（8.8.5）：六個面可帶目前色系主色的色調，OKLCH 彩度不得超過 0.015，明度與中性值相同；文字色仍是純無彩色。三、表格區不用品牌色，只有選取列例外——篩選膠囊選中、側欄 hover、分段控制都用中性灰 `--sel`，品牌色只留給主按鈕、連結、側欄選中項、目前頁籤、選取列。這三條是 S6 安靜的來源。跟隨色系不影響鐵則一與鐵則三：它是整張桌面一起帶色調，側欄、頂列、頁面仍是同一個色；面的色調不承載任何意義，不算「品牌色出現在表格區」。

**S1 與 S6 是一對**：奶油是暖的、軟的，給文件與對外畫面；石墨是冷的、硬的，給工程師與內部工具。後台預設仍是 S1；當專案希望後台有「工具感」而不是「文件感」時選 S6。

### 8.4 矩陣判定的理由與調整方式

**S1 奶油：全部可用。**這是它作為預設風格的價值——中性到不挑色。暖白底與暖色系（C6、C7、C8、C11、C12）最和諧；C4 電光紫彩度最高，在奶油的克制氣質裡略跳，列為可用；SC2 鈷藍 × 亮橘同理，列為可用。

**S2 浮雕：偏好中明度、與底色同調的顏色。**浮雕的底色是冷灰藍 `#E6EAF0`，靠柔和陰影營造立體。

- △ C6 胡桃棕、C7 焦糖磚橘、C8 暖墨：暖色與近黑放在冷灰底上會顯得髒或太硬。**調整方式**：把底色整組換成暖灰 `#EDE8E0`，陰影色同步調暖。
- ✕ SC1：亮黃塊在冷灰底上像貼紙，且副色與底色邊界對比只有 1.35，選型介面直接鎖住。
- ✕ SC2：亮橘配浮雕墨色只有 4.32，承載文字不及格，鎖住。
- △ SC3：石板藍與冷灰底同調；冰川青填色自動加 1px 墨色框線。

**S3 琉璃：需要兩個色有足夠色相差才能形成漂亮漸層。**十二組都沒有純黑，不再需要漸層專用替代色。

- ○ C6、C7、C8、C11、C12：兩端彩度低或一端接近墨色，漸層乾淨但平淡，適合想低調的專案。
- ◎ SC1：深綠到相思黃的漸層疊白玻璃後是淡奶黃，是琉璃最好看的組合之一。
- ◎ SC2：鈷藍到亮橘的對角漸層，最有活動頁的張力。○ SC3：兩端都是冷色，乾淨但平淡。

**S4 手帳：需要暖色或高彩度，冷靜的顏色與手繪氣質互斥。**

- ◎ C5〜C9、C11、C12：暖色與自然色在暖紙底上最自然。
- △ C3 深靛、C4 電光紫：偏冷，彩度高勉強可用；若必須使用建議改選 S1。
- △ SC1：暖紙底偏黃，黃色塊會糊進去；副色填色元件自動加 1px 墨色框線後可用（語彙即「螢光筆」）。
- △ SC2：副色填色同樣自動加框線；鈷藍偏冷。△ SC3：冷色與手繪氣質互斥，若必須使用建議改選 S1。

**S5 極光：需要能柔和暈開的中低彩度色。**

- △ C7 焦糖磚橘、C8 暖墨：一端是近黑的暖墨，暈染開來偏灰，不是發光。若要用，把暈染改成只取主色端。
- ◎ SC1：深綠與黃的柔霧暈染即極光本身，是 SC1 最推薦的風格。
- ◎ SC2：藍與橘的暈染帶出暖光。○ SC3：冷色暈染偏灰，像晨霧。

**S6 石墨：對色系最寬容的一套**（S7 編輯同樣沒有任何一格需調整或鎖住），沒有任何一格「需調整」或「鎖住」。原因是這套風格本來就把品牌色壓到最少——主色只出現在主按鈕、連結、選中列、目前頁籤、側欄選中項；副色只出現在來源標記、圖表第二數列、趨勢數字三處，剛好是 3.4「副色每頁最多三處」的上限。深色系（C8 暖墨）與亮色系（C4 電光紫、C10 節慶桃紅）都不會失控。

- ○ C6 胡桃棕、C7 焦糖磚橘、C11 燒橄欖、C12 玫瑰棕：暖色系放在純無彩色的冷灰結構上略有色溫衝突，但對比全數通過，可用。若專案以暖色為品牌主色，建議優先考慮 S1 奶油。
- ◎ SC1：白卡上的黃色塊乾淨，判定同 S1。
- ○ SC2：對比全數通過，但高彩度與石墨的克制相反，只建議給開發者產品的活動頁。◎ SC3：純無彩灰配冷灰藍，最像工具的一組。

**S7 編輯：全部可用，靠墨色撐場。**暖白紙與墨色是中性的，十五組都通過；雜誌的品牌色通常就是一個沉穩的色加大量黑白。C8 暖墨、C9 唇膏紅、SC3 石板藍最像雜誌；C4 電光紫、C10 節慶桃紅彩度高、C12 玫瑰棕偏柔，與雜誌的克制略有距離，列為可用；SC1、SC2 的淺型副色在紙上也成立，但不是這套風格的語彙，列為可用。

### 8.5 通則：近黑色系用在漸層類風格

十二組核心已無純黑（原含純黑的四組於 v5 退場或改為暖墨、炭灰），v4 的「純黑替代色」與 `--acc-grad` 第四組變數**整段刪除**。剩下的一條通則是：C7 焦糖磚橘的副色炭灰 `#2B2B2B` 與 C8 暖墨的主色 `#23201E` 屬近黑，在 S3 琉璃可用（玻璃會提亮）、在 S5 極光列為需調整（暈染只取另一端的彩色）。

### 8.6 風格的技術實作

每套風格是一個獨立的 CSS 檔案（或一個 class 命名空間），載入後覆寫元件的表面樣式，**不碰任何色彩變數與尺寸變數**。

```html
<!-- 風格以 class 掛在根元素，色系以 CSS 變數注入 -->
<body class="style-cream"
      style="--acc:#B4552D;--acc-soft:#F8EBE3;--acc-deep:#A54C27;
             --acc2:#212121;--acc2-soft:#ECECEC;">
```

```css
/* base.css：所有風格共用的結構、字級、間距、RWD */
/* style-cream.css：.style-cream .card{ border:1px solid var(--line); border-radius:16px; box-shadow:none } */
/* style-emboss.css：.style-emboss .card{ border:none; box-shadow:7px 7px 14px var(--sh-d), -7px -7px 14px var(--sh-l) } */
/* style-graphite.css：.style-graphite{ --page:#FBFBFB; --card:#FFF; --line:#E3E3E3; --r-lg:12px; --r-sm:6px } */
```

**△ 的條件**

- **S2 浮雕用在後台、內部工具、SaaS、內容頁**：只適合表格少的頁面。整頁同一個底色、沒有白色卡片讓眼睛休息；可點與不可點、啟用與停用只靠柔影區分，大量小字的資料表掃讀吃力。用在電商與品牌前台時，商品圖與內容沒有白底可以依託。
- **S3 琉璃用在少資料工具與服務型前台**：玻璃面板上的元件邊界弱，按鈕密集時不好分辨；iOS Safari 不支援 `background-attachment:fixed`，漸層會跟著捲動，小螢幕上整片漸層也會壓過內容，採用前要上實機確認。
- **S4 手帳用在 SaaS 主介面**：只有品牌個性本身就是產品賣點時才用；表格頁的手繪框是噪音，會拖慢掃讀。
- **S5 極光用在開發者與內部工具**：背景暈染對長時間專注是干擾，除非品牌明確要求，否則改選 S6。

**選型三條規則**

1. **先看系統類型，再看品牌調性，最後才挑色系**（8.3）。判斷系統類型只問兩件事：使用者一天看它多久、畫面上資料多不多。
2. **一個系統只有一套風格。**同一個系統同時有前台與後台時，以使用時數最長的那一端決定：點餐系統的店家每天開著後台八小時、顧客點一次三分鐘，就照後台選。前台與後台若是分開的兩個系統（不同網址、不同使用者群），可以各選一套。
3. **字級套與風格無關。**同一套風格裡，做事的頁面用 Productive、看的頁面用 Expressive（見 4.3）；電商的結帳流程仍是 Productive。
4. **密度是系統層的決定，風格只給預設。**S6 預設標準，其餘預設寬鬆（5.7 的矩陣）；一個系統一檔，報表頁可單獨往緊的方向覆寫一次，不得往鬆。

### 8.8 深色模式（S3 琉璃、S5 極光、S6 石墨）

**深色是風格的模式，不是另一套風格。**同一套風格有白天與夜間兩個模式：結構、圓角、陰影的形狀、框線粗細、字型、字級、間距全部不變，只換第二層灰階、第三層語意色、第四層資料色，第一層品牌色另算一組深色值。色系的可用與調整規則沿用該風格的淺色（8.3 的三列深色與各自的淺色列相同）。v14〜v22 的 S6 深色是一份獨立示範頁、在瀏覽器裡排成第八套風格「S6D」，容易讓人以為深色是另一套殼；v23 起深色規則直接寫在該風格的元件庫頁面裡，設計系統瀏覽器在「風格」下面多一列「模式：淺色／深色」，在同一套風格裡切換。

**有深色的三套與理由**：

| 風格 | 為什麼適合深色 | 深色長什麼樣 |
|---|---|---|
| S6 石墨 | 純無彩灰、零陰影、細線，翻成深色最自然 | 近黑頁面、卡片亮一階、1px 灰線；預設帶目前色系主色的極淡色調（跟隨色系，8.8.5） |
| S3 琉璃 | 毛玻璃本來就有「深玻璃」一種（淺色版的導覽層），深色只是把它升格成主材質；深底上的半透明與背景模糊反而比淺底更明顯 | 壓暗的品牌雙色漸層 ＋ 80% 深玻璃面板 ＋ 白 5〜9% 的薄霧元件 |
| S5 極光 | 暈染在近黑底上像真的極光，比淺底更有辨識度 | 近黑底 ＋ 三團提亮後的主副色柔霧 ＋ 84〜96% 的深色霧面板 |

**不做深色的四套**：S1 奶油（暖紙色就是它的身分，翻成深色只剩一般的深灰後台，與 S6 深色重疊）、S2 浮雕（凸凹柔影靠「同色底上的亮面與暗面」成立，深底上亮面變灰、暗面看不見，立體感消失）、S4 手帳（手繪硬影與紙張紋理是印在淺紙上的隱喻）、S7 編輯（紙本雜誌的白紙黑字，深色會變成另一種閱讀器）。需要深色的專案，風格選 S3、S5、S6（8.7）。

**什麼時候提供**：使用者長時間盯著的工具型後台、監控與維運畫面、開發者工具、夜間作業的系統，以及品牌明確要深色調的前台。預設跟隨作業系統的設定（`prefers-color-scheme`），並提供手動切換：淺色／深色／跟隨系統三選一，使用者的選擇要記住。

#### 8.8.1 三套共用的做法

**品牌色的深色值**——主色在淺色模式同時當填色（配白字）與文字色；到了深色底，同一個顏色不可能兩邊都過 4.5（夠亮才能當字，夠亮就配不了白字）。所以深色模式的規則是：

1. 主色在 OKLab 色彩空間**只加明度、保留色相**，加到「本套最亮的面板上 ≥4.6、自己的淡底上 ≥4.8」為止；超出 sRGB 色域時降低彩度而不是逐通道硬切。用 OKLab 而不用 CIELAB：CIELAB 的藍色提亮時色相會往紫偏。「最亮的面板」S6 是卡片 `#1A1A1A`、S3 是 `#1F2433`、S5 是凸面 `#262A36`——面板越亮，主色要提得越亮，所以同一組色系在三套的深色主色不同。
2. 淡底 ＝ 深色主色 16% 混入同一個面板色。
3. **填色上一律放深色字**（`--on-acc` ＝ `#121212`），不放白字。
4. 副色填色提亮到面板上 ≥3.0；深副色（當字用）提亮到面板、副色淡底、主色淡底上都 ≥4.8。
5. 門檻比 4.5 多留 0.1〜0.3：小字的反鋸齒會讓實測底色偏亮，C5 森林綠計算 4.61、實測只有 4.44。
6. 語意色四色三套相同（深色值 `#F28B82`／`#E2B341`／`#74C483`／`#7DB6EE`），淡底為該色混入本套的實心面，混入比例以「自己淡底上 ≥4.8」為準。
7. 資料色第四層八色，深底上不到 3.0 的（`--d1` 三套都是）在 OKLab 只加明度提到 3.2 以上；S6 只換 `--d1`，S3、S5 的面板較亮，另換幾色（見各套）。

**寫法**：同一份元件 HTML、同一張樣式表。深色規則一律掛在 `html[data-theme="dark"]` 底下：灰階、語意色、資料色以根變數區塊覆寫並宣告 `color-scheme:dark`（讓捲軸與原生表單控件跟著變深）；元件裡寫死的顏色由 `build_dark.py` 轉一份深色值，**緊接在原規則之後**插入、以 `:where()` 包住前綴（權重為 0，疊加順序與原本完全相同）。品牌色深色值由 `theme.js` 的 `DARK` 表（依風格分表）在切換時套用。元件裡填色上的白字改引用四個變數——`--on-acc`（主色填色上）、`--on-acc2`（深副色填色上）、`--on-err`（錯誤紅填色上）、`--on-ink`（提示氣泡、Toast 這類墨色底上）；淺色模式四者都是白，深色模式都是 `#121212`。**新寫的元件請直接引用變數，不要再寫死 `#fff` 或淺灰**，否則深色模式會冒出白塊。例外是疊在圖片上的半透明深色遮罩，上面的白字照舊；S3、S5 的深色氣泡（Toast、提示氣泡）改亮一階、字維持淺色。

**切換**：`<html data-theme="dark">` 強制深色、`data-theme="light"` 強制淺色、不寫則跟隨系統；`dist/` 的三個風格檔同時輸出兩段（`html[data-theme="dark"]` 與 `@media (prefers-color-scheme:dark)`），切換不換檔、不重載。元件庫示範頁以網址 `#c1.dark` 或頁首的「模式」鈕切換；設計系統瀏覽器的網址寫成 `#s6/c1/dark`，舊連結 `#s6d/…` 自動轉成 S6 深色。S6 另有「深色底：跟隨色系／中性石墨」二選一（8.8.5）：網址加 `.neutral`（`#c1.dark.neutral`）、頁首「深色底」鈕、瀏覽器「模式」下面的「深色底」一列（`#s6/c1/dark/neutral`）。

**驗收**（v23 起交付前多三項）：
- `verify_dark.py`：一、淺色模式下，插入深色規則前後每個元素的計算樣式完全相同；二、插回同一頁的深色與「整份換成深色」的對照頁逐元素相同（證明沒有被淺色規則蓋掉）；三、同一頁淺深兩模式的字級、行距、字距、內外距、間距、高度、圓角、框線粗細與元素大小完全相同——深色只准換顏色，所以行高稽核、token 檢查與尺寸稽核淺色過了深色就過。七份元件庫與七張前台示範頁皆 0 差異。
- `audit_contrast.py s3:dark,s5:dark,s6:dark`（前台示範頁寫 `sf-s3:dark`）：三套 × 十五組，元件庫與前台示範頁共 90 次掃描，**0 處不及格**。
- `verify_css_split.py` 的深色兩種入口（`sX:dark` 指定深色、`sX:system` 跟隨系統）三套皆 0 差異。
- v29：`audit_contrast.py` 的 `s6:dark` 量的是預設的跟隨色系，`s6:dark+neutral`（網址 `#c1.dark.neutral`）量中性石墨，兩者 × 十五組 **0 不及格**；`verify_css_split.py` 加 `s6:dark+neutral`、`s6:system+neutral` 兩次；`check_tokens.py` 加一條：`DARK_TINT` 每個面的 OKLCH 彩度 ≤0.015、與中性值的明度差 ≤0.002，S6 深色文字三色紅綠藍三值相等。

v23 轉換時另以 S6 對 v22 的 `components_s6d_graphite_dark.html`、`storefront_s6d_graphite_dark.html` 逐元素比對：62 節與前台頁全部一致，S6 的深色值與 v22 一字不差。

#### 8.8.3 S3 琉璃

**材質**：淺色版有兩種玻璃——亮玻璃（白 70%，放資料）與深玻璃（墨色 66%，放導覽）。深色模式把深玻璃升格成主材質，依淺色版的不透明度分三級對應：

#### 8.8.5 S6 深色底：跟隨色系（預設）與中性石墨（v29）

**起因**：S6 深色原本是 `#121212` 系列的純無彩灰，整頁中性深灰。暗色模式不必是黑或純灰——Mercury 的導覽列 `#171721` 換算成 OKLCH 是 L 0.209、C 0.020、h 285，帶極少量品牌色調的深色保留了品牌個性，又不影響閱讀。S6 的做法是**底色自動帶一點目前色系主色的色調**，不讓使用者從多款背景挑（那會讓組合爆量）；使用者只多一個二選一的開關。

**開關**：

| 選項 | 寫法 | 效果 |
|---|---|---|
| 跟隨色系（預設） | 不寫，或 `<html data-dark-tint="follow">` | 六個面帶目前色系主色的色調，換色系時自動跟著換 |
| 中性石墨 | `<html data-dark-tint="neutral">` | 與 v28 以前完全相同：`#121212` 系列純無彩色（8.8.2） |

1. **預設是跟隨色系。**這代表既有 S6 專案升級到 v29 後，深色畫面會帶色調；要維持原樣的專案在 `<html>` 寫 `data-dark-tint="neutral"`，或在設定頁讓使用者切回。
2. **只對 S6 的深色有效。**淺色模式不受影響；S3 琉璃、S5 極光的深色本來就帶品牌色（漸層與暈染），不加這個開關。
3. 與色系、深淺、密度互相獨立，可任意組合。三處一致（4.2）：後台設定頁、使用者偏好（`localStorage` 的 `ds.darkTint`）、網址參數（`?tint=neutral`；元件庫示範頁網址加 `.neutral`，例如 `#c1.dark.neutral`）。生效順序：網址 ＞ 使用者偏好 ＞ 頁面寫的 `data-dark-tint` ＞ 預設跟隨。

**推導規則**（`code/dark_tint/derive_dark_tint.py`）：

1. **明度不動**：六個面（page、card、paperc、sel、line、line-2）各自保留中性值的 OKLab 明度，層次、線條與卡片的亮度差和中性石墨一模一樣。
2. **色相取主色**：取該色系**淺色**主色 `--acc` 的 OKLCH 色相。
3. **彩度固定且有上限**：面的彩度為 `min(0.012, 主色自己的彩度)`——主色本身接近無彩色的色系（C8 暖墨，主色彩度 0.006）只帶得到一半，不會比品牌本身還鮮豔。上限 0.015。偏紅的四組（C7、C9、C10、C12）也是 0.012，與錯誤紅 `--err` 的彩度差十倍以上，不會混淆。
4. **轉回 sRGB 十六進位**：超出色域時降彩度、明度色相不動。程式與規範裡只寫十六進位（3.9），OKLCH 只是推導方法。
5. **文字不帶色**：`--ink #EDEDED`、`--muted #A3A3A3`、`--dark #D4D4D4` 與四個 `--on-*` 深色字 `#121212` 一律不變。
6. **淡底照舊規則重算**：四個語意淡底與品牌兩個淡底仍是「該色 16% 混入卡片色」，卡片色變了就跟著變。
7. **品牌色深色值照 8.8.1 補明度**：主色在卡片上 ≥4.6、在主色淡底上 ≥4.8；深副色在頁面、卡片、淡底面三種底上都 ≥4.8；不夠時 OKLab 只加明度。

**驗算**：十五組各 31 項、共 465 項，**0 不及格**（主文字與次要文字放四種面、四個語意色放卡片與自己的淡底、主文字放六種淡底、主色放卡片與淡底、深副色放三種底、填色上的深色字）。主文字對比與中性石墨相差最多 0.09；餘裕最小的是 SC2 鈷藍 × 亮橘 的 acc 放 acc-soft 4.80（門檻 4.8）。同一套驗算以彩度 0 跑一次，十五組的面逐值等於中性石墨、品牌色不需補明度——驗算方法與 8.8.2 一致。渲染後逐節點的 `audit_contrast.py` 見 8.8.1 驗收。

**寫法**：`theme.js` 在「S6 ＋ 深色 ＋ 沒有寫 `neutral`」三個條件都成立時，把該組的六個面、四個語意淡底與品牌色注入 `:root`；任一條件不成立就移除這些行內變數，退回 CSS 的中性值。CSS 只寫中性值，所以**沒有 JavaScript 時是中性石墨**，這是可接受的降級。跟隨系統深淺時沿用既有的 `prefers-color-scheme` 監聽。

```js
DS.setDarkTint('neutral')   // 'follow'（預設）| 'neutral'；只對 S6 有效，其他風格呼叫無效果
DS.darkTint()               // 目前生效的值：S6 回 'follow' 或 'neutral'；其他風格回 null
DS.DARK_TINT                // 十五組的面、淡底與品牌色（由產生器寫入，不手抄）
```

產品自己的 CSS 不要寫死 `#121212`、`#1A1A1A` 或 `rgba(26,26,26,…)` 這類深色面板值，一律引用 `var(--page)`、`var(--card)`，半透明用 `color-mix(in srgb,var(--card) 95%,transparent)`；寫死的值在跟隨色系時會留一塊中性灰。

**跟隨色系不做的事**：不讓使用者自選色相或彩度（組合會爆量）；不讓文字帶色（帶色的近白字在小字級會發糊，也會跟語意色混淆）；不改淺色模式的 S6（淺色的辨識度就靠中性灰 `#F4F4F4`，和 S1 的暖白拉開）；不加到 S3、S5。

本節的表由 `build_spec_v29.py` 從 `code/dark_tint/dark_tint.json` 即時產生；改推導參數要依序重跑 `derive_dark_tint.py`、`build_dark.py`（逐值比對 `dark_tint.json`，不一致就中止）、`emit_css.py`。

### 9.3 頁面結構通則

任何新頁面都依此順序組裝，不要自創結構：

一、頁首區（標題＋副標＋動作按鈕）
二、摘要區（統計卡，選用）
三、篩選區（搜尋＋條件，選用）
四、主體區（表格／卡片／表單）
五、補充區（說明、相關資訊，選用）

區段之間間距 24px，區段內元素間距 12〜16px。

另外兩條結構規則（v21），針對「每個元件單看都對、放在一起卻線條打架」的情況：

六、**一處分隔只用一條線。** 區塊標題用了延伸細線（9.2 的「中文標題＋延伸細線」），下方就不再放分隔線或卡片標題列的底線；卡片標題列 `.card-title` 已有底線，標題就不再用延伸細線。兩個有框線的容器相鄰時也不再加分隔線——框線本身就是分隔。檢查方法：兩條線之間如果只有空白、沒有任何文字或元件，其中一條就是多餘的。

七、**有框線的元件相鄰時最小間距 `--sp-3`（12px）。** 按鈕列與輸出框、卡片與卡片、輸入框與按鈕，邊緣到邊緣至少 12px；並排的小按鈕、chip、膠囊可以用 `--sp-2`（8px，5.1 已允許）；低於 8px 視為框線貼合，第五項檢查不通過。刻意共用框線的組件不在此限：分段控制、數量調整器、分頁器、頁籤、表格內部，以及下拉選單與觸發元件之間的 `--sp-1`。

間距的三條原則（v22），讓看間距就能分出層級，不必靠框線或底色：

八、**內部間距 ≤ 外部間距。** 元件自己的內距不得大於它與鄰居的距離：卡片內距 16／20，卡片之間就至少 `--sp-6` 24px；儲存格內距 12／20，表格與下一個區塊之間至少 24px。內距比外距大，讀起來會黏成一團。

九、**區塊之間一律大於區塊內部。** 同一區塊裡的元素用 `--sp-3`〜`--sp-4`，區塊與區塊之間用 `--sp-6` 以上，頁面大區段用 `--sp-7`〜`--sp-8`。

十、**`--sp-1`、`--sp-2` 只用在元件內部，以及同一組並排的小元件之間。** 元件內部指圖示與文字、標籤到輸入框這類；同一組指一排並排的小按鈕、chip、膠囊（5.1 的 `--sp-2` 用途）。兩個獨立元件之間、或組與組之間最小 `--sp-3`——這就是第七條，兩條是同一條規則的兩面。這樣 4px 與 8px 不會跑到版面層。

對標：8pt 間距原則的「內部 ≤ 外部」與「相關的靠近、不相關的拉開」；本規範標尺以 4px 為基準，原則一樣適用。

## 十、無障礙規範

### 10.1 對比度

- 一般文字對背景 **至少 4.5:1**（WCAG AA 標準）。
- 大字（18px 以上且字重 700 以上）至少 3:1。
- 本規範第三章的所有色碼都已實測驗證，直接使用即符合標準。新增顏色前必須實測。
- **框線色不得拿來當文字色。** `--line` 與 `--line-2` 是給線條用的；拿來寫「不重要的字」（月曆的非本月日期、麵包屑的分隔符）對比只有 1.4，必然不及格。要淡就用 `--muted`。
- **半透明面板上不放彩色小字。** 琉璃與極光的面板是半透明的，副色或語意色的小字壓上去只剩 3.4〜4.2；改用主文字色，方向與好壞用符號加文字表達，不靠顏色。
- **佔位文字（placeholder）一律 `::placeholder{color:var(--muted);opacity:1}`。** 瀏覽器預設的 `#757575` 在白底 4.61 勉強過，但 S2 的輸入框是底色 `#E6EAF0`（3.82）、S6 深色的卡片 `#1A1A1A`（3.78）、S1 頁面底 `#F6F5F2`（4.23）都不及格；而佔位文字不是文字節點，v17 以前的對比稽核量不到它。v18 起 `audit_contrast.py` 把每個有佔位文字的輸入框當一個節點量。

### 10.2 不可只靠顏色

總則四的具體做法：狀態標籤用「● 待確認」，不是只有一個黃點；錯誤欄位用「紅框＋下方文字說明」，不是只把框變紅；圖表的每個數列除顏色外要有圖例或直接標註。

### 10.3 鍵盤操作

- 所有可互動元件必須能用 Tab 鍵到達，順序與視覺順序一致。
- **Focus 狀態必須可見，而且七套同一種寫法**：

```css
/* 鍵盤到達才顯示（:focus-visible），滑鼠點擊不顯示；一律 2px 主色，外推 2px */
.btn:focus-visible,.chip:focus-visible,.pillf:focus-visible,.tabs .tab:focus-visible,.nitem:focus-visible,
.seg button:focus-visible,a:focus-visible,[tabindex]:focus-visible{outline:2px solid var(--acc);outline-offset:2px}
/* 輸入框、下拉選單、多行輸入：外推 0，環貼著框線 */
input:focus-visible,select:focus-visible,textarea:focus-visible{outline:2px solid var(--acc);outline-offset:0}
```

  不可用 `outline:none` 移除而不補上替代樣式——換框線色不算替代樣式（1.5px 的框線在玻璃與浮雕底上看不出來）。v17 以前七套只有色系切換鈕照做，按鈕、chip、頁籤、側欄項目全是瀏覽器預設的 1px 黑框，輸入框 S1、S6、S7 寫 `outline:none` 再換框線色、S2 寫 outline，鍵盤使用者在七套裡看到三種焦點。**驗收**：`audit_sizes.py` 把每類可互動元件的第一個實例聚焦，計算值必須是 `2px solid` 且顏色等於 `--acc`。
- 彈窗開啟時焦點移入彈窗、關閉時歸還原按鈕；Esc 可關閉。
- 下拉選單支援方向鍵選擇、Enter 確認、Esc 關閉。

### 10.4 表單

- 每個輸入框都要有 `<label>` 並用 `for` 正確關聯，不可只靠 placeholder 當標籤（placeholder 在輸入後會消失，使用者會忘記這欄是什麼）。
- 必填用「文字標籤＋紅色星號」雙重標示，並在 `aria-required` 標記。
- 錯誤訊息放在該欄位下方、用 `aria-describedby` 關聯，讓螢幕閱讀器唸得到。

### 10.5 動態效果

- 轉場的時長、緩動與可動屬性見 5.5：一律引用 `--dur-*` 與 `--ease-*`，元件內不超過 320ms，不做會觸發重新排版的屬性。
- 尊重系統的「減少動態」設定。轉場時長已由 5.5 的 token 歸零；迴圈動畫（骨架屏、轉圈）另外用下面這段停掉：

```css
@media (prefers-reduced-motion: reduce){
  *{ animation-duration:.01ms !important; transition-duration:.01ms !important; }
}
```

## 十一、介面文案規範

文字是設計材料，不是裝飾。以下規則與視覺規範同等重要。

### 11.1 從使用者的角度命名

用使用者控制與認得的詞，不要用系統內部的說法。

| ✕ 不要寫 | ◎ 應該寫 |
|---------|---------|
| 建立 Variant | 新增規格 |
| Entity 設定 | 基本資料 |
| 同步主檔 | 更新資料 |
| Slug | 網址前綴 |

### 11.2 動作用主動語態，且全程同名

按鈕寫清楚按下去會發生什麼：寫「送出申請」不要寫「確認」；寫「儲存變更」不要寫「提交」。

**同一個動作在整個流程中必須同名**：按鈕寫「送出申請」，成功提示就要是「申請已送出」，不可變成「申請已建立」。介面的用語就是使用者學習系統的路標。

### 11.3 錯誤訊息

說明「發生什麼事」與「怎麼修正」，不道歉、不模糊。

- ✕「發生錯誤，請稍後再試」
- ◎「數量超出範圍，請輸入 1〜999」
- ✕「操作失敗」
- ◎「這個時段已被預約，請改選其他時間」

### 11.4 空狀態是邀請，不是報告

- ✕「無資料」
- ◎「還沒有資料。從右上角『新增』開始建立第一筆。」

### 11.5 語氣

句首大寫式的句子語氣（sentence case），不用全大寫中文，不用驚嘆號堆疊，不用「喔」「唷」等語尾助詞。對後台使用者的語氣是專業同事；對前台使用者的語氣是可靠的服務方。兩邊都不諂媚、不撒嬌。

### 11.6 一個元素只做一件事

標籤就是標籤、範例就是範例，不要讓 placeholder 兼任說明、不要讓按鈕文字兼任警告。需要補充說明就另開一行灰色小字。

## 十二、開發對接

這一章回答工程師開工第一天會問的四個問題：CSS 從哪裡引用、怎麼和框架搭、支援哪些瀏覽器、怎麼確認自己沒做歪。

### 12.1 檔案：引用，不複製

元件的樣式**不是**從示範頁 `components_s*.html` 的 `<style>` 複製出來用。公開倉庫 `art0428/webdesign` 的 `dist/` 由 `emit_css.py` 自七套元件庫產生，是唯一來源，每個檔頭都有版本號（與本規範同版）：

| 檔 | 內容 | 誰載 |
|---|---|---|
| `tokens.css` | 字級、行距、間距、圓角、高度、動態、層級 token（第四、五章） | 所有產品 |
| `base.css` | 結構層 ＋ S1 奶油的材質：62 項元件的 class、尺寸、焦點環、佔位文字、RWD、欄格 `.grid`（6.5）、密度三檔 `data-density`（5.7）。**S1 為基準** | 七套全部 |
| `style-s1.css` | 空殼（S1 材質已在 base），保持三檔載法一致 | S1 |
| `style-s6.css` | 石墨淺色 ＋ 深色（8.8），切換不換檔 | S6 |
| `style-s7.css` | 編輯的材質（明體標題、直角、欄線） | S7 |
| `style-s2.css`〜`style-s5.css` | 浮雕、琉璃、手帳、極光的材質（v20 起以 S1 為基底重建，與 S6、S7 同為薄檔）；`style-s3.css`、`style-s5.css` 另含深色（8.8，v23） | S2〜S5 |
| `theme.js` | 色系切換、鎖定規則、深淺模式、S6 深色底（`DARK_TINT`，8.8.5） | 所有產品 |

載入順序（七套相同）：

```html
<html lang="zh-Hant" data-style="s6">
<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="base.css">
<link rel="stylesheet" href="style-s6.css">   <!-- 全站只換這一行 -->
<script src="theme.js"></script>
```

順序不能換：風格層靠「排在後面」覆寫，權重與基準相同，不用 `!important`。v20 起七套一律三檔；v19 的 S2〜S5 過渡版（兩檔、不配 `base.css`）已退場，從 19.x 升上來的 S2〜S5 產品要把 `base.css` 加回去，元件 HTML 照 S1 的語彙（數量調整器用 `<input>`）。

**為什麼是「一份結構 ＋ 每套一個薄材質檔」而不是七份完整檔**：七套的 CSS 有九成以上規則一字不差，七份完整檔等於同一條 `.btn` 存七份，改一次漏一處就是 v17 以前「S1 儲存格 16px、S2 20px」的翻版。結構層只有一份，風格層才改不壞結構。

**版本**：`dist/` 的版號跟本規範走（v30 ＝ `30.0.0`；沒有改 CSS 的版本不另發版號，例如 v21）。產品引用固定版號；規範升版，產品把版號改掉就跟上，diff 一目了然。

### 12.2 風格層純度（第六項檢查的一半）

`style-s*.css` 的薄檔只准出現顏色、框線、陰影、圓角、字型；**不得出現** `min-height`、`height`、`padding`、`margin`、`gap`、`font-size`、`line-height`、`z-index`、`width`、`display`、`position`。規範明訂的風格層例外（8.2 的 S7 外層區塊內距、4.1 的 S6 等寬字字距、8.2 的 S5 暈染背景 `body::before` 與 hero 暈點 `.statc.hero::after` 的定位）列在 `audit_layers.py` 的 ALLOW 表，其餘一律不通過。v20 起七個風格檔全查（v19 只查得了 S1、S6、S7）。這是 8.1「風格是殼，只覆寫材質」第一次有程式守著。

### 12.3 拆檔無損（第六項檢查的另一半）

`verify_css_split.py` 把每張示範頁的 `<style>` 全部拿掉、換成只引用 `dist/` 的三個檔，再渲染一次，逐元素比對 48 個計算屬性（顏色、框線、圓角、陰影、內距、字級、行距、層級、尺寸、`::before`／`::after`、佔位文字色）。七份元件庫（各以該套的預設密度：S6 標準、其餘寬鬆），加上 S3、S5、S6 深色的兩種入口（`data-theme="dark"` 指定、跟隨系統），加上其他密度檔（S6 的緊湊淺色與深色、S6 寬鬆，S1 的標準與緊湊，S7 標準），加上 S6 深色的中性石墨（指定、跟隨系統兩種入口；預設的跟隨色系含在 S6 深色那兩次裡，8.8.5）共 21 次比對 **0 差異**才算 `dist/` 可出貨（5.7）。這代表示範頁與 `dist/` 不可能分家：示範頁是來源，`dist/` 是產物，中間由程式保證一致。

### 12.4 theme.js

```js
DS.applyTheme('c3')          // 切換色系 c1〜c12、sc1〜sc3；不適用於本風格的組合退回 c1，回傳實際套用的 key
DS.setColorScheme('dark')    // 'dark' | 'light' | 'system'；只對 S3、S5、S6 有效，跟隨系統時監聽 prefers-color-scheme
DS.setDarkTint('neutral')    // 'follow'（預設）| 'neutral'；S6 深色底跟隨色系或中性石墨（8.8.5），其他風格無效果；DS.darkTint() 回目前生效的值
DS.labelTables()             // 依表頭替表格每格補 data-l（手機卡片列的欄名，6.3）；載入時自動跑一次，動態新增列後再呼叫
DS.setDensity('compact')     // 'comfortable' | 'normal' | 'compact'；不在本風格可選範圍的檔退回該套預設，回傳實際套用的檔（5.7 的矩陣 DS.DENSITY）
DS.onFallback = (asked, used) => notify(asked + ' 不適用於此風格，已切回 C1')
```

風格由 `<html data-style="s6">` 宣告，建置時決定、全站一套（8.1）。偏好以 localStorage 的 `ds.theme`、`ds.scheme`、`ds.darkTint`、`ds.density` 記住，網址參數 `?theme=c3`、`?tint=neutral` 優先（4.2 要求三處一致）。深色模式的品牌色由 `DARK` 表套用（8.8；v23 起依風格分表：`DARK.s3`、`DARK.s5`、`DARK.s6`），`--on-acc`、`--on-acc2`、`--acc2-text` 一併切換；S6 深色的跟隨色系由 `DARK_TINT` 注入六個面、四個語意淡底與品牌色（8.8.5）。

### 12.5 對接路線：純 CSS，不混第三方 UI 庫的外觀

產品以任何框架（React、Vue、Svelte、原生）開發都可以，但**元件的 HTML 照元件庫的 class 語彙寫，樣式只來自 `dist/`**；框架負責資料綁定與狀態，不負責長相。不得在同一產品混用 Ant Design、Element Plus、MUI 等第三方 UI 庫的元件外觀——它們的尺寸、圓角、焦點環、間距都不是本規範的，混進來第五、六項檢查一定不過。需要第三方的行為（日期選擇、虛擬捲動、拖曳）時，用無樣式（headless）的函式庫，外觀仍由 `dist/` 決定。

選這條路線的理由：七套風格切換天然支援、檢查腳本直接適用、沒有兩套 token 要對照。代價是複雜元件（級聯選擇、穿梭框、日期範圍）的行為要自己寫或找 headless 庫。

### 12.6 瀏覽器支援基線與降級

元件庫用到的新特性與最低版本：

| 特性 | 用在 | Chrome／Edge | Safari | Firefox |
|---|---|---|---|---|
| `:focus-visible` | 10.3 焦點環 | 86 | 15.4 | 85 |
| `:has()` | SC 色系與 warning 同列的品牌標記（3.4） | 105 | 15.4 | 121 |
| `color-mix()` | 警示條框線、S5 暈染 | 111 | 16.2 | 113 |
| `aspect-ratio` | 正圓元件、商品縮圖 | 88 | 15 | 89 |
| `backdrop-filter` | S3 琉璃面板 | 76 | 9（`-webkit-`） | 103 |
| `text-wrap:balance` | 前台 H0（4.2） | 114 | 17.5 | 121 |

**支援基線：Chrome／Edge 111+、Safari 16.4+（iOS 16.4+）、Firefox 121+。不支援 IE 與 Android 系統瀏覽器。** 這條線以內所有特性都原生可用。再舊的瀏覽器會退化但不會壞版：`color-mix()` 失效處退回 `--acc-soft` 純色；`:has()` 失效只影響 SC 色系與 warning 並存那一格的品牌標記顏色；`text-wrap:balance` 失效只是斷行較差；`backdrop-filter` 失效時 S3 面板退回 92% 不透明白。驗收：支援基線的最低版本各開一次元件庫示範頁，五項加第六項檢查全部通過。
