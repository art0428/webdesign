本文件是通用的網頁介面視覺依據，不綁任何特定產品或系統類型。任何系統要新增或修改畫面，先讀這份，再動工。

v10 變更範圍：H2 與 H3 的用途改正，不動任何字級數值。4.2 兩張字級表的 H2 改為「區塊標題、彈窗與面板標題」、H3 改為「卡片標題列、行內小標題」，並新增「H2 與 H3 怎麼分」一段；4.5「標題不得小於它所領導的內文」一條改指向 4.2。起因是 v9 的 H3 與 B1 同為 14px 後，「卡片標題」這個用途說明會讓有份量的卡片、彈窗、面板標題顯得太小——業界把 14px 的標題階用在表格分區與行內小標題，卡片與面板標題用大一階。元件庫配套改兩處：彈窗標題由 H3 改 H2、側滑面板標題由 B1 改 H2。其餘章節與 v9 逐字相同。

## 二、五條設計總則

一、**內容專業、外殼柔和**。資料區（表格、數字、編號）維持高對比與緊湊密度，保證看得快、看得準；容器與操作元件用大圓角與柔和線條，降低剛硬感。這是本視覺系統的核心矛盾與解法。

二、**顏色是專案的，結構是規範的**。品牌雙色只負責「強調」與「品牌感」，介面的辨識度來自版型、字級層級、元件形狀。換掉任何顏色，介面都必須依然成立。

三、**每頁只有一個視覺焦點**。一頁最多一顆實心主按鈕、最多一個放大的關鍵數字。其餘元件保持安靜。

四、**狀態不可只靠顏色表達**。所有狀態標示一律「符號＋文字」並用（例如「● 待確認」），確保色覺不同的使用者也能判讀。

五、**數字要當主角處理**。金額、編號、單號、數量一律使用 Arial 等寬對齊、靠右排列、加千分位。

## 三、色彩體系

### 3.1 三層架構

色彩分成三層，各自的可變性不同。這是整套系統最重要的結構決策。

| 層 | 內容 | 可變性 |
|----|------|--------|
| 第一層｜品牌雙色 | accent-1 主色、accent-2 副色 | 每個專案從十二組核心或 SC 特殊色系中選一組，程式執行時注入 |
| 第二層｜結構灰階 | 文字、次要文字、框線、底色、表頭帶 | 全系統固定 |
| 第三層｜語意色 | error 紅、warning 琥珀、success 綠、info 藍 | 全系統固定，永不隨品牌變 |

**鐵則：介面上不得出現這三層以外的任何顏色。**需要區分更多層次時，用灰階深淺或留白解決，不要新增色相。

### 3.2 雙色分工

| 色 | 負責 | 具體用在哪 | 出現頻率 |
|----|------|-----------|----------|
| accent-1 主色 | 所有「操作」 | 主按鈕、選中狀態、連結、聚焦框、目前頁籤、進行中狀態 | 每頁大量 |
| accent-2 副色 | 所有「點綴」 | 品牌識別（側欄 Logo 標記）、圖表第二數列、趨勢箭頭 | 每頁少量，通常 1〜3 處 |

副色的存在意義是讓品牌有兩個顏色可以表達，而不是讓介面變花。**副色出現超過三處就是用錯了。**

### 3.3 十二組核心品牌雙色（完整色碼）

### 3.4 副色的使用限制（重要）

十二組副色裡只有四組在白底上白字達 4.5（C1、C6、C7、C9）——副色本來就是選來當點綴的，飽和度與明度都高。因此副色分兩型，且承載文字時一律走深副色：

**深型**（十二組核心全部屬此型）：不承載文字的填色（進度條第二段、圖表第二數列、裝飾）用 `--acc2`；**承載文字的填色一律用 `--acc2-deep` 配白字**（AI 標記、副色頭像、漸層鈕的深端）；副色當字（漲跌數字、副色連結）一律用 `--acc2-deep`。

**淺型**（僅 SC 系列）：填色上放 `--ink` 主文字，不放白字（實作上讀 `--acc2-text`，深型為白、淺型為該風格的 `--ink`）；副色當字一律用 `--acc2-deep`；填色元件必須有 1px 框線或置於白卡上，不得裸放在頁面底；同一元件或同一列內不得與語意色 warning 琥珀並存（兩者色相相近，會讓人分不清品牌點綴與待處理狀態）。

兩型的判定不憑目測，以計算為準：白字對比 ≥4.5 為深型、`--ink` 對比 ≥4.5 為淺型。副色出現超過三處就是用錯了（見 3.2）。

### 3.5 結構灰階（各風格一組，風格內固定）

`--ink` 主文字、`--muted` 次要文字、`--line` 框線、`--band` 表頭帶、`--page` 頁面底、`--card` 卡片底。灰階不隨品牌色改變；各風格因底色不同各有一組值，但都必須在**自己所有底色**上達 4.5。

| Token | S1 奶油（預設） | 對白底對比 | 用途 |
|-------|----------------|-----------|------|
| `--ink` 主文字 | `#26292E` | 14.59 | 所有主要文字、標題、金額 |
| `--muted` 次要文字 | `#6F6B64` | 5.30 | 欄位標籤、說明文字、日期、單位 |
| `--line` 框線 | `#E4E2DE` | — | 所有 1px 框線、分隔線 |
| `--band` 表頭帶 | `#FBFAF8` | — | 表格表頭與表尾、卡片標題列底色 |
| `--page` 頁面底 | `#F6F5F2` | — | 後台頁面背景（讓白色卡片浮出來） |
| `--card` 卡片底 | `#FFFFFF` | — | 卡片、表格、面板的底色 |

|------|-----------|----------------|--------------------|
| S1 奶油 | `#26292E` | `#6F6B64` | 頁面底 4.86 |
| S2 浮雕 | `#333B49` | `#5F6673` | 浮雕底 4.78 |

S3 琉璃的面板是半透明的，實際顯示色是「白玻璃疊在品牌漸層上」的合成結果；亮玻璃固定為白 70%，深玻璃固定為墨色 66% 配白字。琉璃的鐵則：**文字不落在漸層上（一律墊玻璃）、彩色字不落在 70% 玻璃上（一律墊白）**。

S6 石墨的灰階是**純無彩色**——每個灰的紅綠藍三值必須完全相等（`#FBFBFB`／`#F6F6F6`／`#F2F2F2`／`#E3E3E3`／`#D9D9D9`／`#171717`／`#6A6A6A`／`#3B3B3B`），不得帶藍調或黃調。帶色偏的冷灰與暖灰各自屬於別的風格語言，混用會讓整頁看起來髒。石墨的鐵則：**側欄、頂列與頁面同色，只有卡片與輸入元件是白的**；表格區不用品牌色，只有選取列例外。

### 3.6 語意色（固定，永不隨品牌變）

四個語意色六套風格共用同一組，以最深的不透明底色（S2 浮雕的 `#E6EAF0`）為約束條件反推，使四色在六套風格的所有底色上都 ≥4.5。

| 語意 | 變數 | 文字色 | 淡底 | 對白底 | 對浮雕底 | 使用場景 |
|------|------|--------|------|--------|----------|----------|
| error 紅 | `--err` / `--err-soft` | `#B23F2F` | `#F7ECEA` | 5.76 | 4.77 | 錯誤訊息、必填星號、逾期、已取消、不可回復動作 |
| warning 琥珀 | `--wrn` / `--wrn-soft` | `#846200` | `#F3EFE6` | 5.63 | 4.67 | 待處理、待確認、額度不足、需人工判斷 |
| success 綠 | `--ok` / `--ok-soft` | `#2A722E` | `#EAF1EA` | 5.92 | 4.91 | 成功、已完成、已通過、資源充足 |
| info 藍 | `--info` / `--info-soft` | `#1A66AA` | `#E8F0F6` | 5.96 | 4.93 | 中性提示、說明、系統訊息、維護公告 |

info 藍是獨立的資訊色：中性提示不再借用 accent-1（accent-1 隨品牌改變，同一個提示框在酒紅品牌會被誤讀成警告）。語意色一律「符號＋文字」並用（見總則四），不單靠顏色傳達。

### 3.7 狀態的顏色對應

這是全站最常出現的狀態集合，對應關係固定：

| 狀態語意 | 顏色 | 理由 |
|----------|------|------|
| 待人處理 | warning 琥珀 | 需要有人去處理 |
| 進行中 | accent-1 主色 | 流程正常在跑 |
| 成功結束 | success 綠 | 階段性成功 |
| 結案封存 | 灰 | 結案，不需再注意 |
| 異常 | error 紅 | 出錯或被中止 |
| 中性提示 | info 藍 | 與狀態無關的系統訊息、說明、公告 |

各系統把自己的狀態名對應到這六類即可，顏色語意在所有系統之間保持一致。

### 3.8 CSS 變數實作

色彩以 CSS 變數（寫在樣式表裡的可替換參數）實作。依專案設定，在 HTML 的 `<html>` 或 `<body>` 標籤上注入 style 屬性覆寫第一層的七個變數即可，其餘全部固定不動。

```css
:root{
  /* 第一層：品牌雙色（runtime 注入，僅此七個可變） */
  --acc:#2B5FB8;  --acc-soft:#EDF1F9;  --acc-deep:#2B5FB8;
  --acc2:#C2377B; --acc2-soft:#FAEEF4; --acc2-deep:#BA3576;
  --acc2-text:#FFFFFF;        /* 深型副色為白；淺型副色為該風格的 --ink */

  /* 第二層：結構灰階（以 S1 奶油為例，其餘風格見 3.5） */
  --ink:#26292E; --muted:#6F6B64; --line:#E4E2DE;
  --band:#FBFAF8; --page:#F6F5F2; --card:#FFFFFF;

  /* 第三層：語意色（固定） */
  --err:#B23F2F;  --err-soft:#F7ECEA;
  --wrn:#846200;  --wrn-soft:#F3EFE6;
  --ok:#2A722E;   --ok-soft:#EAF1EA;
  --info:#1A66AA; --info-soft:#E8F0F6;
}
```

注入範例（頁面產生時寫入，以 C7 焦糖磚橘為例）：

```html
<body style="--acc:#A8481F;--acc-soft:#F8EFEC;--acc-deep:#A8481F;
             --acc2:#2B2B2B;--acc2-soft:#EDEDED;--acc2-deep:#2B2B2B;--acc2-text:#FFFFFF;">
```

元件庫與選型介面以 `THEMES` 物件存放十三組設定（十二組核心 ＋ SC1），每組帶 `styles`（可用風格）與 `adjust`（可用但自動套調整的風格）欄位；切換風格時逐組檢查，不適用者鎖住、目前色系不合法時退回 C1 並提示，網址 hash 與跨頁訊息也走同一個檢查，不得靜默套用。

**禁止事項**：任何元件的 CSS 不得寫死色碼，一律引用變數。唯一例外是純黑純白（`#fff`）與陰影用的半透明黑。

### 3.9 色彩的定義單位

一、本規範所有顏色以 sRGB 色碼（六位十六進位）為唯一真值。對比度、色盲檢查、色差檢查一律以此色碼計算。

二、外部色彩系統（PANTONE、RAL、DIC 等）只作對照，不作定義。規範本體與 skill 不得出現任何外部色號。

三、專案導入既有品牌色時，若客戶以外部色號提供：以該系統官方工具取得 sRGB 近似值，依本章及第十章門檻驗收，不合格者調整色碼並在專案文件記錄「螢幕版與印刷版不同」。外部色號與查詢日期只記錄在專案自己的品牌文件。

四、允許以 `color(display-p3 …)` 提供廣色域增強，但每個顏色必須同時存在 sRGB 後備值，驗收以 sRGB 後備值為準。

### 3.10 SC 特殊色系

SC 系列收錄「需要例外規則、或只在部分風格可用」的色系。它們不佔核心十二組的位置、不隨年度退場，但每一組都必須標明適用風格，元件庫與選型介面須依此鎖定。

| 編號 | 名稱 | `--acc` | `--acc-soft` | `--acc-deep` | `--acc2` | `--acc2-soft` | `--acc2-deep` | 副色型 |
|------|------|---------|--------------|--------------|----------|---------------|---------------|--------|
| SC1 | 深綠 × 相思黃 | `#35463D` | `#EFF0EF` | `#35463D` | `#DACD65` | `#FCFBF3` | `#6F6519` | 淺型 |

SC1 實測：主色白字 10.02、放淡底 8.77、放浮雕底 8.30、放手帳紙 9.07；副色配 `--ink`（五風格分別為 8.97／6.93／8.95／8.76／9.32）；深副色白字 5.91、放浮雕底 4.90、放手帳紙 5.35、放頁面底 5.42、放副色淡底 5.70；副色與 warning 琥珀 `#846200` 對比 3.46（故訂並存禁令）；副色與各底色邊界對比 1.35〜1.63（故訂框線規則）。琉璃 70% 白玻璃疊在相思黃上合成 `#F4F0D1`，次要文字 `#454C59` 對比 7.5；墨色 66% 深玻璃疊上去合成 `#59573E`，白字 7.35。

| 風格 | 判定 | 理由 |
|------|------|------|
| S1 奶油 | ◎ 可用 | 白卡上的黃色塊乾淨 |
| S2 浮雕 | ✕ 不建議（鎖定） | 浮雕靠同色凸凹表現材質，冷灰底上的亮黃塊像貼紙；邊界對比亦最低 1.35 |
| S3 琉璃 | ◎ 可用 | 深綠到黃的漸層疊白玻璃為淡奶黃 |
| S4 手帳 | △ 需調整 | 暖紙底偏黃，黃色塊會糊進去；填色元件自動加 1px `--ink` 框線後可用，語彙即「螢光筆」 |
| S5 極光 | ◎ 最推薦 | 深綠與黃的柔霧暈染即極光本身 |

年度趨勢色系（T 系列）本版不進正選，2027 年度色發布後再議；候選見《流行色候選研究 v1》。

## 四、字型、字級與行距

### 4.1 字型家族

```css
/* 中文：Google Fonts 黑體，確保跨系統一致 */
--font-cjk: 'Noto Sans TC', sans-serif;
/* 數字與英文：系統字 Arial，後接中文備援 */
--font-num: Arial, Helvetica, 'Noto Sans TC', sans-serif;
```

引入方式：

```html
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500;700;900&display=swap" rel="stylesheet">
```

使用規則：

- 中文一律 Noto Sans TC，只載入 400／500／700／900 四個字重，不要載入更多（每個字重都是額外的下載量，中文字型檔案很大）。
- 數字、英文、料號、單號、金額、日期、電話一律 Arial。Arial 沒有中文字符，堆疊 `Arial, 'Noto Sans TC'` 可讓中英數在同一段文字裡自動分流，混排安全。
- **中文絕不使用斜體**。中文沒有真正的斜體字面，瀏覽器會用機械傾斜模擬，字型會變形難看。要強調用字重或顏色。
- Arial 在 macOS 會以 Helvetica 系呈現，跨系統有些微差異，這是已知且接受的。

**風格層例外（僅 S6 石墨）**：N4 級（料號、單號、日期、IP、追蹤碼這類技術識別碼）改用等寬字堆疊 `"SF Mono", Menlo, Consolas, "Liberation Mono", monospace`，讓上下兩列逐字對齊。**僅限 N4 一級**——金額（N1〜N3）仍用 Arial，中文一律 Noto Sans TC。其他五套風格不套用此例外。

### 4.2 字級層級表（雙套）

字級分成兩套，共用同一組代號，**元件的 HTML 與 class 名稱不需要改**，只在 `<body>` 掛 `data-type` 切換：

```html
<body data-type="productive">   <!-- 後台、工作介面、結帳流程 -->
<body data-type="expressive">   <!-- 前台、閱讀與瀏覽型頁面 -->
```

未指定時預設 Productive。這是全站唯一的字級來源，不得自行發明中間值。

**Productive 生產型**——資訊密度優先，一屏要放得下更多列。

Expressive 的放大倍率**刻意不等比**：頂端 D1 放大約 47%、底端 L2 只放大 10%。表現型要的是「大的更大」造成的節奏感；標籤字若跟著等比放大，頁面會顯得鬆散、失去重心。

**唯一的行動裝置例外**：Expressive 的 D1 在 768px 以下降為 36px（3.6rem），行距維持 1.10。44px 的數字在手機上會擠壓同列的其他內容。其餘十二級在手機上都不縮小。

**H2 與 H3 怎麼分。**分界不是「區塊還是卡片」，而是這個標題領導的是一整塊獨立內容，還是緊接著一列密集內容：

- **H2**：頁面裡的區塊標題；彈窗標題；側滑面板標題；獨立存在、自成一件事的大卡片（例如設定頁的一張設定卡、儀表板上的主圖表卡）。
- **H3**：卡片的標題列（下方有分隔線、帶 `--band` 底色的那一條）、表格標題、圖表卡的標題列、表格分區標籤、表單裡的分組小標題。

H3 與 B1 同為 14px（Expressive 同為 16px），層級靠字重 900 與 0.08em 字距撐起來，所以它只適合「下方緊接著分隔線或密集內容」的場合；標題底下是大段留白與多段內文時，改用 H2。這與 IBM Carbon 的分工一致：14px 的 heading-compact-01 用在表格分區與行內小標題，卡片與面板標題用 16px 的 heading-02——本規範的 H1 21／H2 17／H3 14／B1 14 正好對應 Carbon 的 20／16／14／14。覺得某張卡片的標題太小，直接改用 H2，不得新增中間值。

**字級與行距必須配成同一代號。** 寫了 `var(--fs-b2)` 就要同時寫 `var(--lh-b2)`，不可以拿 B2 的字級去配 B3 的行距。十三級是「字級 ＋ 行距」成對設計的，拆開配會讓同一頁出現兩種看不出理由的垂直節奏；更麻煩的是每個值單獨看都在表上，所以肉眼與逐值檢查都抓不出來。

沒有自己指定行距的元素會往上繼承，所以 `body` 一定要寫 `line-height:var(--lh-b1)`。漏掉的話整份文件的預設行距會是瀏覽器的 `normal`（約 1.2 倍），所有沒單獨設定行距的文字都不合規。

這一條有兩個例外，都是本規範自己要求的，不算違規：

- **貨幣前綴縮小 0.68 倍**（見 4.6）。它是跟著金額走的附屬符號，不是獨立的一級。
- **768px 以下的輸入框 16px**（見 6.4）。這是為了擋掉 iOS Safari 的自動放大。

**驗收：交付前跑 `audit_lineheight.py`，這是第四項自動檢查。** 它分兩關：先靜態掃每一條 CSS 規則與行內 `style`，檢查同一條規則裡的字級與行距是不是同代號、有沒有寫了字級卻漏掉行距；再把頁面渲染出來，逐一取每個文字元素實際算出來的字級與行距來比對。兩關都要 0 不合規。只看宣告值的 `check_tokens.py` 抓不到這一類。

### 4.3 兩套怎麼選

| 頁面性質 | 用哪一套 |
|----------|----------|
| 後台所有畫面 | Productive |
| 資料密集的清單、表格、報表 | Productive |
| 結帳、核對、輸入數值的流程 | Productive |
| 前台首頁、目錄、內容頁 | Expressive |
| 閱讀型頁面、活動頁 | Expressive |
| 登入、錯誤頁、空狀態 | Expressive |

判斷準則一句話：**這一頁是「拿來看的」還是「拿來做事的」**。看的用 Expressive，做事的用 Productive。同一個流程中途切換是允許的，因為使用者的任務性質確實改變了。

### 4.4 行距的設計理由

行距（line-height）是中文介面最容易被忽略、但對閱讀感受影響最大的一項。本規範的邏輯：

- **中文段落 1.8**：中文字是方塊字、字面率高、沒有英文那種起伏的輪廓，行距太小會糊成一片。1.8 是中文長文的舒適下限。
- **表格內 1.7**：表格要密集，但仍需可讀，比段落稍緊。
- **說明文字 1.70**：字級小（12px）時要用比內文更大的「行距除以字級」來補償，否則顯得擁擠。1.70 ＝ 20.4px，對齊 Ant Design 與 TDesign 給 12px 的 20px；舊版的 1.85 ＝ 22.2px 偏鬆。
- **標題 1.4〜1.5**：標題通常一到兩行，行距太大會讓標題「散開」失去份量。
- **純數字 1.15〜1.25**：數字沒有下伸部（像 g、y 那樣往下延伸的筆畫），不需要多餘的垂直空間；大數字行距太鬆會顯得軟弱無力。

**行距不得改用其他設計系統的數值。**常見的 14px/1.43 是為拉丁字母調的——英文有 b、d、g、y 這類上下伸出的筆畫，字與字之間天然有起伏，行與行不容易黏在一起。中文套用會讓整段糊成一塊灰。

**單位寫法**：一律使用無單位倍數（`line-height: 1.8`），不要寫 `28px`。無單位值會依各元素自己的字級計算，巢狀元素才不會繼承到錯誤的行高。

### 4.5 最小字級規定

- **12px 是承載句子的最小字級。**任何完整句子、說明文字不得小於 12px。Expressive 的下限是 13px。
- **11px 是整套標尺的絕對下限，而且只給「微標籤」**——一到四個字的單詞或極短片語（例如「客戶」「NT$」「待確認」），且必須字重 700 以上、加大 letter-spacing 補償辨識度。不得用來寫句子。
- **欄位標籤不得用 11px，一律 12px（L1）。**欄位標籤是表單裡每一列都要讀的功能性文字，不是微標籤。IBM Carbon、Atlassian、GitHub Primer、Ant Design、Arco、TDesign、Element Plus、Semi 八套的欄位標籤都是 12px。
- **不得出現 10px 以下的字。**中文圈五套主流元件庫（Ant Design、Arco、TDesign、Element Plus、Semi）的最小字級 token 全部是 12px，零例外；西方只有 Salesforce 有 10px，而且整份樣式表只出現六次，全部用於開關的 ON／OFF 與頭像縮寫這類兩個字母的標記。
- 行動裝置不縮小字級（唯一例外見 4.2 的 D1）。透過版型改變（單欄化）而非縮字來適應。
- **標題不得小於它所領導的內文。**H3（卡片標題列、行內小標題）與 B1（內文）同為 14px，靠字重 900 與 0.08em 字距區分，H2 與 H3 的用途分界見 4.2；這與 IBM Carbon 的做法一致（heading-compact-01 與 body-compact-01 都是 14px，只差字重），好處是標題與內文共用同一條基線格線，排在一起不會錯位。

這幾條的對標依據與十四套設計系統的逐項比對見《字級與行距對標主流 v1》。

### 4.6 金額與數字格式

金額固定寫法：縮小的灰色前綴 ＋ Arial 粗體數字 ＋ 千分位。

```html
<span class="price"><small>NT$</small>17,830</span>
```

```css
.price{ font-family:var(--font-num); font-weight:700; font-variant-numeric:tabular-nums; white-space:nowrap; }
.price small{ font-size:.68em; color:var(--muted); font-weight:400; margin-right:2px; }
```

規則：

- 千分位一律加。
- 貨幣前綴縮小至 0.68 倍並轉灰，讓數字本身成為視覺主體。
- 表格中的金額一律靠右對齊，數字位數才會對齊、方便上下比較。
- 金額與料號欄位加 `font-variant-numeric: tabular-nums`，讓每個數字佔用等寬。
- 數量、頁碼、計數等純數字同樣使用 Arial，但字重視情況（表格中的數量用 700，次要資訊用 400）。
- 負數或折讓金額前加減號並轉 error 紅。

### 4.7 單位：字級與間距用 rem，造型用 px

使用者可以在瀏覽器設定裡調整預設字型大小，這是視力不佳者最常用的輔助手段。用 px 寫死的頁面完全不理會這個設定；用 rem 寫的會跟著放大。

```css
html{ font-size:62.5%; }                      /* 1rem = 10px */
body{ font-size:1.4rem; line-height:1.8; }    /* B1 */
```

採 62.5% 寫法的好處是心算容易——**px 值除以 10 就是 rem 值**（14px → 1.4rem）。因為 62.5% 本身是相對值，使用者調整設定時整站仍會等比放大。

| 項目 | 單位 | 理由 |
|------|------|------|
| 字級 | rem | 本項的目的 |
| 元件高度、內距 | rem | 字變大時框要跟著長高，否則字被裁切 |
| 間距標尺 | rem | 字變大時段落之間也要跟著鬆開 |
| 容器最大寬度 | px | 版面寬度由螢幕決定，不該由字級決定 |
| RWD 斷點 | px | 斷點若用 rem 會在放大時意外切換版型 |
| 圓角 | px | 造型，不是內容 |
| 框線粗細 | px | 造型；1px 線放大後會變糊 |
| 陰影位移與模糊 | px | 造型 |
| 行距 | 無單位倍數 | 依各元素自己的字級計算 |

**固定高度一律改為 min-height。**原本寫 `height:40px` 的元件，字級放大後框不會變高，字會被裁掉。

```css
/* 錯誤 */ .btn{ height:40px; padding:0 24px; font-size:13px; }
/* 正確 */ .btn{ min-height:4.0rem; padding:1.0rem 2.4rem; font-size:1.3rem; }
```

**驗收條件**：在瀏覽器預設字級 100%、125%、150% 三種設定下各檢查一輪，確認沒有文字被裁切或溢出、按鈕與輸入框跟著長高、表格的數值欄不換行、側欄選單文字不換成兩行、版面沒有出現水平捲軸。

## 五、間距、圓角與框線

### 5.1 間距標尺（4px 基準）

所有 margin 與 padding 一律取自此標尺，不得出現標尺以外的數值（例如 13px、18px）。

| Token | 值 | rem | 典型用途 |
|-------|-----|-----|----------|
| space-1 | 4px | 0.4rem | 圖示與文字之間、標籤內距 |
| space-2 | 8px | 0.8rem | 元件內的小間隔、並排的小按鈕 |
| space-3 | 12px | 1.2rem | 元件之間的標準間距、表格儲存格垂直內距 |
| space-4 | 16px | 1.6rem | 卡片垂直內距、區塊內元素間距 |
| space-5 | 20px | 2.0rem | 卡片與儲存格水平內距 |
| space-6 | 24px | 2.4rem | 區塊與區塊之間 |
| space-8 | 32px | 3.2rem | 大區段之間 |
| space-10 | 40px | 4.0rem | 頁面區段分隔 |
| space-12 | 48px | 4.8rem | 頁首與內容之間 |
| space-16 | 64px | 6.4rem | 頁面上下留白 |

全站最常出現的兩個內距，一律取自標尺：

| 位置 | 垂直 | 水平 |
|------|------|------|
| 卡片內距 | 16px（1.6rem） | 20px（2.0rem） |
| 表格儲存格 | 12px（1.2rem） | 20px（2.0rem） |

儲存格比卡片緊，是刻意的——表格要密、卡片要鬆。兩者水平內距相同，卡片與表格並排時左緣才會對齊。

### 5.2 圓角尺度（四級，固定）

| 級別 | 值 | 用在哪 |
|------|-----|--------|
| 焦點框 | 18px | 頁面的招牌元件（重點標註框）、確認彈窗 |
| 大容器 | 16px | 表格外框、標題卡片、大面板 |
| 小件 | 12px | 統計卡、輸入框、選項 chip、下拉面板 |
| 膠囊 | 999px | **所有按鈕**、狀態標籤、篩選器、搜尋框、數量調整器、側欄選中項 |

設計邏輯：**面積越大，圓角越大**（大面積配小圓角會顯得生硬，小面積配大圓角會變玩具感）。

**按鈕圓度一律一致**：全部膠囊，不因重要性改變形狀。按鈕的層級只靠「填色」區分——實心 accent-1 ＝主要動作、accent-1 外框＝強調動作、灰框＝一般動作、error 紅框＝不可回復動作。

**風格層例外（僅 S6 石墨）**：按鈕與輸入框改為 **6px**、卡片與表格容器改為 **12px**；狀態膠囊、篩選膠囊、屬性 tag 仍維持 999px。這與 S4 手帳的手繪歪框、S5 極光的一角收尖同性質——都是風格的表面覆寫，不是破例。其餘四套依上表。

### 5.3 框線與陰影

- 框線一律 **1px**，色 `--line`。
- 選中或聚焦狀態的框線 **1.5px**，色 `--acc`。
- **預設零陰影**。層次靠框線、底色深淺（`--band` 與 `--card`）與留白建立，不用 box-shadow。
- 例外：S2 浮雕（雙向柔影）、S3 琉璃（面板投影）、S4 手帳（硬影位移）三套風格的視覺原理就建立在陰影上，依第八章各自的定義實作。S1 奶油、S5 極光與 S6 石墨維持零陰影。

### 5.4 元件標準尺寸

一律使用 `min-height`，不使用 `height`（理由見 4.7）。

| 元件 | 桌機 | 行動裝置 | 內距 |
|------|------|----------|------|
| 主按鈕 | 4.0rem | 4.4rem | 1.0rem 2.4rem |
| 一般按鈕 | 3.8rem | 4.4rem | 0.9rem 2.0rem |
| 小按鈕 | 3.2rem | 4.0rem | 0.6rem 1.4rem |
| 輸入框 | 4.0rem | 4.4rem | 0.9rem 1.3rem |
| 搜尋框 | 4.0rem | 4.4rem | 膠囊 |
| 數量調整器 | 3.4rem | 4.4rem | 加減鈕各 3.2rem 寬 |
| 狀態膠囊 | 2.4rem | 2.4rem | 0.4rem 1.2rem，不放大 |
| 表格列 | 4.4rem | — | 手機轉卡片，見第六章 |
| 側欄項目 | 3.8rem | — | 手機收進抽屜選單 |

**行動裝置的 4.4rem（44px）是觸控目標的國際慣例下限**，小於這個尺寸手指容易點錯。狀態膠囊不是可點擊元件，所以不受此限。

## 六、RWD 響應式規範

### 6.1 斷點定義

```css
/* 手機直立 */            @media (max-width: 479px)
/* 大手機／手機橫向 */     @media (min-width: 480px) and (max-width: 767px)
/* 平板 */                @media (min-width: 768px) and (max-width: 1023px)
/* 筆電 */                @media (min-width: 1024px) and (max-width: 1279px)
/* 桌機 */                @media (min-width: 1280px)
```

實務上只有兩個斷點真正改變版型，其餘只是微調：

- **768px**：主要分界。側欄收合、多欄變單欄、表格轉卡片。
- **480px**：次要分界。網格清單從兩欄變一欄、按鈕改為滿版寬度。

### 6.2 容器寬度

| 情境 | 最大寬度 | 左右內距 |
|------|----------|----------|
| 後台內容區 | 1060px | 桌機 26px／平板 20px／手機 16px |
| 前台頁面 | 1080px | 同上 |
| 表單型頁面（結帳、設定） | 720px | 同上 |

超過最大寬度時內容置中，兩側留白。不做滿版拉伸——表格列太長會讓眼睛從左掃到右時掉行。

### 6.3 各類畫面的響應行為

**導覽框架**

| 斷點 | 行為 |
|------|------|
| ≥ 1024px | 左側欄固定展開 226px，內容區自適應 |
| 768〜1023px | 側欄縮成 64px 只留圖示，滑鼠移上去展開浮層 |
| < 768px | 側欄完全隱藏，改為左上角漢堡選單開啟的抽屜（覆蓋式，右側半透明遮罩） |

**資料表格**——最關鍵的響應處理

| 斷點 | 行為 |
|------|------|
| ≥ 1024px | 完整表格，所有欄位顯示 |
| 768〜1023px | 隱藏次要欄位，保留識別碼／名稱／狀態／數值 |
| < 768px | **表格轉為卡片列表**：每筆一張卡，識別碼與數值在第一行左右對齊，次要資訊在第二行，狀態膠囊在右下，整張卡可點 |

表格在手機上做水平捲動是下策——使用者看不到全貌、容易漏讀。卡片化雖然佔垂直空間，但每筆資料完整可讀。

**主體＋摘要面板**（左邊操作、右邊即時結果）

| 斷點 | 行為 |
|------|------|
| ≥ 860px | 左主體區 ＋ 右側 340px 摘要面板（並排） |
| < 860px | 單欄堆疊：主體在上、摘要在下 |
| < 768px | 摘要改為**底部固定條**：永遠停在畫面底部，顯示關鍵數值與主要動作按鈕；點一下展開完整明細 |

底部固定條是行動裝置的標準做法——使用者在上方操作時，關鍵數值與主要按鈕始終在拇指可及之處，不必捲到底。

**網格清單**

| 斷點 | 欄數 |
|------|------|
| ≥ 1024px | 4 欄 |
| 768〜1023px | 3 欄 |
| 480〜767px | 2 欄 |
| < 480px | 1 欄 |

**清單＋摘要**

| 斷點 | 行為 |
|------|------|
| ≥ 860px | 左清單 ＋ 右摘要（並排，摘要 sticky 吸附） |
| < 860px | 單欄：清單在上、摘要在下、主要動作按鈕滿版 |

### 6.4 行動裝置的通則

- **相鄰可點元件之間至少留 8px 間隔**（觸控目標尺寸見 5.4）。
- **表單欄位單欄化**，不在手機上並排兩個輸入框。
- **主要動作按鈕滿版寬度**（`width:100%`），次要動作放在其下方或收進「⋯」選單。
- **避免 hover 才出現的功能**。手機沒有 hover 狀態，所有功能必須用點擊可達。表格列的操作按鈕在桌機可以 hover 才浮現，但手機版必須常駐顯示。
- **輸入框加上正確的 inputmode**：數量與金額欄位設 `inputmode="numeric"`，電話設 `type="tel"`，這樣手機會直接跳出數字鍵盤。

## 七、元件規範

本章定義**每個元件必須實作的狀態**——這是最容易被漏掉的部分。完整的視覺樣式與互動細節見各風格的元件庫檔案。

### 7.1 元件清單與必要狀態

| # | 元件 | 必須實作的狀態 |
|---|------|----------------|
| 1 | 按鈕 Button | 預設／hover／active 按下／disabled 停用／loading 處理中 |
| 2 | 輸入框 Input | 預設／focus 聚焦／error 錯誤／disabled／唯讀／有值與 placeholder |
| 3 | 下拉選單 Select | 收合／展開／已選／多選計數／搜尋中／無結果 |
| 4 | 選項標籤 Chip | 可選／已選／不可選（半透明劃線）／disabled |
| 5 | 數量調整器 Stepper | 預設／達下限（減號停用）／達上限／不符級距 |
| 6 | 核取與單選 | 未選／已選／disabled／群組必選提示 |
| 7 | 開關 Switch | 關／開／切換中／disabled |
| 8 | 狀態標籤 Badge | 五種語意色（見 3.7），一律「●＋文字」 |
| 9 | 表格 Table | 預設／hover 列／選取列／載入中（骨架屏）／無資料／載入失敗 |
| 10 | 卡片 Card | 預設／可點擊時的 hover／hero 強調版 |
| 11 | 分頁器 Pagination | 目前頁／可點頁／省略號／首末頁停用 |
| 12 | 彈窗 Modal | 開啟／關閉／確認型（雙按鈕）／危險型（紅色主按鈕＋二次確認） |
| 13 | 提示 Toast | 成功／錯誤／處理中；3 秒自動消失，可手動關閉 |
| 14 | 空狀態 Empty | 純空（首次使用）／篩選後無結果（兩者的差別見 7.3） |
| 15 | 載入 Loading | 骨架屏／轉圈圈（用哪一種見 7.3） |
| 16 | 警示條 Alert | 四個語意色各一種；可帶一顆文字動作鈕；成功與中性提示可關、錯誤與警告不可關（見 7.3） |
| 17 | 提示框 Notice | 單一中性樣式，不分語意色、不帶操作、不會消失（見 7.3） |

### 7.2 分頁器規格

全站統一使用 **P4 底線數字式**：無框純數字，目前頁為 accent-1 色＋字重 700＋2px 底線。放在表格外框的表尾區右側。選定理由是視覺重量最輕，不會跟表格內容搶注意力。

### 7.3 幾個容易做錯的元件

**數量調整器**：必須即時驗證數值範圍與級距規則。不符時不是跳錯誤訊息打斷使用者，而是「按鈕鎖住＋下方一行紅字說明」，讓使用者自己修正。

**空狀態**：兩種情境要分開處理。首次使用的空狀態要給行動指引（告訴使用者第一步可以做什麼）；篩選後無結果的空狀態要給「清除篩選」按鈕。用同一個畫面處理兩種情境是常見錯誤。

**載入中**：表格與列表一律用骨架屏。轉圈圈會讓使用者不知道要等多久、也不知道即將出現什麼；骨架屏先把版面撐開，內容到位時不會跳動。

**警示條與提示框**：這兩個元件最常被做得太重。警示條用**淡底 ＋ 1px 同色細框**，不再加粗左色條——底色、框線、左色條、圖示、獨立標題行五種手法同時用，四則排在一起整區就變成色塊牆。另外三條守則：

- **標題是選用的。** 一句話講得完就不要拆成標題加內文；標題與內文併在同一段，短訊息只有一行高。
- **動作最多一顆，而且是文字按鈕。** 實心膠囊鈕在淡底上太搶，會跟頁面的主按鈕打架。
- **錯誤與警告不給關閉鈕。** 使用者需要一直看到的訊息不該能被關掉；只有成功與中性提示可以關。
- **文字動作與關閉鈕要跟內文站在同一條基線上。** 它們現在是文字、不是按鈕，要和內文共用同一個行框（同字級、同行距、靠上對齊），不要再給它 `min-height`——按鈕那個 32px 的最小高度會把整列撐高，變成內文靠上、連結置中，差將近 6px。

提示框則改成**中性灰底塊**，不帶語意色也不帶品牌色、不加框線與左色條。提示框不代表「有事情要處理」，只是補充脈絡；長得像警示條就會被誤讀。

**危險動作**：所有不可回復的動作（刪除、取消、解除綁定）一律二次確認，且確認彈窗要寫明「會發生什麼」與「無法復原」，不是只問「確定嗎」。

## 八、風格家族 S1〜S6

### 8.1 風格與結構的關係

風格是「殼」，結構是「骨」。第三章到第七章的所有規範（色彩三層、字級層級、間距標尺、元件狀態、RWD 行為）**六套風格一體適用**。風格只改變表面材質——陰影、背景、框線質感、形狀細節。

因此換風格不需要重寫元件邏輯，只需要替換一組樣式定義。

### 8.2 六套風格定義

| 編號 | 名稱 | 英文代號 | 材質原理 | 個性 | 建議用途 |
|------|------|----------|----------|------|----------|
| S1 | 奶油 | CREAM | 暖白底、大圓角容器、1px 暖灰線、零陰影 | 最穩、最中性 | **系統預設**；後台標準；資料密集畫面 |
| S2 | 浮雕 | EMBOSS | 元件與背景同色，靠一明一暗柔和陰影做出微凸微凹 | 觸感最強 | 操作元件多、資料密度低的畫面 |
| S3 | 琉璃 | GLAZE | 品牌雙色漸層當背景，半透明毛玻璃面板浮於其上 | 品牌感與科技感最強 | 前台首頁、登入頁、行銷頁 |
| S4 | 手帳 | DOODLE | 暖紙質底、手繪不規則外框、硬影位移、紙膠帶與螢光筆 | 最有人味 | 餐飲、文創、年輕客群的前台 |
| S5 | 極光 | AURORA | 品牌雙色柔霧暈染背景、一角收尖的有機圓角 | 溫和現代 | 品牌故事頁、服務型前台 |
| S6 | 石墨 | GRAPHITE | 純無彩色近白底、1px 細線、零陰影、小圓角、技術識別碼用等寬字 | 冷靜、精準、低裝飾 | 後台、資料密集儀表板、開發者與內部工具、設定頁 |

**S2 的互動語意**：凸＝可以按、凹＝已選中或輸入區。這組隱喻要貫徹全站，不可混用。

**S5 的漸層紀律**：漸層只准出現在三個地方——強調按鈕、重點標記、hero 數字與目前狀態節點。其餘一律純色。漸層一旦濫用立刻顯得廉價。

**S6 的三條鐵則**：一、側欄與頁面同色，只有卡片是白的——「只有資料躺在白紙上，其餘都是同一張桌面」；做成側欄白、頁面灰就變成另一套風格。二、灰階是純無彩色，不得帶色偏（見 3.5）。三、表格區不用品牌色，只有選取列例外——篩選膠囊選中、側欄 hover、分段控制都用中性灰 `--sel`，品牌色只留給主按鈕、連結、側欄選中項、目前頁籤、選取列。這三條是 S6 安靜的來源。

**S1 與 S6 是一對**：奶油是暖的、軟的，給文件與對外畫面；石墨是冷的、硬的，給工程師與內部工具。後台預設仍是 S1；當專案希望後台有「工具感」而不是「文件感」時選 S6。

### 8.4 矩陣判定的理由與調整方式

**S1 奶油：全部可用。**這是它作為預設風格的價值——中性到不挑色。暖白底與暖色系（C6、C7、C8、C11、C12）最和諧；C4 電光紫彩度最高，在奶油的克制氣質裡略跳，列為可用。

**S2 浮雕：偏好中明度、與底色同調的顏色。**浮雕的底色是冷灰藍 `#E6EAF0`，靠柔和陰影營造立體。

- △ C6 胡桃棕、C7 焦糖磚橘、C8 暖墨：暖色與近黑放在冷灰底上會顯得髒或太硬。**調整方式**：把底色整組換成暖灰 `#EDE8E0`，陰影色同步調暖。
- ✕ SC1：亮黃塊在冷灰底上像貼紙，且副色與底色邊界對比只有 1.35，選型介面直接鎖住。

**S3 琉璃：需要兩個色有足夠色相差才能形成漂亮漸層。**十二組都沒有純黑，不再需要漸層專用替代色。

- ○ C6、C7、C8、C11、C12：兩端彩度低或一端接近墨色，漸層乾淨但平淡，適合想低調的專案。
- ◎ SC1：深綠到相思黃的漸層疊白玻璃後是淡奶黃，是琉璃最好看的組合之一。

**S4 手帳：需要暖色或高彩度，冷靜的顏色與手繪氣質互斥。**

- ◎ C5〜C9、C11、C12：暖色與自然色在暖紙底上最自然。
- △ C3 深靛、C4 電光紫：偏冷，彩度高勉強可用；若必須使用建議改選 S1。
- △ SC1：暖紙底偏黃，黃色塊會糊進去；副色填色元件自動加 1px 墨色框線後可用（語彙即「螢光筆」）。

**S5 極光：需要能柔和暈開的中低彩度色。**

- △ C7 焦糖磚橘、C8 暖墨：一端是近黑的暖墨，暈染開來偏灰，不是發光。若要用，把暈染改成只取主色端。
- ◎ SC1：深綠與黃的柔霧暈染即極光本身，是 SC1 最推薦的風格。

**S6 石墨：六套裡對色系最寬容的一套**，沒有任何一格「需調整」或「鎖住」。原因是這套風格本來就把品牌色壓到最少——主色只出現在主按鈕、連結、選中列、目前頁籤、側欄選中項；副色只出現在來源標記、圖表第二數列、趨勢數字三處，剛好是 3.4「副色每頁最多三處」的上限。深色系（C8 暖墨）與亮色系（C4 電光紫、C10 節慶桃紅）都不會失控。

- ○ C6 胡桃棕、C7 焦糖磚橘、C11 燒橄欖、C12 玫瑰棕：暖色系放在純無彩色的冷灰結構上略有色溫衝突，但對比全數通過，可用。若專案以暖色為品牌主色，建議優先考慮 S1 奶油。
- ◎ SC1：白卡上的黃色塊乾淨，判定同 S1。

### 8.5 通則：近黑色系用在漸層類風格

十二組核心已無純黑（原含純黑的四組於 v5 退場或改為暖墨、炭灰），v4 的「純黑替代色」與 `--acc-grad` 第四組變數**整段刪除**。剩下的一條通則是：C7 焦糖磚橘的副色炭灰 `#2B2B2B` 與 C8 暖墨的主色 `#23201E` 屬近黑，在 S3 琉璃可用（玻璃會提亮）、在 S5 極光列為需調整（暈染只取另一端的彩色）。

### 8.6 風格的技術實作

每套風格是一個獨立的 CSS 檔案（或一個 class 命名空間），載入後覆寫元件的表面樣式，**不碰任何色彩變數與尺寸變數**。

```html
<!-- 風格以 class 掛在根元素，色系以 CSS 變數注入 -->
<body class="style-cream"
      style="--acc:#B4552D;--acc-soft:#F8EBE3;--acc-deep:#A54C27;
             --acc2:#212121;--acc2-soft:#ECECEC;">
```

```css
/* base.css：所有風格共用的結構、字級、間距、RWD */
/* style-cream.css：.style-cream .card{ border:1px solid var(--line); border-radius:16px; box-shadow:none } */
/* style-emboss.css：.style-emboss .card{ border:none; box-shadow:7px 7px 14px var(--sh-d), -7px -7px 14px var(--sh-l) } */
/* style-graphite.css：.style-graphite{ --page:#FBFBFB; --card:#FFF; --line:#E3E3E3; --r-lg:12px; --r-sm:6px } */
```

## 十、無障礙規範

### 10.1 對比度

- 一般文字對背景 **至少 4.5:1**（WCAG AA 標準）。
- 大字（18px 以上且字重 700 以上）至少 3:1。
- 本規範第三章的所有色碼都已實測驗證，直接使用即符合標準。新增顏色前必須實測。
- **框線色不得拿來當文字色。** `--line` 與 `--line-2` 是給線條用的；拿來寫「不重要的字」（月曆的非本月日期、麵包屑的分隔符）對比只有 1.4，必然不及格。要淡就用 `--muted`。
- **半透明面板上不放彩色小字。** 琉璃與極光的面板是半透明的，副色或語意色的小字壓上去只剩 3.4〜4.2；改用主文字色，方向與好壞用符號加文字表達，不靠顏色。

### 10.2 不可只靠顏色

總則四的具體做法：狀態標籤用「● 待確認」，不是只有一個黃點；錯誤欄位用「紅框＋下方文字說明」，不是只把框變紅；圖表的每個數列除顏色外要有圖例或直接標註。

### 10.3 鍵盤操作

- 所有可互動元件必須能用 Tab 鍵到達，順序與視覺順序一致。
- **Focus 狀態必須可見**：一律 2px `--acc` 外框，不可用 `outline:none` 移除而不補上替代樣式。這是最常見的無障礙缺失。
- 彈窗開啟時焦點移入彈窗、關閉時歸還原按鈕；Esc 可關閉。
- 下拉選單支援方向鍵選擇、Enter 確認、Esc 關閉。

### 10.4 表單

- 每個輸入框都要有 `<label>` 並用 `for` 正確關聯，不可只靠 placeholder 當標籤（placeholder 在輸入後會消失，使用者會忘記這欄是什麼）。
- 必填用「文字標籤＋紅色星號」雙重標示，並在 `aria-required` 標記。
- 錯誤訊息放在該欄位下方、用 `aria-describedby` 關聯，讓螢幕閱讀器唸得到。

### 10.5 動態效果

- 轉場動畫一律 150ms 以內，只做 opacity 與 transform，不做會觸發重新排版的動畫。
- 尊重系統的「減少動態」設定：

```css
@media (prefers-reduced-motion: reduce){
  *{ animation-duration:.01ms !important; transition-duration:.01ms !important; }
}
```

## 十一、介面文案規範

文字是設計材料，不是裝飾。以下規則與視覺規範同等重要。

### 11.1 從使用者的角度命名

用使用者控制與認得的詞，不要用系統內部的說法。

| ✕ 不要寫 | ◎ 應該寫 |
|---------|---------|
| 建立 Variant | 新增規格 |
| Entity 設定 | 基本資料 |
| 同步主檔 | 更新資料 |
| Slug | 網址前綴 |

### 11.2 動作用主動語態，且全程同名

按鈕寫清楚按下去會發生什麼：寫「送出申請」不要寫「確認」；寫「儲存變更」不要寫「提交」。

**同一個動作在整個流程中必須同名**：按鈕寫「送出申請」，成功提示就要是「申請已送出」，不可變成「申請已建立」。介面的用語就是使用者學習系統的路標。

### 11.3 錯誤訊息

說明「發生什麼事」與「怎麼修正」，不道歉、不模糊。

- ✕「發生錯誤，請稍後再試」
- ◎「數量超出範圍，請輸入 1〜999」
- ✕「操作失敗」
- ◎「這個時段已被預約，請改選其他時間」

### 11.4 空狀態是邀請，不是報告

- ✕「無資料」
- ◎「還沒有資料。從右上角『新增』開始建立第一筆。」

### 11.5 語氣

句首大寫式的句子語氣（sentence case），不用全大寫中文，不用驚嘆號堆疊，不用「喔」「唷」等語尾助詞。對後台使用者的語氣是專業同事；對前台使用者的語氣是可靠的服務方。兩邊都不諂媚、不撒嬌。

### 11.6 一個元素只做一件事

標籤就是標籤、範例就是範例，不要讓 placeholder 兼任說明、不要讓按鈕文字兼任警告。需要補充說明就另開一行灰色小字。
