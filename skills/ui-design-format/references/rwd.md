## 六、RWD 響應式規範

### 6.1 斷點定義

```css
/* 手機直立 */            @media (max-width: 479px)
/* 大手機／手機橫向 */     @media (min-width: 480px) and (max-width: 767px)
/* 平板 */                @media (min-width: 768px) and (max-width: 1023px)
/* 筆電 */                @media (min-width: 1024px) and (max-width: 1279px)
/* 桌機 */                @media (min-width: 1280px)
```

實務上只有兩個斷點真正改變版型，其餘只是微調：

- **768px**：主要分界。側欄收合、多欄變單欄、表格轉卡片。
- **480px**：次要分界。網格清單從兩欄變一欄、按鈕改為滿版寬度。

### 6.2 容器寬度

| 情境 | 最大寬度 | 左右內距 |
|------|----------|----------|
| 後台內容區 | 1060px | 桌機 26px／平板 20px／手機 16px |
| 前台頁面 | 1080px | 同上 |
| 表單型頁面（結帳、設定） | 720px | 同上 |

超過最大寬度時內容置中，兩側留白。不做滿版拉伸——表格列太長會讓眼睛從左掃到右時掉行。

### 6.3 各類畫面的響應行為

**導覽框架**

| 斷點 | 行為 |
|------|------|
| ≥ 1024px | 左側欄固定展開 226px，內容區自適應 |
| 768〜1023px | 側欄縮成 64px 只留圖示，滑鼠移上去展開浮層 |
| < 768px | 側欄完全隱藏，改為左上角漢堡選單開啟的抽屜（覆蓋式，右側半透明遮罩） |

**資料表格**——最關鍵的響應處理

| 斷點 | 行為 |
|------|------|
| ≥ 1024px | 完整表格，所有欄位顯示 |
| 768〜1023px | 隱藏次要欄位，保留識別碼／名稱／狀態／數值 |
| < 768px | **表格轉為卡片列表**：每筆一張卡，識別碼與數值在第一行左右對齊，次要資訊在第二行，狀態膠囊在右下，整張卡可點 |

表格在手機上做水平捲動是下策——使用者看不到全貌、容易漏讀。卡片化雖然佔垂直空間，但每筆資料完整可讀。

**主體＋摘要面板**（左邊操作、右邊即時結果）

| 斷點 | 行為 |
|------|------|
| ≥ 860px | 左主體區 ＋ 右側 340px 摘要面板（並排） |
| < 860px | 單欄堆疊：主體在上、摘要在下 |
| < 768px | 摘要改為**底部固定條**：永遠停在畫面底部，顯示關鍵數值與主要動作按鈕；點一下展開完整明細 |

底部固定條是行動裝置的標準做法——使用者在上方操作時，關鍵數值與主要按鈕始終在拇指可及之處，不必捲到底。

**網格清單**

| 斷點 | 欄數 |
|------|------|
| ≥ 1024px | 4 欄 |
| 768〜1023px | 3 欄 |
| 480〜767px | 2 欄 |
| < 480px | 1 欄 |

**清單＋摘要**

| 斷點 | 行為 |
|------|------|
| ≥ 860px | 左清單 ＋ 右摘要（並排，摘要 sticky 吸附） |
| < 860px | 單欄：清單在上、摘要在下、主要動作按鈕滿版 |

### 6.4 行動裝置的通則

- **相鄰可點元件之間至少留 8px 間隔**（觸控目標尺寸見 5.4）。
- **表單欄位單欄化**，不在手機上並排兩個輸入框。
- **主要動作按鈕滿版寬度**（`width:100%`），次要動作放在其下方或收進「⋯」選單。
- **避免 hover 才出現的功能**。手機沒有 hover 狀態，所有功能必須用點擊可達。表格列的操作按鈕在桌機可以 hover 才浮現，但手機版必須常駐顯示。
- **輸入框加上正確的 inputmode**：數量與金額欄位設 `inputmode="numeric"`，電話設 `type="tel"`，這樣手機會直接跳出數字鍵盤。
