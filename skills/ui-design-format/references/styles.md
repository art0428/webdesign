## 八、風格家族 S1〜S7

### 8.1 風格與結構的關係

風格是「殼」，結構是「骨」。第三章到第七章的所有規範（色彩三層、字級層級、間距標尺、元件狀態、RWD 行為）**七套風格一體適用**。風格只改變表面材質——陰影、背景、框線質感、形狀細節。

因此換風格不需要重寫元件邏輯，只需要替換一組樣式定義。

### 8.2 七套風格定義

| 編號 | 名稱 | 英文代號 | 材質原理 | 個性 | 建議用途 |
|------|------|----------|----------|------|----------|
| S1 | 奶油 | CREAM | 暖白底、大圓角容器、1px 暖灰線、零陰影 | 最穩、最中性 | **系統預設**；後台標準；資料密集畫面 |
| S2 | 浮雕 | EMBOSS | 元件與背景同色，靠一明一暗柔和陰影做出微凸微凹 | 觸感最強 | 操作元件多、資料密度低的畫面 |
| S3 | 琉璃 | GLAZE | 品牌雙色漸層當背景，半透明毛玻璃面板浮於其上 | 品牌感與科技感最強 | 前台首頁、登入頁、行銷頁 |
| S4 | 手帳 | DOODLE | 暖紙質底、手繪不規則外框、硬影位移、紙膠帶與螢光筆 | 最有人味 | 餐飲、文創、年輕客群的前台 |
| S5 | 極光 | AURORA | 品牌雙色柔霧暈染背景、一角收尖的有機圓角 | 溫和現代 | 品牌故事頁、服務型前台 |
| S6 | 石墨 | GRAPHITE | 純無彩色近白底、1px 細線、零陰影、小圓角、技術識別碼用等寬字 | 冷靜、精準、低裝飾 | 後台、資料密集儀表板、開發者與內部工具、設定頁 |
| S7 | 編輯 | EDITORIAL | 暖白紙底、墨色、明體標題、2px 欄線分段、1px 細線、直角、零陰影 | 安靜、有份量、像雜誌 | 內容網站、品牌官網、活動頁、長文閱讀 |

依系統類型怎麼選，見 8.7 的推薦表；色系怎麼配，見 8.3。

**S7 的編輯紀律**：一、外層區塊不加框，改用上緣 2px 墨線分段（雜誌的欄線）；框只留給卡片與輸入元件，而且是 1px 細線。二、明體只給標題，內文一律黑體。三、外層區塊不留左右內距，內容與欄線的左緣對齊；欄線到內容之間留 `--sp-6`。

**S2 的互動語意**：凸＝可以按、凹＝已選中或輸入區。這組隱喻要貫徹全站，不可混用。

**S5 的漸層紀律**：漸層只准出現在三個地方——強調按鈕、重點標記、hero 數字與目前狀態節點。其餘一律純色。漸層一旦濫用立刻顯得廉價。

**S6 的三條鐵則**：一、側欄與頁面同色，只有卡片是白的——「只有資料躺在白紙上，其餘都是同一張桌面」；做成側欄白、頁面灰就變成另一套風格。二、灰階是純無彩色，不得帶色偏（見 3.5）。三、表格區不用品牌色，只有選取列例外——篩選膠囊選中、側欄 hover、分段控制都用中性灰 `--sel`，品牌色只留給主按鈕、連結、側欄選中項、目前頁籤、選取列。這三條是 S6 安靜的來源。

**S1 與 S6 是一對**：奶油是暖的、軟的，給文件與對外畫面；石墨是冷的、硬的，給工程師與內部工具。後台預設仍是 S1；當專案希望後台有「工具感」而不是「文件感」時選 S6。

### 8.4 矩陣判定的理由與調整方式

**S1 奶油：全部可用。**這是它作為預設風格的價值——中性到不挑色。暖白底與暖色系（C6、C7、C8、C11、C12）最和諧；C4 電光紫彩度最高，在奶油的克制氣質裡略跳，列為可用；SC2 鈷藍 × 亮橘同理，列為可用。

**S2 浮雕：偏好中明度、與底色同調的顏色。**浮雕的底色是冷灰藍 `#E6EAF0`，靠柔和陰影營造立體。

- △ C6 胡桃棕、C7 焦糖磚橘、C8 暖墨：暖色與近黑放在冷灰底上會顯得髒或太硬。**調整方式**：把底色整組換成暖灰 `#EDE8E0`，陰影色同步調暖。
- ✕ SC1：亮黃塊在冷灰底上像貼紙，且副色與底色邊界對比只有 1.35，選型介面直接鎖住。
- ✕ SC2：亮橘配浮雕墨色只有 4.32，承載文字不及格，鎖住。
- △ SC3：石板藍與冷灰底同調；冰川青填色自動加 1px 墨色框線。

**S3 琉璃：需要兩個色有足夠色相差才能形成漂亮漸層。**十二組都沒有純黑，不再需要漸層專用替代色。

- ○ C6、C7、C8、C11、C12：兩端彩度低或一端接近墨色，漸層乾淨但平淡，適合想低調的專案。
- ◎ SC1：深綠到相思黃的漸層疊白玻璃後是淡奶黃，是琉璃最好看的組合之一。
- ◎ SC2：鈷藍到亮橘的對角漸層，最有活動頁的張力。○ SC3：兩端都是冷色，乾淨但平淡。

**S4 手帳：需要暖色或高彩度，冷靜的顏色與手繪氣質互斥。**

- ◎ C5〜C9、C11、C12：暖色與自然色在暖紙底上最自然。
- △ C3 深靛、C4 電光紫：偏冷，彩度高勉強可用；若必須使用建議改選 S1。
- △ SC1：暖紙底偏黃，黃色塊會糊進去；副色填色元件自動加 1px 墨色框線後可用（語彙即「螢光筆」）。
- △ SC2：副色填色同樣自動加框線；鈷藍偏冷。△ SC3：冷色與手繪氣質互斥，若必須使用建議改選 S1。

**S5 極光：需要能柔和暈開的中低彩度色。**

- △ C7 焦糖磚橘、C8 暖墨：一端是近黑的暖墨，暈染開來偏灰，不是發光。若要用，把暈染改成只取主色端。
- ◎ SC1：深綠與黃的柔霧暈染即極光本身，是 SC1 最推薦的風格。
- ◎ SC2：藍與橘的暈染帶出暖光。○ SC3：冷色暈染偏灰，像晨霧。

**S6 石墨：對色系最寬容的一套**（S7 編輯同樣沒有任何一格需調整或鎖住），沒有任何一格「需調整」或「鎖住」。原因是這套風格本來就把品牌色壓到最少——主色只出現在主按鈕、連結、選中列、目前頁籤、側欄選中項；副色只出現在來源標記、圖表第二數列、趨勢數字三處，剛好是 3.4「副色每頁最多三處」的上限。深色系（C8 暖墨）與亮色系（C4 電光紫、C10 節慶桃紅）都不會失控。

- ○ C6 胡桃棕、C7 焦糖磚橘、C11 燒橄欖、C12 玫瑰棕：暖色系放在純無彩色的冷灰結構上略有色溫衝突，但對比全數通過，可用。若專案以暖色為品牌主色，建議優先考慮 S1 奶油。
- ◎ SC1：白卡上的黃色塊乾淨，判定同 S1。
- ○ SC2：對比全數通過，但高彩度與石墨的克制相反，只建議給開發者產品的活動頁。◎ SC3：純無彩灰配冷灰藍，最像工具的一組。

**S7 編輯：全部可用，靠墨色撐場。**暖白紙與墨色是中性的，十五組都通過；雜誌的品牌色通常就是一個沉穩的色加大量黑白。C8 暖墨、C9 唇膏紅、SC3 石板藍最像雜誌；C4 電光紫、C10 節慶桃紅彩度高、C12 玫瑰棕偏柔，與雜誌的克制略有距離，列為可用；SC1、SC2 的淺型副色在紙上也成立，但不是這套風格的語彙，列為可用。

### 8.5 通則：近黑色系用在漸層類風格

十二組核心已無純黑（原含純黑的四組於 v5 退場或改為暖墨、炭灰），v4 的「純黑替代色」與 `--acc-grad` 第四組變數**整段刪除**。剩下的一條通則是：C7 焦糖磚橘的副色炭灰 `#2B2B2B` 與 C8 暖墨的主色 `#23201E` 屬近黑，在 S3 琉璃可用（玻璃會提亮）、在 S5 極光列為需調整（暈染只取另一端的彩色）。

### 8.6 風格的技術實作

每套風格是一個獨立的 CSS 檔案（或一個 class 命名空間），載入後覆寫元件的表面樣式，**不碰任何色彩變數與尺寸變數**。

```html
<!-- 風格以 class 掛在根元素，色系以 CSS 變數注入 -->
<body class="style-cream"
      style="--acc:#B4552D;--acc-soft:#F8EBE3;--acc-deep:#A54C27;
             --acc2:#212121;--acc2-soft:#ECECEC;">
```

```css
/* base.css：所有風格共用的結構、字級、間距、RWD */
/* style-cream.css：.style-cream .card{ border:1px solid var(--line); border-radius:16px; box-shadow:none } */
/* style-emboss.css：.style-emboss .card{ border:none; box-shadow:7px 7px 14px var(--sh-d), -7px -7px 14px var(--sh-l) } */
/* style-graphite.css：.style-graphite{ --page:#FBFBFB; --card:#FFF; --line:#E3E3E3; --r-lg:12px; --r-sm:6px } */
```

**看表的捷徑：使用者看得久、畫面上資料多的系統，只考慮 S1 與 S6；以閱讀為主的前台，先看 S7。**S2、S3、S4、S7 是給前台與展示型頁面的殼，不要拿來當資料密集後台的主風格。

**△ 的條件**

- **S2 浮雕用在後台、內部工具、SaaS、內容頁**：只適合表格少的頁面。整頁同一個底色、沒有白色卡片讓眼睛休息；可點與不可點、啟用與停用只靠柔影區分，大量小字的資料表掃讀吃力。用在電商與品牌前台時，商品圖與內容沒有白底可以依託。
- **S3 琉璃用在少資料工具與服務型前台**：玻璃面板上的元件邊界弱，按鈕密集時不好分辨；iOS Safari 不支援 `background-attachment:fixed`，漸層會跟著捲動，小螢幕上整片漸層也會壓過內容，採用前要上實機確認。
- **S4 手帳用在 SaaS 主介面**：只有品牌個性本身就是產品賣點時才用；表格頁的手繪框是噪音，會拖慢掃讀。
- **S5 極光用在開發者與內部工具**：背景暈染對長時間專注是干擾，除非品牌明確要求，否則改選 S6。
- **S6 石墨用在電商、服務型前台、品牌官網**：冷、零裝飾，缺少情緒與記憶點。例外是開發者產品——它的官網與文件用 S6 反而一致。
- **S7 編輯用在後台與 SaaS 主介面**：明體標題與多一級的留白會降低資訊密度，欄線分段放在密集的表格頁會變成一條條橫線；只建議用在「內容管理」這類以文章為主的後台。

**選型三條規則**

1. **先看系統類型，再看品牌調性，最後才挑色系**（8.3）。判斷系統類型只問兩件事：使用者一天看它多久、畫面上資料多不多。
2. **一個系統只有一套風格。**同一個系統同時有前台與後台時，以使用時數最長的那一端決定：點餐系統的店家每天開著後台八小時、顧客點一次三分鐘，就照後台選。前台與後台若是分開的兩個系統（不同網址、不同使用者群），可以各選一套。
3. **字級套與風格無關。**同一套風格裡，做事的頁面用 Productive、看的頁面用 Expressive（見 4.3）；電商的結帳流程仍是 Productive。

不確定就選 S1。

### 8.8 S6 石墨的深色模式

**深色是 S6 的模式，不是第七套風格。**結構、圓角、零陰影、1px 細線、技術識別碼的等寬字全部不變，只換第二層灰階、第三層語意色、第四層資料色，第一層品牌色另算一組深色值。色系的可用與調整規則沿用 S6（8.3 的 S6 深色一列與 S6 相同）。

**只有 S6 有深色模式。**它本來就是純無彩灰、零陰影、細線，翻成深色最自然；其餘六套的材質——暖紙、毛玻璃、浮雕柔影、極光暈染、雜誌紙——都建立在淺底上，硬翻成深色會失去自己。需要深色的專案，風格選 S6。

**什麼時候提供**：使用者長時間盯著的工具型後台、監控與維運畫面、開發者工具、夜間作業的系統。預設跟隨作業系統的設定（`prefers-color-scheme`），並提供手動切換：淺色／深色／跟隨系統三選一，使用者的選擇要記住。

**品牌色的深色值**——主色在淺色模式同時當填色（配白字）與文字色；到了深色底，同一個顏色不可能兩邊都過 4.5（夠亮才能當字，夠亮就配不了白字）。所以深色模式的規則是：

1. 主色在 OKLab 色彩空間**只加明度、保留色相**，加到「卡片上 ≥4.6、自己的淡底上 ≥4.8」為止；超出 sRGB 色域時降低彩度而不是逐通道硬切。用 OKLab 而不用 CIELAB：CIELAB 的藍色提亮時色相會往紫偏。
2. 淡底 ＝ 深色主色 16% 混入卡片色。
3. **填色上一律放深色字**（`--on-acc` ＝ 頁面底色 `#121212`），不放白字。十五組的深色字對比最低 6.58。

**寫法**：同一份元件 HTML，深色值以 `:root` 覆寫並宣告 `color-scheme:dark`（讓捲軸與原生表單控件跟著變深）。元件裡填色上的白字改引用四個變數——`--on-acc`（主色填色上）、`--on-acc2`（深副色填色上）、`--on-err`（錯誤紅填色上）、`--on-ink`（提示氣泡、Toast 這類墨色底上）；淺色模式四者都是白，深色模式都是頁面底色。現有的淺色元件庫仍寫死 `#fff` 與淺灰，由 `build_s6_dark.py` 依同一條規則的底色換成對應變數，並掃描殘留（殘留為 0 才算完成）；**新寫的元件請直接引用變數，不要再寫死 `#fff` 或淺灰**，否則深色模式會冒出白塊。唯一例外是疊在圖片上的半透明深色遮罩，上面的白字照舊。

**不做的事**：不用 `filter:invert()` 整頁反轉（圖片、品牌色、陰影都會反掉）；不把陰影改成發光；不把圖片調暗——圖片是內容，不是介面。
