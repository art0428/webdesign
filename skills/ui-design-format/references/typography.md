## 四、字型、字級與行距

### 4.1 字型家族

```css
/* 中文：Google Fonts 黑體，確保跨系統一致 */
--font-cjk: 'Noto Sans TC', sans-serif;
/* 數字與英文：系統字 Arial，後接中文備援 */
--font-num: Arial, Helvetica, 'Noto Sans TC', sans-serif;
```

引入方式：

```html
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500;700;900&display=swap" rel="stylesheet">
```

使用規則：

- 中文一律 Noto Sans TC，只載入 400／500／700／900 四個字重，不要載入更多（每個字重都是額外的下載量，中文字型檔案很大）。
- 數字、英文、料號、單號、金額、日期、電話一律 Arial。Arial 沒有中文字符，堆疊 `Arial, 'Noto Sans TC'` 可讓中英數在同一段文字裡自動分流，混排安全。
- **中文絕不使用斜體**。中文沒有真正的斜體字面，瀏覽器會用機械傾斜模擬，字型會變形難看。要強調用字重或顏色。
- Arial 在 macOS 會以 Helvetica 系呈現，跨系統有些微差異，這是已知且接受的。

**風格層例外（僅 S6 石墨）**：N4 級（料號、單號、日期、IP、追蹤碼這類技術識別碼）改用等寬字堆疊 `"SF Mono", Menlo, Consolas, "Liberation Mono", monospace`，讓上下兩列逐字對齊。**僅限 N4 一級**——金額（N1〜N3）仍用 Arial，中文一律 Noto Sans TC。其他風格不套用此例外。

**風格層例外（僅 S7 編輯）**：標題 H0、H1、H2、H3 與元件內的標題（卡片標題列、彈窗、側滑面板、表格標題、圖表卡標題）改用明體 `'Noto Serif TC', 'Songti TC', 'Source Han Serif TC', 'PMingLiU', serif`，Google Fonts 另載入 `family=Noto+Serif+TC:wght@700;900`。**只換字型**——字級、行距、字距、字重照 4.2 的十四級表；內文、標籤、按鈕仍是 Noto Sans TC，D1 與金額仍是 Arial。明體只給標題，是因為中文明體在小字與長段落的辨識度不如黑體。

### 4.2 字級層級表（雙套）

字級分成兩套，共用同一組代號，**元件的 HTML 與 class 名稱不需要改**，只在 `<body>` 掛 `data-type` 切換：

```html
<body data-type="productive">   <!-- 後台、工作介面、結帳流程 -->
<body data-type="expressive">   <!-- 前台、閱讀與瀏覽型頁面 -->
```

未指定時預設 Productive。這是全站唯一的字級來源，不得自行發明中間值。

**Productive 生產型**——資訊密度優先，一屏要放得下更多列。

| D1 | 顯示數字（hero 統計） | 30px | 3.0rem | 700 | -0.01em | 1.15 | Arial |
| H0 | 展示標題（後台不用） | 26px | 2.6rem | 900 | 0.02em | 1.30 | 黑體 |
| H1 | 頁面標題 | 21px | 2.1rem | 900 | 0.03em | 1.40 | 黑體 |
| H2 | 區塊標題、彈窗與面板標題 | 17px | 1.7rem | 900 | 0.06em | 1.45 | 黑體 |
| H3 | 卡片標題列、行內小標題 | 14px | 1.4rem | 900 | 0.08em | 1.50 | 黑體 |

**Expressive 表現型**——閱讀與瀏覽優先，需要視覺節奏。

| 代號 | 用途 | 字級 | rem | 字重 | letter-spacing | 行距 | 字型 |
|------|------|------|-----|------|----------------|------|------|
| D1 | 顯示數字 | 44px | 4.4rem | 700 | -0.01em | 1.10 | Arial |
| H0 | 展示標題（Hero、活動主標） | 40px | 4.0rem | 900 | 0.02em | 1.25 | 黑體 |
| H1 | 頁面標題 | 30px | 3.0rem | 900 | 0.03em | 1.35 | 黑體 |
| H2 | 區塊標題、彈窗與面板標題 | 22px | 2.2rem | 900 | 0.06em | 1.40 | 黑體 |
| H3 | 卡片標題列、行內小標題 | 16px | 1.6rem | 900 | 0.08em | 1.50 | 黑體 |
| B1 | 內文 | 16px | 1.6rem | 400 | 0 | 1.90 | 黑體 |
| B2 | 密集內文 | 14px | 1.4rem | 400 | 0 | 1.80 | 黑體 |
| B3 | 說明文字 | 13px | 1.3rem | 400 | 0 | 1.90 | 黑體 |
| L1 | 欄位標籤 | 12px | 1.2rem | 700 | 0.08em | 1.50 | 黑體 |
| L2 | 微標籤 | 11px | 1.1rem | 700 | 0.15em | 1.50 | 黑體 |
| N1 | 金額（大） | 30px | 3.0rem | 700 | 0 | 1.15 | Arial |
| N2 | 金額（中） | 23px | 2.3rem | 700 | 0 | 1.20 | Arial |
| N3 | 金額（表格） | 14px | 1.4rem | 700 | 0 | 1.60 | Arial |
| N4 | 料號／日期 | 13px | 1.3rem | 400 | 0.02em | 1.60 | Arial |

Expressive 的放大倍率**刻意不等比**：頂端 D1 放大約 47%、底端 L2 只放大 10%。表現型要的是「大的更大」造成的節奏感；標籤字若跟著等比放大，頁面會顯得鬆散、失去重心。

**行動裝置例外只有兩個**：Expressive 的 D1 在 768px 以下降為 36px（3.6rem），行距維持 1.10——44px 的數字在手機上會擠壓同列的其他內容；Expressive 的 H0 在 768px 以下降為 32px（3.2rem），行距維持 1.25——40px 的標題在 390px 寬的畫面一行只放得下八、九個字。其餘十二級在手機上都不縮小。

**H0 展示標題**：只給前台的 Hero 主標與活動頁主標，**一頁最多一個**，後台畫面不用（Productive 也定義 H0，只是為了讓兩套的代號一一對齊）。一行以十四個字為上限、最多兩行；必須加 `text-wrap:balance`，讓瀏覽器平衡各行長度——40px 的中文標題很容易在最後一行只剩一兩個字。D1 仍然只給數字：它的行距 1.10 是為沒有下伸部的數字設計的，放中文會擠在一起。

**H2 與 H3 怎麼分。**分界不是「區塊還是卡片」，而是這個標題領導的是一整塊獨立內容，還是緊接著一列密集內容：

- **H2**：頁面裡的區塊標題；彈窗標題；側滑面板標題；獨立存在、自成一件事的大卡片（例如設定頁的一張設定卡、儀表板上的主圖表卡）。
- **H3**：卡片的標題列（下方有分隔線、帶 `--band` 底色的那一條）、表格標題、圖表卡的標題列、表格分區標籤、表單裡的分組小標題。

H3 與 B1 同為 14px（Expressive 同為 16px），層級靠字重 900 與 0.08em 字距撐起來，所以它只適合「下方緊接著分隔線或密集內容」的場合；標題底下是大段留白與多段內文時，改用 H2。這與 IBM Carbon 的分工一致：14px 的 heading-compact-01 用在表格分區與行內小標題，卡片與面板標題用 16px 的 heading-02——本規範的 H1 21／H2 17／H3 14／B1 14 正好對應 Carbon 的 20／16／14／14。覺得某張卡片的標題太小，直接改用 H2，不得新增中間值。

**字級與行距必須配成同一代號。** 寫了 `var(--fs-b2)` 就要同時寫 `var(--lh-b2)`，不可以拿 B2 的字級去配 B3 的行距。十四級是「字級 ＋ 行距」成對設計的，拆開配會讓同一頁出現兩種看不出理由的垂直節奏；更麻煩的是每個值單獨看都在表上，所以肉眼與逐值檢查都抓不出來。

沒有自己指定行距的元素會往上繼承，所以 `body` 一定要寫 `line-height:var(--lh-b1)`。漏掉的話整份文件的預設行距會是瀏覽器的 `normal`（約 1.2 倍），所有沒單獨設定行距的文字都不合規。

這一條有兩個例外，都是本規範自己要求的，不算違規：

- **貨幣前綴縮小 0.68 倍**（見 4.6）。它是跟著金額走的附屬符號，不是獨立的一級。
- **768px 以下的輸入框 16px**（見 6.4）。這是為了擋掉 iOS Safari 的自動放大。

**驗收：交付前跑 `audit_lineheight.py`，這是第四項自動檢查。** 它分兩關：先靜態掃每一條 CSS 規則與行內 `style`，檢查同一條規則裡的字級與行距是不是同代號、有沒有寫了字級卻漏掉行距；再把頁面渲染出來，逐一取每個文字元素實際算出來的字級與行距來比對。兩關都要 0 不合規。只看宣告值的 `check_tokens.py` 抓不到這一類。

### 4.3 兩套怎麼選

| 頁面性質 | 用哪一套 |
|----------|----------|
| 後台所有畫面 | Productive |
| 資料密集的清單、表格、報表 | Productive |
| 結帳、核對、輸入數值的流程 | Productive |
| 前台首頁、目錄、內容頁 | Expressive |
| 閱讀型頁面、活動頁 | Expressive |
| 登入、錯誤頁、空狀態 | Expressive |

判斷準則一句話：**這一頁是「拿來看的」還是「拿來做事的」**。看的用 Expressive，做事的用 Productive。同一個流程中途切換是允許的，因為使用者的任務性質確實改變了。

Expressive 的完整樣貌見八張前台示範頁 `storefront_s*.html`（七套風格加 S6 深色，設計系統瀏覽器的「前台示範」檢視）：同一套風格、只用元件庫既有的 class，做成一個選物店首頁。閱讀型前台的首選是 S7 編輯（見 8.7）。

### 4.4 行距的設計理由

行距（line-height）是中文介面最容易被忽略、但對閱讀感受影響最大的一項。本規範的邏輯：

- **中文段落 1.8**：中文字是方塊字、字面率高、沒有英文那種起伏的輪廓，行距太小會糊成一片。1.8 是中文長文的舒適下限。
- **表格內 1.7**：表格要密集，但仍需可讀，比段落稍緊。
- **說明文字 1.70**：字級小（12px）時要用比內文更大的「行距除以字級」來補償，否則顯得擁擠。1.70 ＝ 20.4px，對齊 Ant Design 與 TDesign 給 12px 的 20px；舊版的 1.85 ＝ 22.2px 偏鬆。
- **標題 1.4〜1.5**：標題通常一到兩行，行距太大會讓標題「散開」失去份量。
- **純數字 1.15〜1.25**：數字沒有下伸部（像 g、y 那樣往下延伸的筆畫），不需要多餘的垂直空間；大數字行距太鬆會顯得軟弱無力。

**行距不得改用其他設計系統的數值。**常見的 14px/1.43 是為拉丁字母調的——英文有 b、d、g、y 這類上下伸出的筆畫，字與字之間天然有起伏，行與行不容易黏在一起。中文套用會讓整段糊成一塊灰。

**單位寫法**：一律使用無單位倍數（`line-height: 1.8`），不要寫 `28px`。無單位值會依各元素自己的字級計算，巢狀元素才不會繼承到錯誤的行高。

### 4.5 最小字級規定

- **12px 是承載句子的最小字級。**任何完整句子、說明文字不得小於 12px。Expressive 的下限是 13px。
- **11px 是整套標尺的絕對下限，而且只給「微標籤」**——一到四個字的單詞或極短片語（例如「客戶」「NT$」「待確認」），且必須字重 700 以上、加大 letter-spacing 補償辨識度。不得用來寫句子。
- **欄位標籤不得用 11px，一律 12px（L1）。**欄位標籤是表單裡每一列都要讀的功能性文字，不是微標籤。IBM Carbon、Atlassian、GitHub Primer、Ant Design、Arco、TDesign、Element Plus、Semi 八套的欄位標籤都是 12px。
- **不得出現 10px 以下的字。**中文圈五套主流元件庫（Ant Design、Arco、TDesign、Element Plus、Semi）的最小字級 token 全部是 12px，零例外；西方只有 Salesforce 有 10px，而且整份樣式表只出現六次，全部用於開關的 ON／OFF 與頭像縮寫這類兩個字母的標記。
- 行動裝置不縮小字級（例外只有 4.2 的 D1 與 H0）。透過版型改變（單欄化）而非縮字來適應。
- **標題不得小於它所領導的內文。**H3（卡片標題列、行內小標題）與 B1（內文）同為 14px，靠字重 900 與 0.08em 字距區分，H2 與 H3 的用途分界見 4.2；這與 IBM Carbon 的做法一致（heading-compact-01 與 body-compact-01 都是 14px，只差字重），好處是標題與內文共用同一條基線格線，排在一起不會錯位。

這幾條的對標依據與十四套設計系統的逐項比對見《字級與行距對標主流 v1》。

### 4.6 金額與數字格式

金額固定寫法：縮小的灰色前綴 ＋ Arial 粗體數字 ＋ 千分位。

```html
<span class="price"><small>NT$</small>17,830</span>
```

```css
.price{ font-family:var(--font-num); font-weight:700; font-variant-numeric:tabular-nums; white-space:nowrap; }
.price small{ font-size:.68em; color:var(--muted); font-weight:400; margin-right:2px; }
```

規則：

- 千分位一律加。
- 貨幣前綴縮小至 0.68 倍並轉灰，讓數字本身成為視覺主體。
- 表格中的金額一律靠右對齊，數字位數才會對齊、方便上下比較。
- 金額與料號欄位加 `font-variant-numeric: tabular-nums`，讓每個數字佔用等寬。
- 數量、頁碼、計數等純數字同樣使用 Arial，但字重視情況（表格中的數量用 700，次要資訊用 400）。
- 負數或折讓金額前加減號並轉 error 紅。

### 4.7 單位：字級與間距用 rem，造型用 px

使用者可以在瀏覽器設定裡調整預設字型大小，這是視力不佳者最常用的輔助手段。用 px 寫死的頁面完全不理會這個設定；用 rem 寫的會跟著放大。

```css
html{ font-size:62.5%; }                      /* 1rem = 10px */
body{ font-size:1.4rem; line-height:1.8; }    /* B1 */
```

採 62.5% 寫法的好處是心算容易——**px 值除以 10 就是 rem 值**（14px → 1.4rem）。因為 62.5% 本身是相對值，使用者調整設定時整站仍會等比放大。

| 項目 | 單位 | 理由 |
|------|------|------|
| 字級 | rem | 本項的目的 |
| 元件高度、內距 | rem | 字變大時框要跟著長高，否則字被裁切 |
| 間距標尺 | rem | 字變大時段落之間也要跟著鬆開 |
| 容器最大寬度 | px | 版面寬度由螢幕決定，不該由字級決定 |
| RWD 斷點 | px | 斷點若用 rem 會在放大時意外切換版型 |
| 圓角 | px | 造型，不是內容 |
| 框線粗細 | px | 造型；1px 線放大後會變糊 |
| 陰影位移與模糊 | px | 造型 |
| 行距 | 無單位倍數 | 依各元素自己的字級計算 |

**固定高度一律改為 min-height。**原本寫 `height:40px` 的元件，字級放大後框不會變高，字會被裁掉。

```css
/* 錯誤 */ .btn{ height:40px; padding:0 24px; font-size:13px; }
/* 正確 */ .btn{ min-height:4.0rem; padding:1.0rem 2.4rem; font-size:1.3rem; }
```

**驗收條件**：在瀏覽器預設字級 100%、125%、150% 三種設定下各檢查一輪，確認沒有文字被裁切或溢出、按鈕與輸入框跟著長高、表格的數值欄不換行、側欄選單文字不換成兩行、版面沒有出現水平捲軸。
