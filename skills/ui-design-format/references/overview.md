# 網頁設計規範

本文件是通用的網頁介面視覺依據，不綁任何特定產品或系統類型。任何系統要新增或修改畫面，先讀這份，再動工。

v10 變更範圍：H2 與 H3 的用途改正，不動任何字級數值。4.2 兩張字級表的 H2 改為「區塊標題、彈窗與面板標題」、H3 改為「卡片標題列、行內小標題」，並新增「H2 與 H3 怎麼分」一段；4.5「標題不得小於它所領導的內文」一條改指向 4.2。起因是 v9 的 H3 與 B1 同為 14px 後，「卡片標題」這個用途說明會讓有份量的卡片、彈窗、面板標題顯得太小——業界把 14px 的標題階用在表格分區與行內小標題，卡片與面板標題用大一階。元件庫配套改兩處：彈窗標題由 H3 改 H2、側滑面板標題由 B1 改 H2。其餘章節與 v9 逐字相同。

v9 變更範圍：字級標尺對標十四套業界設計系統後的四項調整（見《字級與行距對標主流 v1》）。4.2 Productive 的 H3 由 13px 改 14px、L1 由 11px 改 12px、L2 由 10px 改 11px、B3 行距由 1.85 改 1.70；Expressive 的 H3 由 15px 改 16px。4.4 說明文字的行距理由改寫並補上業界對照；4.5 最小字級規定整段改寫，標籤下限由 10px 提高到 11px，並新增「欄位標籤不得用 11px」。**內文 14px 與行距 1.80 經對標確認站在主流上，不動。**其餘章節與 v8 逐字相同。

v8 變更範圍：4.2 新增「字級與行距必須配成同一代號」的硬規則與兩個例外，並把行高配對列為交付前的第四項自動檢查（`audit_lineheight.py`）；7.3 警示條補第四條守則（文字動作與關閉鈕與內文共用同一個行框）。起因是六套元件庫查出 112 條宣告的行距配錯代號、`body` 甚至沒有寫行距，而原本的三項檢查全部抓不到這一類。其餘章節與 v7 逐字相同。

v7 變更範圍：7.1 元件狀態表補警示條與提示框兩列、7.3 新增「警示條與提示框」一段（淡底加細框、標題選用、動作最多一顆且用文字按鈕、錯誤與警告不給關閉鈕、提示框改中性灰底塊），10.1 補兩條對比守則。選型依據見《警示條與提示框選型調研 v1》。其餘章節與 v6 逐字相同。

v6 變更範圍：新增第六套風格 **S6 石墨 GRAPHITE**——3.5 結構灰階加一列、4.1 字型家族加 N4 等寬字的風格層例外、5.2 圓角加按鈕與輸入框 6px 的風格層例外、5.3 陰影補列、第八章標題與 8.1〜8.4 由五套改為六套並補矩陣一列，名詞對照表新增兩條。其餘章節與 v5 逐字相同。

v5 變更範圍：第三章色彩體系整章改寫（十二組核心雙色 ＋ SC 特殊色系、四個語意色、新結構灰階、色彩定義單位），8.3〜8.5 風格 × 色系矩陣重畫，名詞對照表新增三條，文末新增附錄「歷年色系」。其餘章節與 v4 逐字相同。色彩推導與實測見《色彩系統定義 v2》《色系改版交接 v1》《對比稽核報告 v1、v2》；S6 的取樣與檢查見《S6 石墨風格規範條文 v1》《S6 風格比對 v1》《對比稽核報告 v3》。

## 名詞對照表

| 名詞 | 白話解釋 |
|------|----------|
| Design Token | 設計變數：把顏色、字級、圓角等統一成可替換的參數，改一處全站生效 |
| RWD | 響應式網頁設計：同一個網頁自動適應手機、平板、電腦的畫面寬度 |
| 斷點 Breakpoint | 版面切換的螢幕寬度門檻（例如小於 768px 就把側欄收起來） |
| 行距 line-height | 兩行文字之間的垂直距離，通常寫成字級的倍數（1.8 ＝ 字級的 1.8 倍） |
| 字重 weight | 字的粗細，400 是一般、700 是粗、900 是最粗 |
| letter-spacing | 字元之間的水平間距 |
| 膠囊 pill | 左右兩端完全半圓的形狀（CSS 寫 border-radius: 999px） |
| 語意色 | 固定代表某種意思的顏色（紅＝錯誤、黃＝待處理、綠＝成功），不隨品牌色改變 |
| 結構灰階 | 文字、框線、底色用的中性色，不隨品牌色改變 |
| 淡底 soft | 某個顏色的極淡版本，用來當標籤與提示框的底色 |
| WCAG AA | 國際無障礙標準的一個等級，要求文字與背景的對比度達 4.5:1 |
| Hover / Focus | Hover＝滑鼠停在上面；Focus＝用鍵盤 Tab 選到該元件 |
| CSS 變數 | 寫在樣式表裡的可替換參數，本規範用它實現「換一組顏色整站變色」 |
| 骨架屏 skeleton | 資料載入時先顯示內容形狀的灰色佔位，避免版面跳動 |
| Productive／Expressive | 兩套字級：Productive 給密集操作的工作介面（字偏小、排得緊），Expressive 給閱讀與瀏覽型頁面（字偏大、排得鬆） |
| rem | 相對於瀏覽器根字級的倍數單位；本規範設定成 1rem ＝ 10px |
| min-height 最小高度 | 元件的高度下限，內容變高時框會跟著長；相對的 height 是寫死，字放大會被裁掉 |
| 等寬數字 tabular-nums | 讓每個數字佔用相同寬度的字型設定，上下列的位數才會對齊 |
| 下伸部 descender | 字母往基線以下延伸的筆畫（g、y、p），中文沒有，所以中文需要更大的行距 |
| SC 特殊色系 | 需要例外規則、或只在部分風格可用的品牌雙色；與核心 C 系列、年度趨勢 T 系列分開編號 |
| 淺型副色 | 副色本身很亮（例如黃），填色上放主文字而不是白字；相對的深型副色填色上放白字 |
| 深副色 `--acc2-deep` | 副色加深後的版本；副色要當文字、或承載文字的填色時一律用它 |
| sRGB | 螢幕最通用的色彩空間；本規範所有色碼都是 sRGB 十六進位 |

| 無彩色灰 | 紅綠藍三個數值完全相同的灰，沒有任何色偏；S6 石墨的灰階全部是這種灰 |
| 等寬字 monospace | 每個字元寬度相同的字體，讓上下兩列的料號與單號逐字對齊 |

## 一、文件目的與使用方式

### 1.1 這份文件管什麼、不管什麼

**管**：色彩體系、字型與字級、間距圓角框線、元件必須實作的狀態、響應式行為、版型骨架、無障礙底線、介面文案原則。這些是任何系統都一樣的部分。

**不管**：功能邏輯、資料結構、技術選型，以及各系統專屬的畫面與流程。那些寫在各專案自己的文件裡。

判斷方式：**換一個系統還成立的規則寫在這裡，只對某個系統成立的寫在那個專案。**

## 二、五條設計總則

一、**內容專業、外殼柔和**。資料區（表格、數字、編號）維持高對比與緊湊密度，保證看得快、看得準；容器與操作元件用大圓角與柔和線條，降低剛硬感。這是本視覺系統的核心矛盾與解法。

二、**顏色是專案的，結構是規範的**。品牌雙色只負責「強調」與「品牌感」，介面的辨識度來自版型、字級層級、元件形狀。換掉任何顏色，介面都必須依然成立。

三、**每頁只有一個視覺焦點**。一頁最多一顆實心主按鈕、最多一個放大的關鍵數字。其餘元件保持安靜。

四、**狀態不可只靠顏色表達**。所有狀態標示一律「符號＋文字」並用（例如「● 待確認」），確保色覺不同的使用者也能判讀。

五、**數字要當主角處理**。金額、編號、單號、數量一律使用 Arial 等寬對齊、靠右排列、加千分位。
