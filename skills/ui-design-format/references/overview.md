# 網頁設計規範

本文件是通用的網頁介面視覺依據，不綁任何特定產品或系統類型。任何系統要新增或修改畫面，先讀這份，再動工。

v22 變更範圍：**版面基礎——斷點命名、容器內距、欄格系統、間距原則**（見《版面基礎條文草案 v2》、《版型對標主流與架構缺口 v1》）。v21 以前規範只管「元件長什麼樣」，沒有管「元件放在哪裡、彼此隔多遠」，每張頁面的對齊各自量像素。6.1 給五個斷點加級別名稱（緊湊、中、平板、寬、特寬，像素不變）；6.2 容器左右內距桌機 26px 改 24px（26 不在 5.1 標尺上；元件庫與 `dist/` 本來就沒有用 26，只是條文寫錯），720px 容器加「長文閱讀」用途；**新增 6.5「欄格系統」**——12 欄流體格（平板以下 8 欄、480 以下 4 欄）、欄距兩檔（標準 `--sp-6`、緊湊 `--sp-3`）、跨欄只開五種、固定寬的側欄與面板不佔欄格，`base.css` 加 `.grid`、`.grid.dense`、`.col-3`〜`.col-12`；9.1 補一行；**9.3 新增第八至十條間距原則**（內部 ≤ 外部、區塊之間大於區塊內部、`--sp-1`／`--sp-2` 只用在元件內部與同一組小元件之間），第十條與 v21 第七條合為同一條規則。5.1 兩列用途補欄距、12.1 版號改 `22.0.0`（v21 沒有改 CSS，沒有另發 21.0.0）。範例頁 `dist/examples/` 的容器內距改照 6.2，S1 後台範例的統計卡列改用欄格 3×4。不動任何 token 的值、不改元件外觀。其餘章節與 v21 逐字相同。

v21 變更範圍：**分隔線與框線的兩條結構規則**，起因是 AI 依 S1 產生的工具頁出現「區塊標題延伸細線下方再壓一條分隔線」與「按鈕列貼著輸出框」——材質層對了、結構層沒人管。9.3 新增第六條「一處分隔只用一條線」與第七條「有框線的元件相鄰時最小間距 `--sp-3`」；5.4 驗收加第四條：`audit_sizes.py` 量「有框元件貼合（邊緣距離低於 8px）」與「分隔線重複（兩線相距 12px 以內，或 64px 以內而中間沒有內容）」，七套元件庫與八張前台示範頁現況 0 不合規。不動任何 token、不改元件庫。其餘章節與 v20 逐字相同。

v20 變更範圍：**S2 浮雕、S3 琉璃、S4 手帳、S5 極光改為以 S1 為基底重建**（見《S2至S5重建報告 v1》）。v19 以前這四套是各自獨立的元件庫：同一個元件在四套裡標記不同、規則順序與 S1 不相容，所以 `dist/` 只能把它們當完整樣式表出貨（過渡版，不配 `base.css`），數量調整器的內層標記也和 S1 不同。v20 起七套共用 S1 的元件 HTML 與結構，四套只剩一層材質，`style-s2`〜`s5.css` 與 S6、S7 一樣是薄檔，**載法七套一律 `tokens` ＋ `base` ＋ 一個風格檔**。材質由程式自舊版萃取、以渲染結果驗證後精簡，第六項檢查七套全部 0 差異、七個風格檔 0 結構屬性。12.1、12.2 相應修改；8.1 補一段；8.2 寫明 S5 的「強調按鈕」就是實心主按鈕；5.4 數量調整器的輸入格改 3.0rem（外框 2px 的手帳不再被撐高）。其餘章節與 v19 逐字相同。

v19 變更範圍：新增**第十二章「開發對接」**（見《開發依循性評估 v1》）。v18 以前元件的樣式只存在示範頁的 `<style>` 裡，工程師只能複製，複製那一刻起產品與元件庫就分家。v19 起由 `emit_css.py` 自七套元件庫產生可引用的 `dist/`：`tokens.css`、`base.css`（結構層 ＋ S1 材質）、`style-s1`〜`style-s7.css`（材質層；S6 內含深色模式）、`theme.js`（色系與深淺模式），附版本號。S2〜S5 的元件庫不是由 S1 產生的，暫以完整樣式表出貨（過渡版）。新增**第六項檢查**：拆檔無損驗證 `verify_css_split.py`（示範頁改引用 dist 後逐元素比對計算樣式，0 差異）與風格層純度 `audit_layers.py`（薄檔不得含結構屬性）。寫明瀏覽器支援基線（Chrome／Edge 111+、Safari 16.4+、Firefox 121+）與降級、對接路線（純 CSS，不混第三方 UI 庫外觀）。其餘章節與 v18 逐字相同。

v18 變更範圍：缺口盤點第一批次（見《規範缺口盤點 v1》）。三條「規範早就寫了、元件庫沒照做」：**儲存格水平內距 20px**（五套用 16px）、**焦點環 2px 主色**（按鈕、chip、頁籤、側欄一條 `:focus-visible` 都沒有）、**標籤到輸入框 8px**（六套 4px）；三個便宜的洞：**佔位文字用 `--muted`**（瀏覽器預設 `#757575` 在 S2 底、S6 深色、S1 頁面底都不到 4.5，且對比稽核量不到）、**5.6 層級表**（五層 z-index token）、**5.1 間距 token 改名**與 CSS 一致（原本規範 space-8＝32px、CSS 卻是 `--sp-7`＝32px）。第五項檢查加量水平內距、標籤間距、焦點環；對比稽核加量佔位文字並定格動畫。其餘章節與 v17 逐字相同。

v17 變更範圍：**元件結構尺寸入規**（見《元件尺寸稽核報告 v1》）。七套元件庫實測，同一顆按鈕有三到四種高度、沒有一個等於 5.4 的規範值——高度從未落到 `min-height`，S2、S3、S5 又各自改了內距。5.4 整節改寫：高度做成 `--h-*` token、`min-height` 鎖定、垂直內距歸零、flex 置中，風格層不得覆寫；補列篩選膠囊、選項 chip、屬性 tag、數量調整器；表格列改為由儲存格內距派生，不另設高度；新增**第五項自動檢查** `audit_sizes.py`。4.7 範例、5.1 儲存格內距表配合修改。其餘章節與 v16 逐字相同。

v16 變更範圍：解決前台示範頁暴露的兩個缺口。一、新增 **H0 展示標題**，十三級改十四級——Expressive 40px／1.25（768px 以下 32px）、Productive 26px／1.30；只給前台 Hero 與活動主標，一頁最多一個，加 `text-wrap:balance`。4.1、4.2、4.5 相應修改。二、6.3 新增例外：**商品卡列表在 480px 以下維持兩欄**，附四個條件；6.2 的 480px 分界補一句。其餘章節與 v15 逐字相同。

v15 變更範圍：新增第七套風格 **S7 編輯 EDITORIAL**（紙本雜誌：暖白紙、墨色、明體標題、2px 欄線分段、直角、零陰影），給內容網站、品牌官網、活動頁這類閱讀型前台。兩項風格層例外寫進 4.1（標題用明體）與 5.2（容器 0、按鈕與輸入元件 2px）；3.5、5.3、7.4 與第八章各處由六套改七套；8.3 矩陣與 8.7 選型表各加 S7；可用組合改為 103 種（加 S6 深色合計 118 種）。其餘章節與 v14 逐字相同。

v14 變更範圍：新增 8.8「S6 石墨的深色模式」——深色是 S6 的模式而不是第七套風格；灰階、語意色、資料色的深色值，品牌色深色值的推導規則（OKLab 只加明度）與十五組結果，填色上一律放深色字，以及寫法與不做的事。3.5 灰階實測表加一列、8.3 矩陣加一列。其餘章節與 v13 逐字相同。

v13 變更範圍：新增兩組特殊色系——SC2 鈷藍 × 亮橘（高彩度，給零售、消費品與活動頁）、SC3 石板藍 × 冰川青（冷色、低彩度、像工具，給金融、資安這類要冷靜感的系統）。3.8 組數改十五組；3.10 色系表加兩列並補兩組的實測與風格判定，順帶補上 SC1 漏掉的 S6 一列；8.3 矩陣加兩欄，可用組合由 77 種改為 88 種；8.4 各風格補 SC2、SC3 的判定理由。其餘章節與 v12 逐字相同。

v12 變更範圍：新增 5.5「動態」——三個時長 token（120／200／320ms）、兩條緩動、哪些屬性可以做轉場、減少動態的處理；10.5 改指向 5.5（原本的「150ms 以內、只做 opacity 與 transform」與元件庫實作對不上）。新增 7.4「圖示」——指定 Lucide、16／20／24／48 四個尺寸與字級的配對、線寬與顏色、純圖示按鈕的無障礙要求。4.3 補一句指向六張前台示範頁。不改任何字級、色彩、間距的值。其餘章節與 v11 逐字相同。

v11 變更範圍：新增 8.7「風格 × 系統類型」——十種系統類型 × 六套風格的推薦表、有條件可用的說明、選型三條規則（先看系統類型再看色系、一個系統只有一套風格時以使用時數最長的一端決定、字級套與風格無關）；8.2 表格後補一句指向 8.7。寫明 S2 浮雕與 S3 琉璃不適合當資料密集後台的主風格。不動任何 token，元件庫不需重建。其餘章節與 v10 逐字相同。

v10 變更範圍：H2 與 H3 的用途改正，不動任何字級數值。4.2 兩張字級表的 H2 改為「區塊標題、彈窗與面板標題」、H3 改為「卡片標題列、行內小標題」，並新增「H2 與 H3 怎麼分」一段；4.5「標題不得小於它所領導的內文」一條改指向 4.2。起因是 v9 的 H3 與 B1 同為 14px 後，「卡片標題」這個用途說明會讓有份量的卡片、彈窗、面板標題顯得太小——業界把 14px 的標題階用在表格分區與行內小標題，卡片與面板標題用大一階。元件庫配套改兩處：彈窗標題由 H3 改 H2、側滑面板標題由 B1 改 H2。其餘章節與 v9 逐字相同。

v9 變更範圍：字級標尺對標十四套業界設計系統後的四項調整（見《字級與行距對標主流 v1》）。4.2 Productive 的 H3 由 13px 改 14px、L1 由 11px 改 12px、L2 由 10px 改 11px、B3 行距由 1.85 改 1.70；Expressive 的 H3 由 15px 改 16px。4.4 說明文字的行距理由改寫並補上業界對照；4.5 最小字級規定整段改寫，標籤下限由 10px 提高到 11px，並新增「欄位標籤不得用 11px」。**內文 14px 與行距 1.80 經對標確認站在主流上，不動。**其餘章節與 v8 逐字相同。

v8 變更範圍：4.2 新增「字級與行距必須配成同一代號」的硬規則與兩個例外，並把行高配對列為交付前的第四項自動檢查（`audit_lineheight.py`）；7.3 警示條補第四條守則（文字動作與關閉鈕與內文共用同一個行框）。起因是六套元件庫查出 112 條宣告的行距配錯代號、`body` 甚至沒有寫行距，而原本的三項檢查全部抓不到這一類。其餘章節與 v7 逐字相同。

v7 變更範圍：7.1 元件狀態表補警示條與提示框兩列、7.3 新增「警示條與提示框」一段（淡底加細框、標題選用、動作最多一顆且用文字按鈕、錯誤與警告不給關閉鈕、提示框改中性灰底塊），10.1 補兩條對比守則。選型依據見《警示條與提示框選型調研 v1》。其餘章節與 v6 逐字相同。

v6 變更範圍：新增第六套風格 **S6 石墨 GRAPHITE**——3.5 結構灰階加一列、4.1 字型家族加 N4 等寬字的風格層例外、5.2 圓角加按鈕與輸入框 6px 的風格層例外、5.3 陰影補列、第八章標題與 8.1〜8.4 由五套改為六套並補矩陣一列，名詞對照表新增兩條。其餘章節與 v5 逐字相同。

v5 變更範圍：第三章色彩體系整章改寫（十二組核心雙色 ＋ SC 特殊色系、四個語意色、新結構灰階、色彩定義單位），8.3〜8.5 風格 × 色系矩陣重畫，名詞對照表新增三條，文末新增附錄「歷年色系」。其餘章節與 v4 逐字相同。色彩推導與實測見《色彩系統定義 v2》《色系改版交接 v1》《對比稽核報告 v1、v2》；S6 的取樣與檢查見《S6 石墨風格規範條文 v1》《S6 風格比對 v1》《對比稽核報告 v3》。

## 名詞對照表

| 名詞 | 白話解釋 |
|------|----------|
| Design Token | 設計變數：把顏色、字級、圓角等統一成可替換的參數，改一處全站生效 |
| RWD | 響應式網頁設計：同一個網頁自動適應手機、平板、電腦的畫面寬度 |
| 斷點 Breakpoint | 版面切換的螢幕寬度門檻（例如小於 768px 就把側欄收起來） |
| 行距 line-height | 兩行文字之間的垂直距離，通常寫成字級的倍數（1.8 ＝ 字級的 1.8 倍） |
| 字重 weight | 字的粗細，400 是一般、700 是粗、900 是最粗 |
| letter-spacing | 字元之間的水平間距 |
| 膠囊 pill | 左右兩端完全半圓的形狀（CSS 寫 border-radius: 999px） |
| 語意色 | 固定代表某種意思的顏色（紅＝錯誤、黃＝待處理、綠＝成功），不隨品牌色改變 |
| 結構灰階 | 文字、框線、底色用的中性色，不隨品牌色改變 |
| 淡底 soft | 某個顏色的極淡版本，用來當標籤與提示框的底色 |
| WCAG AA | 國際無障礙標準的一個等級，要求文字與背景的對比度達 4.5:1 |
| Hover / Focus | Hover＝滑鼠停在上面；Focus＝用鍵盤 Tab 選到該元件 |
| CSS 變數 | 寫在樣式表裡的可替換參數，本規範用它實現「換一組顏色整站變色」 |
| 骨架屏 skeleton | 資料載入時先顯示內容形狀的灰色佔位，避免版面跳動 |
| Productive／Expressive | 兩套字級：Productive 給密集操作的工作介面（字偏小、排得緊），Expressive 給閱讀與瀏覽型頁面（字偏大、排得鬆） |
| rem | 相對於瀏覽器根字級的倍數單位；本規範設定成 1rem ＝ 10px |
| min-height 最小高度 | 元件的高度下限，內容變高時框會跟著長；相對的 height 是寫死，字放大會被裁掉 |
| 等寬數字 tabular-nums | 讓每個數字佔用相同寬度的字型設定，上下列的位數才會對齊 |
| 下伸部 descender | 字母往基線以下延伸的筆畫（g、y、p），中文沒有，所以中文需要更大的行距 |
| SC 特殊色系 | 需要例外規則、或只在部分風格可用的品牌雙色；與核心 C 系列、年度趨勢 T 系列分開編號 |
| 淺型副色 | 副色本身很亮（例如黃），填色上放主文字而不是白字；相對的深型副色填色上放白字 |
| 深副色 `--acc2-deep` | 副色加深後的版本；副色要當文字、或承載文字的填色時一律用它 |
| sRGB | 螢幕最通用的色彩空間；本規範所有色碼都是 sRGB 十六進位 |

| 無彩色灰 | 紅綠藍三個數值完全相同的灰，沒有任何色偏；S6 石墨的灰階全部是這種灰 |
| 等寬字 monospace | 每個字元寬度相同的字體，讓上下兩列的料號與單號逐字對齊 |
| 欄格系統 Column grid | 把內容區寬度切成固定欄數，元素靠「佔幾欄」對齊，而不是各自量像素（6.5） |
| 欄距 Gutter | 欄與欄之間的空隙，固定值，不隨視窗寬度變 |
| 跨欄 Span | 一個元素佔幾欄，例如 12 欄格裡佔 6 欄就是一半寬 |
| 混合格 Hybrid grid | 一邊固定寬（側欄、摘要面板）、另一邊流體（內容區）；欄格只鋪在流體的那一邊 |

## 一、文件目的與使用方式

### 1.1 這份文件管什麼、不管什麼

**管**：色彩體系、字型與字級、間距圓角框線、元件必須實作的狀態、響應式行為、版型骨架、無障礙底線、介面文案原則。這些是任何系統都一樣的部分。

**不管**：功能邏輯、資料結構、技術選型，以及各系統專屬的畫面與流程。那些寫在各專案自己的文件裡。

判斷方式：**換一個系統還成立的規則寫在這裡，只對某個系統成立的寫在那個專案。**

## 二、五條設計總則

一、**內容專業、外殼柔和**。資料區（表格、數字、編號）維持高對比與緊湊密度，保證看得快、看得準；容器與操作元件用大圓角與柔和線條，降低剛硬感。這是本視覺系統的核心矛盾與解法。

二、**顏色是專案的，結構是規範的**。品牌雙色只負責「強調」與「品牌感」，介面的辨識度來自版型、字級層級、元件形狀。換掉任何顏色，介面都必須依然成立。

三、**每頁只有一個視覺焦點**。一頁最多一顆實心主按鈕、最多一個放大的關鍵數字。其餘元件保持安靜。

四、**狀態不可只靠顏色表達**。所有狀態標示一律「符號＋文字」並用（例如「● 待確認」），確保色覺不同的使用者也能判讀。

五、**數字要當主角處理**。金額、編號、單號、數量一律使用 Arial 等寬對齊、靠右排列、加千分位。
